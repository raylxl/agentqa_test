## 一、四层结构标准（§5.5）

固定 **4 层不超**，从测试用例 MD 生成：

| 层 | 内容（新标 §5.6 五列表格 MD） | 示例 |
| --- | --- | --- |
| L1 | MD 文件名主干（去 .md、去尾部 _vN）+ 总条数**直拼** | `财务需求2026_示例仓_示例仓储流程价格_11.30_测试用例978` |
| L2 | **章-节合并节点**：`{章标题}（{章总条数}条）-{节标题原文}`，全角括号，每节一个节点 | `二、通用逻辑章（…）（142条）-2.1 编辑（22条）` |
| L3 | 用例标题 = MD `####` 行**原文** | `TC-GEN-EDIT01 编辑入口回显：…（P1）` |
| L4 | 用例详情层，每条恰 4 个并列子节点：`优先级：` `前置条件：` `操作步骤：` `预期结果：` | `优先级：P0` |
| 不进 XMind | 判断依据、测试方法两列（MD 为正源）；无 TC 的章/节（附录、代入表、统计、修改记录区） | — |

**归一化**：单元格内 `<br>` → 字面换行（XMind 8 title 原生多行展示）；Markdown 加粗 `**` 剥离。

## 二、两种输入格式（自动识别）

| | 新标 §5.6（默认） | 旧 WorkBuddy V21（向下兼容） |
| --- | --- | --- |
| 章节结构 | `## 章` → `### 节（N条）`，L2=章节合并节点 | 仅 `## 模块`，L2=`模块(N条)` 半角 |
| 用例行 | `#### TC-XX-nn 标题（P0）` | `#### TC_001｜名称 [P0]【必须验证】` |
| 字段表格 | 无加粗五列：`\| 前置条件 \| … \|`（判断依据/测试方法解析但不进 L4） | 加粗行：`\| **前置条件** \| … \|`；「操作步骤」自动别名映射为「测试步骤」进 L4 |

识别规则：取 MD 中**第一条** `####` 用例行的样式定整册模式；两种格式不得混排。

## 三、三步生成纪律（禁止跳步）

```bash
cd 05_交付工具链/07_新标准工具链   # 包内相对路径（自包根起）

# 1. 生成（输出路径缺省 = MD 同名 .xmind；sheet 标题缺省取 MD 的 H1）
python -X utf8 xmind_unified_generator_v2.py <md路径> [<xmind输出路径>] [--sheet-title 标题]

# 2. 结构验证（传 md 附带源对账：L1 精确匹配 / L3 总数 / TC 编号集合 / L3 原文一致）——须 0 错误 0 警告
python -X utf8 xmind_format_validator_v2.py <xmind路径> <md路径>

# 3. 数据终验（逐条逐字段：优先级/前置条件/操作步骤/预期结果 全文比对）——差异 = 0 才交付
python -X utf8 compare_md_xmind_v2.py <md路径> <xmind路径>
```

**交付提醒**：让用户先关闭 XMind 中已打开的旧文件再重新打开，避免编辑器内存旧版造成"改了没生效"误判。

## 四、XMind 8 兼容要点（为什么这么写文件）

- zip 成员 = `content.xml` + `meta.xml`（xmap-meta 官方成员名，**不是** metadata.xml）+ `META-INF/manifest.xml`；**禁 content.json**（XMind Zen 格式，XMind 8 打不开）。
- content.xml 根元素必须是 `xmap-content`（写成 `content` 是 Zen 格式）。
- **不要用本机 xmind 库 1.2 构建**：WorkbookDocument 无 stylesbook 不可保存、removeChild DOM 报错（仓内实证）；库仅可用于回读核对。
- MD 一律 `utf-8-sig` 读取（BOM 会使 `#` 前缀正则失效，L1 回退文件名）。
- 根标题以**文件名**为正源，不取 H1；H1 只作 sheet（画布）标题。

## 五、v2 相对 v1（01 目录）的修复清单

| # | 问题 | v2 行为 |
| --- | --- | --- |
| 1 | L2 只有章级节点，不符 §5.5 章-节合并 | 每节一个 L2，`章（章总条数条）-节`；章计数=章内 TC 总数（注意不是节条数） |
| 2 | 无 TC 的节/章混进 XMind（仓内成品 19 个空节点，附录还错挂到"七、页签5"下） | 按"有无 TC"裁剪：空节/空章整章不进；验证器将空 L2 判 ERROR |
| 3 | 旧格式多重【标注】（`[P0]【必须验证】【边界值】`）整条静默丢失（退货费 115 丢 6） | 用例行正则 `（【…】）*` 收全标注；比对脚本对 MD 侧字段缺失也会告警兜底 |
| 4 | meta 成员名 metadata.xml（非官方） | 改写 meta.xml；元信息 Creator=ZCode、时间=真实生成时间（仓内成品曾带模板旧值） |
| 5 | L4 字段名"测试步骤"与新标"操作步骤"不一致 | 新标模式直接用「操作步骤」，不再别名改写 |
| 6 | v1 比对脚本正则只认 `TC_\d+`，跑不了新标 | v2 比对/验证器双模式自动识别 |
| 7 | 章名跳过规则"含'修改记录/版本记录/统计'即跳过"**误杀带编号功能章**（示例运价"八、修改记录（26条）"整章 26 条丢失，2026-10-28 实证） | **v2.1（2026-10-28 用户拍板保留）**：改为"剥离（N条）后以关键词开头才跳过"——裸尾注区（"## 修改记录"/"## 版本记录"等）仍跳，带编号功能章（"八、修改记录（26条）"）不误杀；两处调用点同步修复 |
| 8 | 新标五列只认竖排 label 行——**横排五列成册（表头行+分隔行+单数据行）字段全空**，生成器产出垃圾 L4（结构验证不查内容、终验 1358 处差异拦截，示例账单B 2026-11-02 实证） | **v2.2（2026-11-02 示例账单B补）**：parse_new 增横排状态机（表头→分隔→数据行恰 5 列映射前三列；竖排路径原样保留、逐用例识别互不干扰）。自证：存储 679 条三步全绿（终验差异=0）+示例账单A竖排 614 条回归差异=0 |

## 七、已知边界

- 章下直接挂用例（无 `###` 节）的新标 MD：合成 `章（N条）` 单节点，验证器对非合并格式降级 WARN（可豁免）。
- 单元格内裸 `|` 字符会破坏表格切分——比对脚本的"MD 侧字段缺失"告警是兜底信号，出现即人工核对。
- 大文件（1MB+ MD / 千条用例）生成+验证全程秒级，无需分批。
