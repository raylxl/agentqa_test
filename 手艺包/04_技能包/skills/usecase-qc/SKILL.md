## 定位与分离原则（四眼原则在执行域的落地）

- **生产方**=执行用例、落回写、写报告的一方（主会话/执行技能）。
- **质检方**=本技能：**独立上下文**（spawn 独立 subagent，不继承生产方会话结论——生产方说"已完成"对质检方是零信息）、**立场对立**（任务是证伪：假设生产方有错，逐项找证据；不是帮忙确认没问题）、**交付独立**（质检报告独立落档，红项回流生产方修复后由质检方复检）。
- **信息隔离铁则**：质检方一切结论以**工件实文+脚本输出+系统实测**为证；报告/账本/台账中的自述字样（"已回写""已修复""已同步"）**一律不作为完成证据**，必须找到对应的客观锚点。
- 与设计域 usecase-challenger 对称：challenger 管用例设计质量，本技能管**执行-回写-报告交付链**；与门禁验收标准"两员制"衔接（检查者视角条款的执行域实现）。

## 九查清单（逐项独立执行，禁跳项；2026-11-18 六查扩七查；2026-11-25 增 Q8 计时完整性；2026-11-26 增 Q9 沉淀与自证真实性）

**Q1 回写真实性（四载体锚点验证）**——生产方最常漏的环节：
- 扫账本全部条目 detail 中含"回写/拍板/修复后口径/以系统为准"字样者 → 逐条到**用例正本**对应 TC 段落实文 grep 关键值/新口径描述；失效/翻案条 → 验证四载体（正本+分章+XMind+xlsx）标注一致；
- writeback 台账与校验器由公司 profile 的执行适配器提供（done 条目锚点值逐条 grep 正本实文；pending 残留=红）；配置缺失时只能人工对账并明确标记未校验。**机检是下限不是上限：质检方在机检之上做人工证伪**——挂起重出期豁免须复核是否仍在有效期内。
- **附B 声明对账**（2026-11-13 立）：附B 处置列"已修订/已回写/失效打标/已闭环"字样行 → 逐行追问台账记录与实文锚点（回写校验器 ⑥ 自动扫，人工复核其漏报）；
- **跨册拍板扫描**（2026-11-13 立）：附B 出现"N 册统一/连带/四册"类字样 → 机检+人工核对其余册是否同步登记与落地（单册台账不是跨册事项唯一载体——2026-11-13 跨册 12 条漏改事故即此断裂）。

**Q2 数字交叉对账（五源独立汇总；2026-11-17 扩第五源）**：
- 账本（收尾校验器独立跑）/ 报告 §1.2 四态表 / 册统计摘要块 / XMind 与 xlsx 实际计数 / **失败用例专项报告**（交付物§20.10，生效时刻后新轮适用：逐条卡片 ↔ 账本终态 FAIL+挂起(待复验) 条目一一对应，卡片六字段齐全度抽查）——五方数字必须互洽；R 后缀复验条归并规则执行是否正确（双 PASS 才归并，OBSERVE 探针保留计数）；复测行同 id 末次覆盖后终态为准（PASS(复测) 计 PASS、待复验计挂起，禁双计）。

**Q3 抽样系统重放（最硬一查）**：
- 按风险抽取账本 PASS 条目，回到系统真实重放；断言值必须取自用例原文，不能抄执行账本 detail。
- 环境不可用时如实标"本轮未执行+原因"，禁静默跳过。

**Q4 报告合规（冻结模板）**：三段式结构/轮次块 12 字段/两层口径执行痕迹（总结层是否真更新到本轮——比对头部「最后收尾」声明行 vs 账本最新 ts）/附A 附B 时效。

**Q5 校验器自身审计**：审收尾校验器 / 回写校验器规则漏洞与误伤（用近期事故案例反测：如"账本标已回写但文件没改"“分章漏标注”“统计块过时”“R 后缀误伤探针”四类必须能被抓住）；校验器是生产方写的——它的盲区就是质检方要补的位。

**Q6 跨载体一致性**：正本↔分章↔XMind↔xlsx 条数、失效标注集合、关键口径值（抽 5 个口径敏感值全载体 grep）。

**Q7 回写语义复核（2026-11-18 立·"六查"扩"七查"）**：Q1 查锚点"落没落"，本查抽语义"落的对不对"——
- 对拍板回写条目抽 ≥5 条（条目≤10 时全查），将落盘文本（正本对应段+分章+附B 行）与**拍板记录原文**（呈报-拍板台账/答疑闭环表）逐句比对；
- 抓四类语义病：①**口径漂移**（拍板说 A 落成 A'——改一半/表述弱化/范围收窄）；②**半边落地**（拍板含两半只落一半，如"①②两段处置"只落①）；③**载体表述不一**（正本↔分章↔XMind 同口径不同词）；④**张冠李戴**（落到了相邻 TC/错误章节）；
- 机检盲区说明：回写校验器只对锚点值存在性，语义病必须人工/子代理比对——本查禁跳。

**Q8 计时完整性（2026-11-25 立·用户要求"每个步骤都有计时"；2026-11-26 增报告层）**：
- `python -X utf8 "{paths.Agent本体}/tools/timeline_check.py" "{paths.用例文件}/计时/<册名>_timeline.jsonl" --ledger <本轮账本> --upto qc` 退出码 0 才算绿——查各步骤起止打点成不成对、必经段（需求熟悉／答疑／用例生成／用例复核／交付／执行准备）是否都已计时、账本里的轮次与时间线执行轮段是否一一对应；
- **《测试报告》须含「生命周期耗时」章（2026-11-26 用户拍板）**：阶段聚合表（取时间线正本聚合）＋执行链明细（起止时间段＋墙钟＋净操作）＋未计时申报与口径——缺该章＝红；聚合数与时间线 meta 对不上时，先按报告写明的截至时点扣除交付后追加段再比（报告须写明截至时点，未写＝黄），仍对不上（差＞1 秒取整）＝黄；
- **《测试报告》须含「耗时复盘」节（2026-11-26 用户拍板，规范第十四；对齐八条）**：按八条范围逐条核——①三分账（一次性学费/必要成本/纯浪费；独立质检段单列不计入）②因果归因与我方可控性 ③复用资产清单（标复用条件）④执行前预估偏差的原因归类（偏差率数字本身在对账节核）＋下次两场景预估与压缩率（依据要列）⑤不可压缩项声明 ⑥超时逐条带对策 ⑦对策带价值账 ⑧口径与粒度声明——缺该节＝红；对策只报未落位＝红（与 feedback-loop“未完成”同级）；三分账合计与「耗时章已计段合计扣除独立质检段」对不上（差＞取整）＝黄；缺②⑦⑧任一项或偏差对账＝黄。
- **《测试报告》须含「执行前预估与实际对账」节（2026-11-26 用户拍板，规范第十五）**：用例复核通过后、执行开始前，报告须已有“预估测试时间＝用例条数×单耗”及算式、口径、局限提示——缺＝红；预估值与条数×现行单耗不一致＝红；执行开始后预估值被改动（与修订记录、时间线比对）＝红；测试完成后缺实际测试耗时与偏差率＝黄。过渡条款（2026-11-26）：校准来源的首条需求没有事前写下的预估，按回算处理、不判红，但其“给领导的一句”须带回算限定（缺＝黄）。
- "未计时"申报逐条核对原因：生效时刻（2026-11-25 12:00）前已完成的阶段＝合理；生效后的"漏记"＝黄（须生产方书面说明并沉淀坑库）；时间线文件不存在＝红；⚠ 提示行里"调过某技能却没有任何对应阶段的段"须逐条核实是否属本需求。

**Q9 沉淀与自证真实性（2026-11-26 立·"为什么没沉淀脚本"被第三次追责后；分层执行模式＝PASS 即沉淀）**：
- **先自己跑，不信转述**：质检方必须亲自运行收尾校验器（部署侧执行工具目录下的收尾校验脚本，入参＝账本、报告、轮次名）并贴完整输出——生产方写的"校验器全绿"是零信息。校验器跑不起来（账本格式不符、路径不对、报错退出）＝**红**，不是"未运行、只读规则"就能过的黄。实证：某册账本是逐行 JSON、校验器只认 JSON 数组，一跑即崩，质检方"只读其判定规则未运行本体"却放行，收尾校验等于没做。
- **PASS 即沉淀**：账本每个终态 PASS 的 TC，须有以它为 id 的回归脚本，或在报告沉淀清单的"不沉淀"表里逐条写明原因（禁入清单／含人工步骤／不可稳定复现）——有 PASS 既无脚本又不在表＝红；在表但没写原因＝红。收尾校验器的沉淀机检为下限，质检方另抽 ≥3 条"已沉淀"的：脚本声明的 id 与 TC 对得上、造数规格与册的数据准备一致、脚本池里真有可运行的 run。
- **沉淀后是否真跑过**：抽验的脚本须有回归器台账记录（该 TC 的脚本通道执行行）；只落了文件没跑过＝黄；跑出"待复核"未回流定性＝黄。
- **生效边界**：沉淀机检自 2026-11-27 00:00 后收尾的轮次适用；此前轮不追溯，但"规则早已存在、靠用户发现才补"这件事本身要在质检报告里如实写明，不得写成"符合流程"。

## 交付流

1. 生产方完成自证（收尾校验器 + 回写校验器全绿）→ 2. spawn 质检 subagent（本技能，清单+工件路径，禁附生产方结论）→ 3. **质检方亲自重跑校验器**（Q9：拿完整输出，不采信生产方的"全绿"自述）→ 4. 质检报告落 `{需求}_质检报告_v{N}.md`（红/黄/绿+逐项证据+执行 ID）→ 5. 红项回流生产方修复 → 6. 质检方复检 → 7. **双绿（生产自证绿+质检绿）= 交付放行**，报告附C 挂质检结论指针。

## 红黄绿判定

- 🔴 红=可信度问题（锚点缺失/数字不洽/重放不符/结构违规/校验器跑不起来/PASS 未沉淀）——禁交付，回流修复；
- 🟡 黄=风险提示（校验器盲区/漏登记嫌疑/时效滞后/沉淀未实跑）——须生产方书面回应后降级或升级；
- 🟢 绿=该查项证据链完整。**签发=九查全绿**（Q3 环境不可用除外，须声明）。
