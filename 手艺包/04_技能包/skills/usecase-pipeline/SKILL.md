# 用例流水线（编排壳·2026-11-06 拆分版）

**拆分（用户拍板"拆"）**：生成与质疑分离，互相独立——
- 生成方＝`usecase-generator`（按 L1 经典方法与覆盖正本设计；阶段编号为流水线标签，不定义 L6 执行阶段）；
- 质疑方＝`usecase-challenger`（独立覆盖质疑与证书；阶段编号为流水线标签，不覆盖 L6/L7 实际流程）；
- 本技能＝**编排壳＋资产宿主**，不再自带工序。

## 触发与编排

| 指令 | 动作 |
| --- | --- |
| "生成用例 / go / 开始生成 / 重跑生成" | ①generator 全流程 → ②**自动接** challenger（质疑→修复→收敛→证书）→ ③停，交付待指令（出口门=`scripts/cert_gate.py <成册>` 退出码 0=完成证书在；2026-11-19 立，堵宿主降级下"门禁全绿即交付、质疑被跳过"） |
| 只说"生成/重跑生成"（不质疑） | 仅 generator；产出移交清单留在案，提醒用户后续质疑 |
| "检查 XX 册 / 质疑 / 复检 / 跑门禁 / 出证书" | 仅 challenger（输入=已有成册+理解说明；无移交 BRIEF 时按"规划缺省"处理并注明） |
| 有 WB/外部用例 | 质疑收敛后转 `usecase-external-compare`（横向互补） |
| 交付指令 | XMind=`md-to-xmind-v2` 技能三步全绿；Excel=`md2xlsx_v1.py` |

**轻量档短路（2026-11-11，治理标准§1.1）**：接收卡判**轻量档**的需求，编排自动降级——generator 照常但聚焦（章≤3、简化 BRIEF：策略卡+风险清单+档位必留，三矩阵可并为一张交叉表）；challenger 降为**一次聚焦复核**（红线全量+四源抽查+P0123 审计，免全量独立重推导），收敛即签发证书（证书注明"轻量档"）；执行集默认冒烟+变更集。标准/完整档流程不变。档位来源=requirement-qa-loop 阶段⓪.5 的接收卡，无接收卡按标准档走并提示补卡。

## 治理与阶段门（2026-11-11）

新需求治理 JSON 是风险、执行集和阶段状态的唯一机器正本；策略卡、BRIEF、证书、Excel 均为派生视图。设计/验证阶段允许 readiness=`awaiting_environment`；execution 阶段必须 readiness=`ready` 并对齐 dispatch 计划集；closed 阶段逐风险登记处置与责任人。新需求经典设计方法以 L1《通用用例设计标准》§22 为正本；执行期参考旧 §6 是历史迁移附录。存量历史册仅由受信 allowlist/调用参数授予豁免。

## 资产（共享，两方引用）

- `assets/matrices.md`——三矩阵模板（generator 规划用；challenger 另自建一版对照）；
- `assets/certificate.tpl.md`——九项尺子证书模板（**challenger 签发**）；
- `scripts/assemble.py`＋格式转换工具；其他物理形态使用需求侧轻量组装配置（见 generator §3）；
- 公司白名单（历史豁免需求 ID/历史分章目录/归档默认根）＝workspace `.zcode/agent-company.json`「白名单」节，assemble/governance/universal/archive 脚本自加载（2026-11-13 参数化，等价性由部署侧快照校验守护；缺配置=空集/降级路径）。

## 沿用硬规则（对两方同效）

必停点：理解说明未决项/标准外问题/吸收或标准变更/交付前，一律对话内逐条拍板不用选择框；判断依据内嵌出处；金额不补零、举例禁 0 结尾；转测校准句式；标准文件只增不覆盖且改动必经用户确认。
