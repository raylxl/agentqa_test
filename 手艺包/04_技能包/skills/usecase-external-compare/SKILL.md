# 外部用例对比（四查 + 第五查反思回写）

## 0. 公司适配层（开工第 0 步·2026-11-13 参数化）

读 workspace `.zcode/agent-company.json` 解析公司值；下文 `{paths.X}`/`{standards.X}` 均由该文件取值；`WB`＝外部对比方标识（本文以 WB 为例，他团队按实际标识替换）。**无该文件→降级通用模式**：正本=通用测试agent包`01_标准\`；禁凭旧记忆硬写公司路径。

前提：我方成册已交付（`usecase-pipeline` 产物）。外部文件只读不动。

## 1. 基线核对（第四查前置，决定冲突判据）

先读外部用例的文件头/判断依据，确认它的**口径基线版本**：引用的理解说明是几项拍板的哪个时点、引用了哪些标准条款。若对方基线落后于现行（如引用了已被后续拍板修订的旧口径），**先列出"哪些旧口径已被哪条新拍板修订"**——这是后续冲突裁定的依据，也是最容易踩的坑：对方断言本身自洽，只是基线过期。

## 2. 四查映射（全量，逐条对号）

对我方成册（分段 Read 全文）做三向分类，数量对齐对方总数：
- **已包含**：对方测试点我方有落位（按模块给映射表，抽样 TC 对应）；
- **未包含（吸收候选）**：逐条列 WB 编号/测试点/优先级/建议落章/改写要点；
- **口径冲突**：逐条列对方预期 vs 现行口径（写明现行拍板编号），**一律不吸收、以我方为准**；按根因归类（被修订的旧拍板/两可式写法/推演口径）。

模板见 `assets/compare-report.tpl.md`。

## 3. 吸收候选验真（逐条，不许跳）

每条吸收候选查其判断依据的**现行有效性**：
- 引用上游/同族需求的：去 `{paths.需求文档}` grep 上游理解说明与已交付用例，确认该口径现行有效且已拍板——拿到具体出处（文件+节+同口径 TC 编号）才算验真通过；查无实据的标"验真未过，不吸收或挂转测校准"。
- 引用通用规范的：对照{standards.通用正本统称}现行版。
- 内嵌的新口径断言（如某字段的业务计算口径）：确认有拍板/上游出处，否则吸收时挂转测校准兜底。

## 4. 必停拍板（对话内）

吸收清单+冲突裁定呈给用户：每条吸收候选一行（编号/测试点/优先级/验真结论），冲突按根因归组。**用户拍板吸收范围后才动文件**；范围调整（只收某几条）按编号执行。不用 AskUserQuestion 选择框。

## 5. 吸收执行

派吸收代理改**分章源件**（不直接改成册）：按我方横表格式与章码造数重写（不抄对方表格样式与标记），锚引用改为现行出处；更新章/节计数与"覆盖拍板"行补注来源映射。然后重跑 `usecase-pipeline` 的 assemble 脚本门禁+组装，全绿后完成证书追加版本行（吸收记录+条数变化）。

## 6. 第五查 · 根因反思回写（用户定界：不止吸收，要学习）

对每条"对方有我无"，归因到设计方法缺口并**回写标准**，六类缺口对照（《{standards.L1_通用}》§14；降级=通用包四源）：

| 根因类别 | 典型信号 | 回写落点 |
| --- | --- | --- |
| 原文直读缺位 | 原文明写了、以"无拍板口径不另立条"裁掉 | §14 源一（R9 严格化）+域标准 |
| 跨章交叉无人认领 | 两个拍板分属两章、组合场景没人写 | §14 源四 口径交叉表+BRIEF 前置 |
| 操作时序单向 | 只做了"取消后再X"、漏"X后再取消" | §14 源四 时序对矩阵+域标准 |
| 上游特殊规则未映射 | 同族需求已拍的特殊规则在本菜单漏呈现 | §14 源三+域标准映射表 |
| 越权路径不全 | 只测列表过滤、漏精确直查/导出/接口 | §14 源四 越权路径清单 |
| 控件族模板缺 | 通用控件行为（trim/空行/超长）没兜 | §14.5+域标准 §一 |

元教训写进报告：**拍板 100% 反向映射≠需求全覆盖**——数一数漏项里几条不来自任何拍板，写明本次暴露了哪几源缺口。标准回写同样只新增不修改、须用户确认；回写后更新项目记忆。

## 硬规则

- 外部文件只读；吸收必须经用户拍板；冲突不吸收须写明现行依据。
- 报告必须含"反思与回写"节——无反思的吸收视为对比未完成。
- 对比结论三数对齐：已包含+冲突+吸收候选=对方总数。
