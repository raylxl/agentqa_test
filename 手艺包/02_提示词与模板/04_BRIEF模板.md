# BRIEF 模板（测试任务任务书）v1.0

> **用途**：任何测试任务（需求澄清 / 用例设计 / 执行 / 回归）开工前填一份 BRIEF，作为 AI 与人的共同工作基准。**首行两行是铁律位**：标准定位结论 + 全谱系结论，缺一不算开工。
> 配套标准：《AI 自动化测试用例编写标准_通用版》§0.5（角色自检）、§8.5（标准定位序）。

---

## 首行铁律位（必填）

- **标准定位结论**：本任务适用标准清单 = 通用层《…》v? ＋ 领域扩展〔A 类基线库 v? / B 类规则库 v?〕＋ 项目本地口径〔理解说明 v? …〕；拿不准归属的口径已逐条问清，无默认套用。
- **全谱系结论**：本任务测 功能✓ / UI样式✓ / 性能✗（理由：…）/ 兼容✗（…）/ 安全✓（越权线）/ 可靠性✓ / 可用性✓ / 可访问性✗（…）；无明确要求的维度已主动给出建议并获确认。

## 一、任务信息

| 项 | 内容 |
|---|---|
| 被测对象 | 系统/模块/菜单或接口清单 |
| 需求来源 | 需求文档名+版本 / 变更通知 / 逆向（无文档，见§六） |
| 任务类型 | 澄清 / 设计 / 执行 / 回归 / 反馈闭环 |
| 负责人（拍板人） | 姓名/角色——所有口径疑问的最终定夺者 |

## 二、需求要素清单（AI 解析产出，人核对）

1. **功能点列表**：（编号+一句话）
2. **输入字段及约束**：字段名 / 类型 / 长度 / 必填 / 枚举取值 / 数值范围 / 默认值
3. **业务规则**："条件→结果"的 if-then 形式，逐条编号（R1、R2…）
4. **业务流程与状态流转**：主流程 + 状态机（状态×事件→新状态）
5. **角色与权限**：角色×功能×数据范围矩阵

## 三、口径确认记录（只增不覆盖）

| 编号 | 疑问（原文引用） | 结论 | 定夺人/日期 | 影响用例 |
|---|---|---|---|---|

> 疑问用《答疑五段式》逐条提出（见 05 模板），一条一编号；结论回写本表；口径变化不删旧行，新行修正并注明替代关系。

## 四、覆盖规划（设计任务必填）

- **三矩阵**：交叉矩阵（多字段组合）/ 时序矩阵（操作先后双向）/ 越权矩阵（角色×功能×数据范围）——逐格规划，空格须有"不适用"理由；
- **方法映射**：每个功能点 × 设计方法（等价类/边界/判定表/场景/状态迁移/权限/正交/错误推测）；
- **优先级分配**：P0/P1/P2/P3 与判定依据（风险=影响×概率）。

## 五、数据与环境

- 测试数据方案：预置数据清单 + 造数通道（接口/上游产出/预置/DB 直插）+ 清理策略；
- 环境：地址由环境注入，凭证不落文档。

## 六、逆向任务附加节（无需求文档时）

- 现场考古来源清单（页面实测/接口流量/数据库/日志/历史缺陷/在用文档）；
- 逆向稿两栏铁律：**现状（可观测事实）｜推断（待确认假设）**——两栏严格分离，推断未经确认不得写成断言；
- 每条推断走§三确认记录升格为口径。

## 七、完成判据

- 设计任务：覆盖自检表 + 独立质疑收敛证书（双门禁之设计域）；
- 执行任务：执行出口尺全绿（标准 §13）+ 报告（06 模板）+ 独立质检放行（双门禁之执行域）。
