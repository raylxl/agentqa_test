# 缺陷单模板与提单接入_通用版 v1.0

> **用途**：平台无关的缺陷单字段模板 + 提单接入（适配器）契约。模板与落单工序一次定死，接哪个缺陷平台随时可换——**换平台=换适配器，模板与历史呈报零变动**。严重度四级/分类五型/修复后回归口径正本=《执行反馈闭环标准_通用版》§八；已建单条目必须回填单号锚点（审计链"需求→用例→执行→缺陷单"）。
>
> **配套标准**：《执行反馈闭环标准_通用版》《测试报告三段式模板》（轮次块"缺陷单变化"字段）。

---

## 一、缺陷单模板

### 1.1 标题句式（一行式，任何平台都能装）

```
[{需求标识}] {菜单/模块}-{现象一句话}-{严重度}
例：[需求A] 报价维护-无匹配报价时整单不生成账单-P0
```

### 1.2 字段定义（三组）

**核心必填**（缺一不算合格缺陷单）：

| 字段 | 类型 | 约定 |
| --- | --- | --- |
| title | text | 按 1.1 句式；现象一句话说清"什么操作→什么结果" |
| module | text | 所属菜单/模块（与标题句式中的菜单一致） |
| case_id | text | 关联用例编号（多个分号隔）——审计链锚点，禁空 |
| severity | enum | P0~P3 四级（口径=反馈闭环§八；是 defect_severity，与用例优先级 case_priority 隔离，禁因严重度直接改用例级别） |
| category | enum | 分类五型；**仅"功能缺陷"建单**，其余四型（环境/数据/用例错误/需求歧义）走各自闭环不建单 |
| steps | text | 编号复现步骤，**含造数前置**（数据怎么来的写清楚，别人能照着复现） |
| expected | text | 预期=**引用口径出处**（理解说明编号/需求原文章节），不写自由发挥的话 |
| actual | text | 实际=系统返回**消息原文照抄**，禁转述禁概括 |
| evidence | 附件清单 | 证据三件套：UI 截图×2（操作前+报错时）+ 接口报文 + 带注释入参；附执行号 |
| environment | text | 环境+租户/组织+操作账号+代码版本（可取则附） |
| 复现率 | enum+text | 必现 / 偶发（附大致概率） |
| 修复回归要求 | text | **关联用例+影响面用例清单**——修复后回归环节直接照此执行 |
| dedup_key | text | **查重键**=用例编号+步骤号+差异类别；建单前必先查重，**命中同键只追加证据、不重复建单** |

**条件必填**：

| 字段 | 触发条件 | 约定 |
| --- | --- | --- |
| 影响面 | severity=P0/P1 必填 | 波及哪些流程+关联用例数 |

**可选**：

| 字段 | 约定 |
| --- | --- |
| requirement_ids | 关联需求编号（多个分号隔） |
| source | 来源标记（如"AI自动化"），由适配器落单时填写，人工呈报不填 |

**平台侧生成**：

| 字段 | 约定 |
| --- | --- |
| defect_id | 平台生成后**必须回填**报告缺陷锚点 + 呈报-拍板台账行 |

### 1.3 生命周期

```
新建 → 待确认（人工确认后进入流转） → 修复中 → 待回归 → 关闭
                                              └→ 重开（附失败证据）
```

- 创建后初始状态=**待确认**：建单只是"指控待核"，人工确认后才算正式缺陷；
- 修复后回归按单内"修复回归要求"字段执行：关联用例+影响面用例全过 → 关单附执行证据；不过 → 重开附失败证据。

## 二、适配器契约（接入入口可插拔的关键）

缺陷平台接入一律写成**适配器（adapter）**，模板正本永不感知平台差异。每个适配器必须提供四项能力：

| 能力 | 签名 | 作用 |
| --- | --- | --- |
| 提单 | `create(defect) → defect_id` | 按模板字段建单，返回平台单号 |
| 更新 | `update(defect_id, patch)` | 补证据 / 改状态（含追加证据式查重命中） |
| 查询 | `query(filter)` | 按条件查单（状态跟进、锚点回填、盘点拉单） |
| **字段映射表** | 内置声明 | 模板字段 ↔ 平台字段逐一对应；**平台装不下的字段按固定格式拼进描述区**（`【字段名】内容` 逐段），禁丢弃——保证换平台信息零丢失 |

规则：

1. 换平台=换 adapter 文件，模板、落单工序、历史呈报格式零变动；
2. 适配器不含业务判断——severity 映射（如本模板 P0~P3 ↔ 平台高/中/低）、必填校验全部在适配器映射层完成，映射关系写进该适配器的字段映射表；
3. 接入声明放使用方自己的配置层（enabled=false 即未接入）；未接入时落单走降级路径=呈报附完整模板内容、人工落单后回填单号（见 §四第 5 步）；
4. 适配器属使用方环境资产，通用方法与字段契约在本件，具体适配器实现不放通用层。

## 三、与既有模板/标准的关系（指针，不复制）

| 口径 | 正本 |
| --- | --- |
| 严重度四级 / 分类五型 / 修复后回归 | 执行反馈闭环标准_通用版 §八 |
| 仅"功能缺陷"建单的分流判定 | 执行反馈闭环标准_通用版 §二（分流三选一） |
| 五段式呈报（现象/用例原文/系统表现/分流初判/拍板请求） | 答疑与呈报五段式模板 |
| 报告轮次块"缺陷单变化"字段 | 测试报告三段式模板 |

## 四、落单工序（发现→拍板→落单→回归→关单）

1. **呈报**：执行发现按五段式呈报，一次一事，对话内文字拍板；
2. **拍板**：用户拍板"建缺陷"（分流①用例对、实现错）；两可时呈报不擅自分流；
3. **查重**：按 dedup_key（用例编号+步骤号+差异类别）查当前平台未关闭单——命中同键→只追加证据（update），不重复建单；
4. **填单落单**：按 §一 模板逐字段填齐（核心必填缺一不提）→ 经当前 adapter create 落单 → 拿到 defect_id；
5. **回填**：defect_id 回填报告该失败条目缺陷锚点 + 呈报-拍板台账行 + 轮次块"缺陷单变化"字段；**adapter 未接入时**=呈报附完整模板内容（全部字段照 §一 填好），人工落单后把单号回填同样三处；
6. **状态跟进**：按 adapter query 跟进（待确认→修复中→待回归）；
7. **修复回归**：研发标记修复 → 按单内"修复回归要求"执行关联用例+影响面用例回归 → 通过=关单附执行证据；不通过=重开附失败证据；
8. **闭环销账**：关单后报告余项清单销账，用例预期不变（缺陷修复不回头改用例，除非走 SYS 源拍板修码）。
