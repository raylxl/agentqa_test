# 公司层接入方法（凭证与数据库）——方法在此，值在公司层

> 原则（一句话）：**接入方法留包、连接信息留公司层**。任何账号口令、数据库地址、内网端点都不写进技能文件、提示词、标准或报告——它们只存你本机的私有凭证文件；本文件只讲"怎么接"。

## 一、凭证接入方法（私有凭证文件模式）

### 1. 建一个私有凭证文件（本机，永不分发）

放在你的 workspace 配置目录（如 `<workspace>/.zcode/agent-secrets.json`），并把它列入你的禁发清单。结构示例（值全部换成你自己的）：

```json
{
  "_说明": "公司层私有凭证文件：唯一明文落点，永不出门；任何技能/脚本/文档/报告/记忆禁止复述其中明文",
  "login_a": { "user": "your-account", "pass": "your-password", "display": "显示名" },
  "login_b": { "user": "your-account-2", "pass": "your-password-2", "note": "口令来源与状态备注" },
  "db_main": { "host": "your-db-host", "port": 3306, "database": "your-db", "user": "your-db-user", "pass": "your-db-password" }
}
```

### 2. 技能/脚本读取模式（三优先级 + 缺凭证即停）

**优先级固定：环境变量临时覆盖 > 凭证文件字段。脚本里禁止硬编码明文兜底。**

Node 脚本示例（登录类脚本头部）：

```js
// 账密只存公司层私有凭证文件；接入方法见手艺包 02/07
let _sec = {};
try {
  _sec = JSON.parse(require('fs').readFileSync(
    process.env.MY_SECRETS || '<workspace>/.zcode/agent-secrets.json', 'utf8')).login_a || {};
} catch (e) { console.error('读公司层凭证文件失败：' + e.message); }
const ACCOUNT = process.env.MY_ACCOUNT || _sec.user;
const SECRET  = process.env.MY_SECRET  || _sec.pass;
if (!ACCOUNT || !SECRET) { console.error('未取到账密：检查公司层凭证文件'); process.exit(1); }
```

Python 同理：`os.environ.get(...) or secrets["login_a"]["user"]`，取不到即 `sys.exit(1)` 带明确报错。

### 3. 禁令（发版机检兜底）

- 技能文件、提示词、标准、报告、个人记忆里**禁止出现明文账密**（含部分口令+用户名的组合）；
- 描述登录方式时写"账密读公司层凭证文件 xx 字段"，不写值；
- 发版/外发前跑密钥扫描（`user/pass` 对、明文口令模式），红项清零才放行。

## 二、数据库接入方法（测试考古 / DB 反推用）

### 1. 连接信息全部来自凭证文件

脚本零硬编码：host/port/database/user/pass 一律读凭证文件的 `db_main` 字段（或公司适配层 `paths.凭证文件` 指到的文件）。

```python
# -*- coding: utf-8 -*-
import json, sys, pymysql
SEC = json.load(open(r'<workspace>/.zcode/agent-secrets.json', encoding='utf-8'))['db_main']
conn = pymysql.connect(host=SEC['host'], port=SEC['port'], database=SEC['database'],
                       user=SEC['user'], password=SEC['pass'], charset='utf8mb4')
```

### 2. 考古三步（无需求文档时反推数据模型与状态机）

1. **表清单**：`SHOW TABLES;` → 按业务名词圈候选表；
2. **表结构**：`SHOW CREATE TABLE t_xxx;` / `DESC t_xxx;` → 字段、类型、默认值、索引、外键名；
3. **枚举与关联**：`SELECT DISTINCT status_col FROM t_xxx LIMIT 50;` → 状态机候选；按外键名/join 试关联，反推主从关系。

### 3. 两条铁律（方法再好也不能破）

- **DB 只是旁路证据**：查到的是"系统现状"，**现状≠断言**——凡要当"预期"用的规则必须经需求方拍板，防把 bug 测成 PASS；
- **写库须谨慎**：测试造数/改数只动测试环境、只动带测试标识的数据；改前先 `SELECT` 确认影响行，改后复核；生产库永不出现在凭证文件里。

## 三、双机检怎么配合

| 机检 | 管什么 |
|---|---|
| 通用层机检（03_检查脚本/generic_layer_check.py + 你的公司词表） | 防公司专属名词/内网地址混进本包 |
| 密钥扫描（扫 user/pass 对、明文口令模式） | 防明文凭证混进任何要出门的文件 |

两个都绿，才允许外发。
