# 开发代码库接入说明（同事版 v1，2026-11-17 立）

> 作用：agent 的"开发代码库"（integrations.dev_git）让技能在**答疑考古、接口契约校验、失败证据定位、ZBASE 日志关键字反查**时直接 grep 开发源码。默认配置指向财务线 29 仓；换你自己的代码库按本文三步走。

## 一、先搞清楚 agent 里它在哪

| 层 | 位置 |
| --- | --- |
| 配置登记 | `公司包/agent-company.json` → `integrations.dev_git`（两个字段：`base_url`=GitLab 组地址、`clone_root`=本地克隆根目录） |
| 实际代码 | 不在 agent 里——`clone_root` 指向你自己磁盘上的克隆目录（默认 `D:/caiwu`） |
| 使用方 | requirement-qa-loop（考古六源）/ usecase-generator（Controller·DTO 契约）/ usecase-feedback-loop（分流②代码实证）/ usecase-executor（前端 vue 定位）/ 缺陷模板（规则依据五源）/ zbase-log-query（代码定位→app_map 查应用→查日志） |

## 二、换库/接新库三步

1. **克隆你有权限的代码**到任意目录（建议和默认分离，如 `D:/mycode`）：
   ```bash
   git clone git@git.yourcompany.com:yourgroup/your-repo.git D:/mycode/your-repo
   # 多个仓就多 clone 几次，都放同一父目录下（agent 按目录递归搜）
   ```
2. **改配置**：编辑 `公司包/agent-company.json`：
   ```json
   "dev_git": {
     "enabled": true,
     "base_url": "git@git.yourcompany.com:yourgroup",   ← 换成你的 GitLab 组
     "clone_root": "D:/mycode"                          ← 换成你的克隆父目录
   }
   ```
3. **验证**：随便让 agent 干一件会用代码库的事（如"在开发代码库里找 XXX 的日志关键字"），能 grep 出结果即通。

## 三、权限说明

- SSH 免密：把你本机 `~/.ssh/id_rsa.pub` 注册到 GitLab（Settings→SSH Keys）；agent 不存任何 git 凭证（**凭证红线：SSH key 在你本机，永 不进 agent 包**）。
- HTTP 方式也可以：`base_url` 写 `http://git.yourcompany.com/yourgroup` 即可，clone 时用账号密码/token。
- **纪律：默认只读 + 指定分支安全同步**——日常考古、契约校验、证据定位只做 grep/读文件/`git status`/`git log`/`git diff`/`git show origin/<分支>:<路径>`。
- 用户明确要求“当前版本逻辑”或指定审计分支时，agent 必须先同步该分支，避免用过时代码下结论：逐仓 `git status` 确认工作区干净 → `git fetch origin` → `git switch <分支>` → `git pull --ff-only` → 记录 `branch@commit`。相关仓库保持同一分支口径。
- 分支同步的安全边界：工作区脏、分支缺失、不可快进或本地克隆缺失时，不覆盖、不重建、不强制处理；改用 `git show origin/<分支>:<路径>` 或向用户说明。仍禁止 push、commit、clone、reset、restore、stash、clean、apply、rebase、merge、cherry-pick、worktree，以及创建/修改/删除 clone_root 内业务文件。代码审计结论必须绑定最终 `branch@commit`。

## 四、多产品线共存

当前结构为**单库组设计**（一份 base_url+clone_root）。要同时挂两组（如财务线+你的产品线）：
- 简单法：把两组克隆放同一父目录，`clone_root` 指父目录（base_url 仅作展示用不影响 grep）；
- 若需严格分组隔离，属配置结构增强，找维护者扩展。

## 五、联动：ZBASE 日志查询的 app_map

zbase-log-query 技能里的 `app_map.json`（应用↔代码仓映射）是**财务线产品的快照**。换产品线后要重抓：
1. 用 zbase-login 登录 ZBASE → 你的产品（productCode 换掉 prddefhov）
2. 应用列表全量 → 逐应用详情页抓"仓库地址"（参照 app_map.json 的 `_meta` 说明）
3. 覆盖生成你的 app_map.json（结构照抄：apps + repo_to_apps 两组）

## 六、不接会怎样

不接 dev_git，agent 的用例设计/执行/报告**主链完全不受影响**；只是上述"源码级证据"环节降级为"问维护者/看知识库"。属于增强项，不是必选项。
