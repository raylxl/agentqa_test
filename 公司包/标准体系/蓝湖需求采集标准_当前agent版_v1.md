## 一、总则

- 目标：把蓝湖（lanhuapp.com）产品原型（axure 跨域 iframe）**原样落盘成可显示图片的 Markdown 需求文档**，供用例流水线使用。
- 四层结构：**标准（本文件，定口径）→ 技能（lanhu-req-extract，做调度）→ 脚本（{paths.蓝湖工具}，做采集与校验）→ 红线（做闸门）**。
- 产物落需求文档权威库（`{paths.需求文档}`），头部 4 行元信息（采集来源/时间/状态/修订），图片目录与 MD 同名 `_images/`。
- **展示原则（2026-11-24 用户拍板）**：蓝湖上怎么展示，采集生成的 MD 就怎么展示；且**兼容各种工具打开**——用什么工具打开，都要能看到蓝湖上展示的内容。
- **展示形态以用户阅读器里实际看到的效果为准**（2026-11-24 教训）：用户在 ZCode 客户端里读文档，客户端把 ```mermaid 代码块**直接画成流程图**。v1.1 把"兼容各种工具"读成"流程图只能靠图片、源码须藏进注释"，结果用户打开一看"流程图没了"。流程图现行做法=可见的流程图代码块 + 图片两层并存（见 R23）。

## 三、红线（继承 v4 全部 22 条，编号不变；摘常引 11 条 + v1.1 增 R23）

- **R1 版本对号**：同名菜单多版本（云仓账单 9.8/10.?），精确匹配叶子节点+点击后回读激活项+内容帧关键标记三证一致才继续，否则中止。
- **R2 问号归一**：配置 `？` 与树 `?` 双向归一后再匹配；菜单名以 probe dump 的树内文本为准。
- **R5 置灰识别**：置灰章节标「⚠️已置灰」，不作计费依据。
- **R6 表格还原**：蓝湖表格必须还原 MD 表，禁只截图；删除线 `~~` 保留。
- **R7 强制重采**：每次采集前重采当前蓝湖并标采集时间——旧文档 ≠ 现状。
- **R8 图片型表格**：宽>1000/高>150 的内嵌大图样表必须下载原图精读后还原 MD 表。
- **R11 就绪判据唯一**：axure 内容帧文本非空=就绪；顶层登录横幅不作阻断判据。
- **R13 唯一脚本**：走标准脚本（{paths.蓝湖工具}），禁一次性脚本当交付物。
- **R14 验收闸门**：四道闸门 + 入库前结构体检——①collect 内置 GATE（截图未落地=exit 3，引用不写入；图示截图数、流程图去向合计须对得上；**页面未渲染不出文档**：点菜单后须等到"文档高超过视口高 或 出现可见文字件"再往下走，最多 60 秒，否则中止；**正文字符数 <20 判红**）②`lanhu_verify.py`（MISSING/表格列数/关键词/残留/流程图块结构，非零退出）③`lanhu_reconcile.js` 对账器（独立质检角色：与采集器同源重访原页，逐文本节点核对覆盖，另查章节序、表格、图示截图、流程图块、**正文被吞进表格**；**coverage=1.0 才算完成**）④`lanhu_fidelity.py` 文字忠实闸（2026-11-19 立：文档文字须能溯源到采集时原页文本；现行判据=文档里每一段都必须原样来自页面：整串**恰好等于**页面上同一行的若干文字按左右顺序拼接，或连续几条文字拼接——按空白拆段"每段是子串"太松，页面上的词换位/重复拼成假行也会放行；**2026-11-24 起没有相似度兜底**，旧法"与源行相似度 ≥0.55 即放行"会放过段落内改一个词/调顺序）⑤结构体检（批量入库前，纯文本）：正文非空、章节标题不在表格数据行的单元格里；⑥漏采审计 `lanhu_uncovered_audit.js`（全量入库前，在线）：页面上可见、但文档里既无文字又没落在任何截图范围内的内容须为 0。不一致绝不声称完成。
- **R14a 改判据必配反向用例**：凡放宽或重写任何一道闸门的判据，须同时用"故意弄坏的文档"验证它仍拦得住（换词、调序、页面词拼假行、自撰句、删表、删连线…），全部拦截才算合格；只看真文档变绿就上线，等于把闸门拆了。用例要覆盖最不利情形（短段落、只改一个字、用的字页面上都有），并随工具入仓（`lanhu_exec/selftest/`，样例用合成数据，不放进真实需求内容）。
- **R20/R21 OCR 取证**：每张交付图身份经确认后才命名；模型不能读图时 WinRT 替代。
- **R22 采集忠实**：产品没画的就是没有；禁写"待确认/疑点/建议"类编辑性标记入文档——疑点在对话里说。
- **R23 流程图还原（2026-11-24 用户确认；v1.2 更正展示形态）**：蓝湖上画成流程图/图示的，文档须以流程图呈现，**重建不出才降级**。每张图三层：
  ①原图截图（2 倍像素，蓝湖原貌）
  ②**可见的 Mermaid 流程图代码块**（```mermaid 围栏——支持流程图的阅读器如 ZCode 客户端、Typora 直接显示为流程图；节点文字可检索，读文档的技能/模型也读得到）
  ③渲染图（`流程图渲染_*.png`——给不支持流程图代码块的阅读器、转 Word 用）。
  拓扑由页面几何机器重建（Axure 连接器箭头的 SVG 里自带整条连线路径），不靠模型看图；两套独立方法结果一致才采信。
  重建不出或渲染不出，才降级为"截图 + 逐行节点文字"。**禁把流程图代码块藏进 HTML 注释**（v1.1 的做法，2026-11-24 实证：用户阅读器里流程图整块消失）——文件校验与对账器判红。
  支持流程图的阅读器里，流程图会出现两次（代码块画出来的 + 渲染图）：这是"兼容各种工具"的已知代价，不算缺陷。

## 四、两条采集路线

- **路线 A（默认）`collect_lanhu_req.js`**：正文 DOM 保真提取+全页图片扫描+按章节插图+内置分类器/闸门。适用离散大图。
- **路线 B（视觉还原）三步**：`extract_lanhu_visual_v3.js`（整帧+_diag.json）→ `assemble_visual_md_v2.py`（面板裁图+y 序组装）→ `convert_to_relative_png.py`（base64→相对 PNG）。适用 axure 碎片小图拼面板。
- 选型判据：图离散大= A；碎片拼面板= B。两路线产物都必过 lanhu_verify。
- **介质忠实原则（2026-11-18 用户拍板）**：蓝湖上是位图的内容（弹窗 mockup 等）→ 文档出**截图**；蓝湖上是 axure 文字/表格 → 文档出**文字/MD 表**，互不替代。列表页 mockup 的**查询条件区（控件排：按钮组/输入框/下拉/查询重置）用一张截图**表达，插在对应列表表格前（extract 自动识别"表格前导控件带"，collect 截图落位 `查询条件_N.png`）；列表本体仍用 MD 表。

## 五、批量与增量

- 批量=技能层循环（菜单清单 lanhu_menus.json 或 probe dump → 逐菜单单采 → `.batch_progress.json` 断点续传 → 单菜单失败不中断）。
- **批量（现行，2026-11-24 立）=`{paths.蓝湖工具}/batch_recollect.py`**：`run` 逐菜单 采集 → 四道闸门 → 结构体检，产物先落**暂存区**、逐菜单状态落盘、断点续传；`report` 汇总（含新旧文档文字差异）；`land` 阶段才动权威库——旧版 md 与 `_images` 整体移入 `历史版本\全量重采前_<日期>\`，新版拷入，入库后逐字节比对；默认只预演，`--apply` 才执行。**采集器或检查代码一变，必须 `--rerun-ok` 全量重跑**（旧的"已通过"不代表现行代码的产物）。
- 增量=`lanhu_diff.py` 小节签名比对 → 仅重采 CHANGED → 升版本号、旧版入历史版本 → **变更摘要呈报用户拍板**是否传导用例（feedback-loop 接口）。

## 七、实测坑（1~6：2026-11-18 首战；7~14：2026-11-24 税务信息维护复盘；15~18：2026-11-24 全量重采，细节见执行坑库 G100）

1. 菜单名含 `/？:` 当文件名=Windows 非法（脚本已 sanitize；--name 自行规整）。
2. 池实例无头态 `el.screenshot` 卡 "waiting for element to be stable"——collect 已内置 bbox+clip 降级，且截图未落地不写引用（闸门 exit 3）。
3. Playwright 1.64→1.65 API 漂移：`addStyleTag` 返回句柄无 `.remove()`（已改 DOM remove+dispose）。
4. browser_pool 正本位首跑两坑：`locks/` 目录缺失；生成的 ps1 无 BOM 被 PowerShell 5.1 按 GBK 误读（已修池代码带 BOM 写入）。
5. 三候选 sid 实测等价（同项目 tid）；换产品直接 `--url`，零改代码。
6. **G65 内容级清理规则=隐形删除器**：cleanResidue 曾有"政策列表整表删除"规则（表头含政策ID/政策名称+创建时间→整块删），一次性残留清理被误当管道通用规则——正文真实示例表被无差别处决（空仓整表/货量第二表实证）。铁律：**管道禁做内容级删除（R22），残留清理只走 verify --olds 显式清单**。另：axure repeater 行异步渲染→提取前须等可见文本节点数稳定（collect 已内置）。
7. **G85~G86 只按文字坐标猜版面=四道闸门假绿**：旧法"文字顶部坐标差 ≤25px 归一行、x 坐标按 80px 聚类定列"——行距 20px 的表两行挤一行、无边框迭代表散成文字（版本归属错位）、流程图节点排成假表格；对账器用同一套猜法所以同错同过。对策：几何预扫描——单元格小图/描边件贴合成网格=表格（文字按中心点入格），节点+连接线=图示。
8. **G87 叠放格与控件值**：冻结在滚动区外的"操作"列叠在"纳税人资质"列上，叠放列在文档里的先后因页而异——不能按先后取格；对策：同一行相邻的控件成组、按"被哪个格完整包住"归格，与格等宽的文本按左右沿贴合度归格。行操作按钮的值在 input 上、不在文字件里，须单独取。同一滚动容器内被后画的格盖住 ≥90% 的格=隐形格，其内容不入文档。
9. **G88 多行文本件并排=两栏**：左右两栏各是一个多行文本件时，旧法用空格拼成一行（右栏标题粘到左栏末句后面）。对策：同行有 ≥2 个多行文本件就逐栏输出，且两栏块禁搬、不作浮层锚点（否则一栏会被塞进另一栏中间）。
10. **G89 横向可滚动的面板**：可视 959 宽、内容 3718 宽的列表，元素截图只拍得到左边；"把面板撑开"也拍不到（iframe 外的内容不渲染）。对策：面板按步横向滚动逐条截图，按滚动位置拼成整表（`stitch_at.py`）。冻结在面板框外的覆盖列不在整表截图里，其文字在 MD 表中。
11. **G90 文字忠实闸无源**：`leaves_text.txt` 此前只由旧路线 B 落，现行路线 A 不写缓存，忠实闸实际在拿旧缓存比对。对策：采集器自己落"本次所见"的可见文字与控件值。
12. **G91~G92 流程图还原**：①SVG 源码里有换行，`<path` 与 `d=` 之间不保证是空格——按"前一个字符是空白的 `d="`"取，并排除 `id="`；②端点可能离节点框留缝（产品挪过框、连线用线段补缝，实测 25px）——允许"轴向对齐且缝 ≤48px"；③流向按"箭头进入目标节点的方向"判（按外框宽高会把上下结构的树判成左右），分支排序左右流向按连线最上沿、上下流向按终点横坐标；④Playwright 的 `page.screenshot` 会把图归一成 1 倍像素，要 2 倍须走 CDP `Page.captureScreenshot`；⑤一个多行文字件整块成了连线标注时，标签溯源须认"整体相等或逐行都相等"。
13. **池化输出不接管道（执行坑库 G98）**：`pool_run.sh` 的输出若接 `| grep` / `| tail`，心跳子进程的 `sleep 300` 会占住管道，命令要卡满 300 秒才返回（脚本其实早跑完）。一律重定向落文件再读。
14. **G93 流程图代码块藏进注释=用户眼里"流程图没了"**：v1.1 为了"不依赖特定阅读器"，把 Mermaid 源码放进 HTML 注释、只留图片（税务信息维护 v5）；用户点对话里的文件链接在 **ZCode 客户端**里读文档，客户端把 ```mermaid 代码块直接画成流程图——藏起来后用户的原话是"怎么流程图没了，还没上次展示的好"。教训：①"蓝湖怎么展示就怎么展示"的验收尺子是**用户阅读器里实际看到的样子**，不是我对原则的推演；②改展示形态前先弄清用户用什么读，改完请用户看一眼再放量；③用户已明确要"兼容各种工具"，就两层并存（可见代码块 + 图片），不要为了"不重复"自作主张砍掉用户看得见的那层。
15. **页面没渲染也照采、空文档判通过**（配送价格 11.30）：点菜单后 axure 页偶发不渲染（文档高停在视口高、可见文字 0），采集器照常采出 5 行 87 字的空文档，内置闸门只查图片/图示/章节数，全绿放行；靠独立对账器的覆盖率=0 才拦下。对策：等到"文档高超过视口或出现可见文字"再采（最多 60 秒）；闸门增"正文字符数 ≥20"。
16. **罩在表格上的大文本框被按中心点归进格子**（报价时效查询、外部参考价）：页面上一大段正文是一个几百像素高的文本框，罩在下方小表上；文字按"中心点落在哪个格子"归格，整段正文成了表格单元格内容。表头一致、行数一致、文字可溯源，四道闸门当时全绿。这是几何归格法引入的退化（旧法不按几何归格，没有）。对策：文字件须"装得进"格子才归格；对账器增"正文被吞进表格"检查；入库前做结构体检。**排查这类问题不能只靠"单元格里有没有章节标题"**——外部参考价被吞的那段不以标题开头，是靠"改前/改后"逐菜单对比才查出来的。
17. **行距小于聚行阈值，页面上下两行被并成一行**（对客报价 4.28 / 11.30）：行距 23px、聚行阈值 25px，"标签…单位"与"首价…单位"上下两行落到同一列后被空格接成一行。新旧文档同型——旧版就有，是忠实闸换成严格判据后才照出来的。对策：同一列里上下叠放的两件用换行接，并排的仍用空格。**教训**：改闸门判据时，"放宽 → 假文档漏过 → 收紧 → 真文档又红"反复了十余轮才收敛；先测量（把过不了的块按页面几何分类统计）再定规则、每次改动配反向用例，才走得直（见 R14a）。
18. **"没人管"的表单控件既无文字也无截图**（报价计算 7.14、报表准确性核对工具 9.28 旧/新；旧文档同样没有）：查询条件带的截图都以下方紧挨着的表格为锚点——工具栏下面没有表格的页面、以及不在任何表格/面板/图示里的复选·单选选项，"查询 重置"被当按钮行清掉、又没有截图承载。靠"漏采审计"（逐项核对页面可见内容的去向）才发现：四道闸门只核 6 字以上的文字件、且豁免面板内的内容。对策：未被任何区域消费的控件两两判相邻（垂直间隙 ≤130px 且水平间隙 ≤450px）后连通成块，一块 ≥2 个控件就拍一张截图，插在它下方第一个内容块之前（介质忠实：控件 → 截图，不出文字）；零星单个控件不拍。聚类别用"只往最后一个簇里合并"的单链法——多行多列的表单后面几行接不上前面的簇（实证漏下十来个控件）。
