## 1. 用例定义与条目格式（五列表，逐条严格执行）

**用例定义（2026-10-28 用户定稿，v1.7）**：测试用例=基于需求内容设计、每条验证一个需求功能点/拍板口径的可执行条目（含可观测预期断言）；**用例所需基础数据不归属用例**——〇位为「执行前数据准备（非用例）」：PRE-xx 编号、不计入用例总数、不进 XMind；准备项不承担需求覆盖（需求口径断言须在正文功能章有用例主条）；各用例前置可引用"共享数据见 PRE-xx"（禁例间引用的唯一例外，见 §2.5）。

```
#### TC-{模块缩写}-{序号} 标题（P0）

| 列 | 内容 |
| --- | --- |
| 前置条件 | 1. ...；2. ... |
| 操作步骤 | 1. ...；2. ... |
| 预期结果 | 1. ...；2. ... |
| 判断依据 | <规则一句话>（源：理解说明 §x / 拍板 Qx） |
| 测试方法 | 场景法/等价类划分/边界值/判定表/因果图/状态迁移/正交与成对组合/错误推测/角色-功能矩阵/并发与时序设计（按 §22 选择，可组合） |
```

- 现行用例优先级采用 **P0/P1/P2/P3 四级**，标在标题行括号内（表内不放优先级行；【必须验证】类标记已停用）。完整判定、风险映射、执行集和发布出口见本标准 **§1.1** 与《测试策略与风险治理标准_v1》；历史册中的 P0/P1/P2 原标签不因本次升版自动重分类。
- **P0 关键阻断**：核心主链、资损/计费错误、数据丢失、权限/租户隔离、合规或安全暴露；必须执行，任一未通过阻断出口。
- **P1 高风险重要**：重要业务规则、状态流转、主要异常路径、高频功能、影响可用性的关键 UI/体验；进入回归集，按出口阈值判定。
- **P2 一般风险**：普通边界、一般异常、低频组合、重要但非主链展示/交互/兼容；进入全量或专项集，失败和未执行必须有处置。
- **P3 低风险观察**：纯装饰性样式、极端长尾组合、历史兼容/低频体验观察；默认不进入日常回归，可专项、抽样或人工执行。P3 不得承载资损、权限、数据、核心流程或安全风险；命中更高风险规则时按最高级别升档。
- **优先级与缺陷严重度分离**：用例优先级字段 `case_priority` 与缺陷严重度字段 `defect_severity` 分开，二者均可使用 P0~P3，但不得互相直接推导。
- 判断依据**必须内嵌**并标注出处（理解说明章节/拍板编号/本标准 §号）；Q 编号**只允许**出现在判断依据行与文件头/导语/修改记录区。
- 表格多值用 `；`，换行用 `<br>`；序号两位起（01…），超 99 自然升三位；各章内连续递增，跨章靠前缀唯一。

### 1.1 四级优先级判定与升档规则（P0123·2026-11-11 现行）

1. **先判风险、后定级别**：优先级是测试资源分配器，不是缺陷严重度；同一测试点命中多条规则时取最高级别。
2. **关键风险硬升 P0**：资损、计费金额、核心流程主干、数据丢失/泄露、权限或租户隔离、安全/合规、不可逆危险操作，最低为 P0。（2026-11-19 拍板：资损/数据丢失/权限隔离/安全合规=**公司级判据**；"计费金额"=财务线的资损形态词，词表正本=agent-company.json 域词·分诊完整档判据，第二线接入换词表不换原则）
3. **P1 不得被普通展示化**：重要业务规则、状态流转、主要异常、高频功能或影响操作可达性的 UI/体验至少 P1。
4. **P2 适用于一般风险**：普通边界、一般异常、低频组合、重要但非主链的展示/交互/兼容场景。
5. **P3 只放低风险观察**：纯装饰、极端长尾、历史兼容或低频体验观察项；必须写明不影响主流程、数据正确性、权限隔离和安全。
6. **只升不降**：不得因“场景少”“实现简单”“只在界面上”“可以人工看”而降低关键风险级别。
7. **级别调整留痕**：从旧级别迁移到 P0123 或执行侧提出升降级时，记录原级别、新级别、理由、影响范围和拍板出处；执行侧不得私自改级。
8. **标题格式统一**：新册标题使用 `（P0）`、`（P1）`、`（P2）`、`（P3）`；工具链遇到缺失或未知级别必须报错，禁止静默漏计。

## 2. 执行规范六条（每条逐条满足）

1. **前置到字段值**：造数写死具体值（名称/日期/段值/金额全写死），禁止"已有一条报价"式模糊前置。
2. **步骤到控件**：菜单→按钮→输入值完整路径（例：财务→XX价格→【新增】→费用名称选…→【保存】）。
3. **预期到可观测**：具体展示值/文案/条数/状态/金额（含完整算式）；空值写明展示形态；不命中类断言用**双断言**（账单无费用行 + 结算交易记录无记录）。**负向排除断言三问**（配送补）：无 X？→实际命中了谁（兜底归属，正向断言）？→账单与交易双断言？（教训：配送漏"未审核 A 落兜底 B 正向"，排除类断言止步"无 X"）
4. **判断依据内嵌**：见 §1。
5. **禁用例间引用**：预期结果不得引用其它用例编号或其执行结果；唯一例外=前置可引用执行前数据准备项 `PRE-xx`（〇位数据准备节，非用例）的共享数据。
6. **独立可重复**：每条可独立执行，造数用本模块 TEST_ 前缀隔离；两可形态（级联初始态/清空可否/默认值形态等）写"形态甲或形态乙均合法、执行记录实际形态"，不作失败判定。**元规则：两可/多可设计仅限用户明确确认过"都可以"的场景；AI 自判"两可"=违规活口，必须先问用户。** 双形态识别前置：需求规则可能多种实现形态时（如首段"默认0+锁定"或"可编辑+拦截"），先设执行识别前置条——形态A（锁定）识别确认即过、形态B（可改）按校验构造拦截。

## 4. 静默修正四式与导入例外（铁律，反复纠偏固化）

**数值/金额输入框**对非法或越界输入一律**静默自动修正，从不弹提示**：

> 〔线级条款·财务线〕本节金额/数值类约定（静默修正四式、数字不补零、数值 0 允许、计费金额舍入、小数举例规矩、计价要素互斥）=财务线产品与拍板产物（2026-11-19 用户拍板：静默修正归**财务线**、非鲸天系统级）；"导入例外=用户手写内容不加工"与"文本框超长截断"原则本身为跨线方法论。

| 输入情形 | 正确预期（不弹提示） |
| --- | --- |
| 超上限 | 钳位为最大值并展示，保存成功 |
| 负数/低于下限 | 钳位为最小值（归零），保存成功 |
| 非数字 | 置空（保存时按必填处理） |
| 整数框录小数 | 四舍五入取整，保存成功 |
| 小数框超位数 | 四舍五入保留规定位数，保存成功 |

- **仍提示拦截的仅有两类**：①业务规则校验（跨字段约束、起止关系、段不交叉、唯一性/判重）；②必填项留空。
- **导入例外**：批量文件场景**不适用**静默修正——所有字段级/规则校验失败（含数值越界、负数、非数字、超精度、跨字段、段规则、判重、必填缺失）均**整文件失败+错误明细按行输出**，数据库无新记录。Excel=白纸：界面控件拦得住的限制导入全部可手写绕过，校验全部后置到导入时执行报错。
- **★导入口径拍板归一（2026-10-28 用户定稿，普适不分需求族）**：导入文件**不做任何静默修正处理**——文件属**用户手写内容**，系统不做加工，**按手写内容原样校验**，任一行校验不过即**整文件失败+错误明细**。上游逻辑参考 〇.5 早期一句"导入与页面同修正（修正后入库不判失败）"**作废**（其自身 §八/红线§八·导入例外与本拍板一致；上游源文件由用户在维护方删除，本地快照只读不动）。
- 导入只测**模板字段+字段逻辑**（对齐/校验/合并/原子性），禁测"文件本身"（空文件/非Excel/表头错位）。
- 文本框超长=限制输入/自动截断（静默），禁"提示超长+拦截"。
- **数字不补零**：输入与保存后详情展示均为输入原样（输 2 显 2 非 2.00、输 1.5 显 1.5），任何精度字段不按精度上限补零；导出原值同理（2.5≠2.50）。
- **数值 0 允许**：需求写"支持输入 0-XXX"的字段 0 合法可保存，除非需求明确排除。
- **计费金额舍入**：所有明细加总后**统一**保留两位（非逐明细先舍入再合计）。
- **小数举例规矩**：造数举例禁用 0 结尾数字（看不出舍进）；两位小数看第 3 位定舍进、四位小数看第 5 位。
- **明细段计价要素互斥合并判定（2026-10-31 配送拍板，报价类通用）**：源 PS"单价、最低收费不允许同时为空"与"基础数量、基础价格、续价不允许同时为空"**合并为一条**——"单价"=基础价格（重量维度=首价）或续价任一；有效约束=**计价要素{基础价格/首价、续价、最低收费}至少其一非空**（一口价/仅续价/仅最低兜底均合法，三者全无才拦截）；"基础数量与基础价格同空同有"继续独立生效。计费侧对应：计价要素仅最低时，段费用=夹取下限（空公式段费用按 0 计，转测校准）。

> **R2 节头澄清注记（v2.1，2026-11-01 平台价格门禁复检用户拍板"从严清理"）**：R2 的"章节标题"**含 ### 小节节头**，与用例标题（####）同规——节头禁挂答疑/拍板/红线/方法论编号（Q/#/S/R/T/F/M/N 等）；节头括号内的**口径说明文字**（如"按钮全展示/置灰仅看勾选/保存确认时拦截"）不属编号、允许保留。拍板理由：用例是**覆盖需求内容**的，不是供使用者对标的；判断依据属用例附属信息，**唯一落点=判断依据格**（文件头/导语/修改记录区除外）。编号溯源删自节头后不丢信息——每条用例判断依据格本就各自挂（源：拍板 xx）。首例：平台价格 v3.9 清理 6 处节头（5.4/6.4"T13"、13.5"#16"、13.6"#15:"、13.8"S5"、13.11"S15:"），全族扫描其余四族零同类命中。

## 13. 通用断言写法六条（G1~G6，2026-10-31 云仓账单 34 项答疑沉淀；全需求族适用）

> 本节按"只新增不修改"置于修订记录之后编号。来源=云仓账单 10.? 需求闭环拍板（F13/F18/F19/F7/F4/F16/F12/F6/F15），经用户 2026-10-31 指令"抽离用例编写标准"入标。

1. **异步时间不作绝对断言（G1）**：跨系统异步链路（账单→结算、任务队列）中的时间字段（交易时间/完成时间）**不作"=操作时间"断言**；快照类断言锚定**触发时点**（如"导出文件内容=任务提交时查询结果"）。（源：F13/F18/F19）
2. **提示存在性断言（G2）**：需求未定文案的操作反馈，断言"**有提示信息**"，不断言具体文案。（源：F7）
3. **源字段跟随断言（G3）**：字段口径="取上游系统当前值"时，用例**不写死值**，断言"=上游当前值"；且**正反向场景都要做**（上游给 A 显 A、给 B 显 B）。（源：F4/F16）
4. **无上限边界探测定界（G4）**：需求未设上限→按**历史常规边界**设计双用例（N 可行 + N+1 可行，预期均通过），实际存在拦截即校准发现（预期方向=不拦截）。（源：F12，单号框 1000/1001 行）
5. **结果集级动态展示断言（G5）**：列/模块按查询结果集动态判定时，断言**绑定当次查询结果集**，并必覆盖：换条件重查重算、空结果集形态（含全量角色如总部）。（源：F6/F15）
6. **跨菜单留痕两线（G6，§2.3 双断言的正向扩展）**：操作菜单内无痕时，留痕断言落**关联菜单两线**（如 事件记录+交易记录），各锚定**可断言字段**（创建人/创建时间），**不可断言字段显式声明"不作断言"**。（源：F13）

### 15.1 答疑阶段疑问呈现格式（五段式·一次一问）（源：通用规范 v25 §12.5）

- **闭环纪律**：拍板即登记进理解说明/正本对应章节，不得同题反复追问。
- requirement-qa-loop skill（四段式→五段式）已同步落地（2026-11-02）。

### 15.2 理解元规则：先查标准→结合已知→再提问（源：按钮参考 v1.10 〇.12）

遇入参/字段用途不明：先查本标准+云仓租户标准，再结合同族已沉淀计费规则联动理解（例：计费查询接口"特殊属性"入参，孤立看无用途，结合拦截费优先级规则即知=匹配优先级维度），都不通才提问；禁孤立盯当前需求文本直接抛问。

### 15.3 通用断言补条 G7~G9（接 §13 G1~G6；源：通用规范 v23/v24 §11.2）

- **G7 上游数据消费原则**：取自上游系统的字段只断言"值=上游当前值"，**禁造"上游变化后按某种规则处理"的假设性断言**（"温层清零还是累计"类二选一提问本身不成立——属上游内部逻辑，消费方无此概念）；上游会怎么变不进用例假设，只设"上游值变→下一事件/重算按新值走"的取源断言。（源：v24，存储账单 Q19 教训；与 G3 配套——G3 管"取什么"、G7 管"别假设上游怎么变"）
- **G8 派生/回退字段四腿矩阵**："A 空取 B、A 有取 A"类派生字段（如结算重量=三方重量优先否则理论重量）按变化矩阵**四腿**各一条：初始态 / 底源头变化跟随 / 新源到达覆盖 / **新源在场时底源头再变（仅展示列更新、派生值与金额不动）**，每腿单独断言金额联动与否；禁只测初始+覆盖两腿。（源：v23①，云仓账单 F3 教训）
- **G9 取源当前值（不缓存不冻结）+ 转测校准清单固定化**：上游取数断言锚"当前值"，须设"改源→新事件→匹配随新值走"专条（匹配窗口随源变更而变=高风险回归点）；实现选型类细节（任务菜单名/提示文案形态/时间边界开闭）不阻塞设计、不逐项追问——按拍板或倾向口径**写死预期+行内标注"转测校准"**，文件尾固定附「转测校准清单」章节集中管理。（源：v23③④）

### 15.4 批量操作原子性分型（源：按钮参考 v1.12 〇.14，整体通用）

- **A 整批原子型**（数据有组内一致性要求：导入/审核通过/审核驳回/删除）：任一条失败→整批失败全不生效。**B 逐单独立型**（逐条独立加工各自成事：重算）：成功的生效、失败的提示，互不影响、不整批拦截。
- 设计前先判型："这个批量操作的数据是一个整体单元（一损俱损），还是各条独立加工（各自成事）？"——需求未写明**必须向用户拍板**，禁自判。
- 两态用例必备：A 型断"部分失败→全批不生效+失败原因标注"；B 型断"成功条生效+失败条提示+互不影响"。

### 15.5 单号查询两模式判型（源：按钮参考 v1.14 〇.16，通用）

- 需求写法"单号A/单号B：多行文本框"（斜杠共框）**≠两个独立框**——设计前先判型（无依据时问用户，控件形态不明确先问再设计；云仓账单 v1"两独立框"返工教训）：**A 一框+维度下拉**（选什么维度按该维度解析）vs **B 前缀自动识别**（按单号前缀归类 OR 查询）。
- A 模式七用例必覆盖：①维度精确命中；②**维度不匹配查无数据**（选订单号输运单号，不报错）；③**混填仅命中选中型**（异类型号按"不存在"处理）；④同维度多单号 OR（一行一个）；⑤单号互斥（其它条件后端忽略、前端不清空）；⑥切换维度行为（转测校准）；⑦控件形态断言（一框+下拉、无第二单号框）。

### 15.7 权限粒度三层模型（源：数据权限 v1.6，通用框架；云仓实例口径=云仓租户标准 §2.1）

- 同一列表行内多数据模块各有独立权限维度的菜单，三层粒度：**第一层·行过滤**（主维度 OR/AND 按需求拍板判整行可见）；**第二层·模块可见性**（行内各模块按各自维度的上级链独立判——A 模块有权≠B 模块有权）；**第三层·呈现粒度=单元格金额**（**表头/列结构恒全可见**，无权限仅该行该模块费用项下金额格展示空——非整列裁剪、非打码；导出与页面同形态）。
- 两条铁断言：权限底线（无权限金额格不得出现任何数值，混合行一屏对照：同列有权行有金额、无权行空）+表头完整（无权限账号列表/导出列头仍完整，防整列裁剪实现）。
- 必测组合 2×2：双线命中（全模块有金额）/单线命中×2（镜像各一条）/双线不命中（行不可见）。
- **云仓账单差异标注（2026-11-02 用户拍板"用动态判定设计用例，用全展示兜底"）**：云仓账单菜单以**结果集级动态判定为主形态**，本节"表头恒全可见"为其**兜底形态（不判缺陷，本节两条铁断言仍须成立）**；两形态均合法、执行记录实际形态；任一形态硬断言=无权限侧金额格零数值。详见云仓租户标准 §2.1 差异标注。

### 15.9 两层校验顺序必测（源：完成定义与生成工序标准 §三.1）

控件级静默修正先行、跨字段业务校验后置（例：最高收费 -10→钳位 0→再按"最高≥最低"拦截）——两层校验的**执行顺序本身是必测点**，与 §4"仍提示拦截的两类"配套出条。

### 15.10 全局口径声明写法（源：完成定义与生成工序标准 §三.2）

某属性在全册 ≥95% 用例中同值时，用"文件头全局默认声明 + 例外逐条显式标注"替代逐条标注（成本零、效果同）。

## 16. 通用计费规则调整答疑沉淀·通用条目（v2.6，2026-11-03 云仓通用计费规则调整 11.30 答疑沉淀，用户拍板入标；全需求族适用）

### 16.1 通用断言补条 G10~G12（接 §13 G1~G6、§15.3 G7~G9；同批双接口切换模式经用户拍板**不入本文件**、归云仓租户标准 §2.6——当前云仓做法非通用纪律）

- **G10 拆分费用项不折叠计数**：费用项的计数与枚举一律以**系统实际费用项**为准，不以需求文档的合并叫法折叠。需求写合并名（如"分拣费"）而系统为拆分项（**整箱分拣费/拆零分拣费**两个费用项，各自独立配报价、独立出账单行）时：计数展开到实际项（写 6 项不写"5 项含分拣"）；用例覆盖逐项设计（整箱、拆零各有正反/边界）；造数与断言按实际项（报价分别维护、账单行分别断言）。新需求拿费用项清单先核对是否存在拆分项。（源：通用计费 11.30 R1 终版拍板，用户纠正"是 6 个，分拣费是拆分的两个费用项"）

- **G11 假占位链接断言法**：需求文档中的 URL/链接若为**占位**（判据：目标页面未上线、产品给不出真实地址，典型于新模块未转测期），链接类断言按**功能断言**而非字面断言：①点击后正常跳转到目标页面/菜单（跳转动作成功+目标正确）；②**不校验 URL 字符串与需求文字一致**；③配套权限断言：无权限用户点击**跳不过去**（显示登录首页/无权限页），属预期降级非缺陷。（源：通用计费 11.30 R2 终版拍板，用户说明"菜单都没转测、产品不可能知道新地址"）

- **G12 未定义即不测+呈报义务**：需求只对部分对象定义规则时，未覆盖对象**不擅自编写同构推导用例**（不把 A 项的规则套到 B 项上编用例）；未覆盖对象仍测需求已定义的通用部分（如缺整项报价提示）。**但测试设计者想到的"需求文本之外的衍生场景/额外疑点"必须逐条呈报需求负责人拍板**（测/不测由用户判断），**禁止自行吞掉**——需求没写、双方都没想到是漏；需求没写、我想到了而不报=测试之漏，正好覆盖"原需求内容衍生之外、用户没想到"的部分。呈报后拍"不测"的挂观察哨（执行中真实出现再升级为正式疑问），不因低概率场景阻塞主线。口诀：**需求写了才测；没写的——想到了必报、报了等拍板、拍了不测才不测。**（源：通用计费 11.30 Q40/16.6⑥ 两例沉淀 + 2026-11-03 用户改措辞拍板"是未定义的不测，但你需要提供给我非需求内容外的东西，我来判断测还是不测"）

- **G13 覆盖对账须含非编号强口径**：覆盖清单（BRIEF 覆盖要求+门禁 A"拍板逐项"）之外，还须对理解说明做一次**非编号强口径扫描**：凡带"须测 / 回归确认 / 重点关注 / 待验证 / 回归即可 / 测试重点关注"字样的结论段（代码走查回填、正文断言、终检推演定稿），逐条列入覆盖对账、逐条找落位 TC，无落位即缺口。（源：通用计费 11.30 WB 对比——代码走查明写"三个直接上级取值路径回归即可"，却因不带拍板编号被门禁略过漏 1 条；第 4 次印证"拍板 100% 映射≠全覆盖"，且本次漏项不来自任何拍板；2026-11-03 用户拍板入标）

## 21. UI 样式测试（功能测试的组成部分·2026-11-10 用户定规立标）

**定位**：UI 样式是功能测试的一部分——用户通过界面完成业务操作，界面有问题导致用户完成不了任务或体验降级，即功能问题。测试设计者对界面的**功能与 UI 样式一并负责**。

### 21.1 五类 UI 样式测试

| 类别 | 测什么 | 断言方式 | 优先级参考 |
| --- | --- | --- | --- |
| **跨菜单一致性** | 共用组件（按钮/图标/颜色/字体/间距）在同系统不同菜单间视觉一致 | 对比断言（"与 XX 菜单一致"） | P2 |
| **布局正确性** | 元素在预期位置（导航/内容区/操作栏/分页），对齐/间距/比例正常 | 位置断言（"分页位于列表下方"） | P2 |
| **内容展示** | 长文本处理（截断/浮框/换行）、空态/加载态/错误态、数据格式化 | 形态断言（"浮框有宽度限制""长文本换行"） | P1~P2 |
| **交互反馈** | 悬停效果/焦点指示/按钮状态（常态/悬停/激活/禁用）/加载动画 | 行为断言（"悬停出现浮框""禁用不可点"） | P2 |
| **可用性守护** | 元素不遮挡、不截断关键信息、不影响操作（按钮可点击/数据可读取） | 负向断言（"浮框不遮挡操作列""列宽不截断金额"） | P1 |

### 21.2 UI 样式用例设计规则

1. **有缺陷单就有用例**：开发优化/缺陷单修复了 UI 样式问题 → 必须有对应守护用例（防止回归）
2. **断言到可观测**：不写"界面美观"，写"操作列按钮样式与同族菜单一致"或"浮框最大宽度不超过屏幕 50%"
3. **对比法优先**：跨菜单一致性用"与 XX 菜单一致"对比断言，无需绝对规格
4. **守护法兜底**：一次性样式修复出简单守护条（"还是对的"级别），P2 观察级
5. **可用性问题升优先级**：样式导致操作不可达/信息不可读 → 升为 P1（本质是功能问题）

### 21.3 与功能用例的关系

- 功能用例管"做对事"（数据/计算/状态/流程）
- UI 样式用例管"好好呈现"（一致/布局/可读/可达/反馈）
- 两者合在一起 = **完整的用户体验质量守护**
- 排版归属：UI 样式用例放入 IMP 章（实现行为固化）或独立"UI 样式"节

## 22. 通用测试设计方法与覆盖选择矩阵（L1 方法论正本·2026-11-11 归属迁移）

> 本节承接《执行期参考_鲸天AI自动化测试-用例编写标准.md》旧 §6.1~§6.5 的设计方法知识。逐字原文快照见《执行期参考_旧版设计方法矩阵_原文保全_v1.md》，执行期参考文件另保留历史附录；现行方法定义与选择以本节为正本。方法按需求要素选用，可多法组合；不得用固定条数替代分析，也不得替代 §14 四源覆盖证明。计费/匹配排序全集穷举、相邻对决等专项见《计费专项标准_v1》§8。

### 22.1 设计步骤

1. **解析需求**：列出功能点、输入字段及约束（类型/长度/必填/枚举/范围/默认值）、条件—结果规则、流程/状态、角色/权限、异步/并发/时序和输出载体。
2. **按特征选法**：对每个功能点按下表选一种或多种设计方法；在覆盖矩阵记录采用方法及其理由。
3. **按方法展开**：根据各方法的覆盖元素生成用例；方法不是用例条数目标，也不能替代原文逐句、拍板、上游规则和交叉时序四源证明（见 §14）。
4. **反向自检**：逐项核对方法要求的等价类、边界、规则列、流程分支、迁移、组合、角色路径是否有用例落位；无法执行或超出本轮范围的，明确标记阻塞/待拍板/不测处置，不虚报覆盖。

### 22.2 需求要素与方法选择

| 需求要素特征 | 推荐方法 | 最低覆盖要求 |
|---|---|---|
| 输入字段/表单（文本、数字、日期、文件、枚举） | 等价类划分；存在范围/长度/数值约束时叠加边界值分析 | 有效等价类至少由正向用例覆盖；不同失效原因/处理结果的无效类分别覆盖；数值覆盖上下界及边界相邻值，长度覆盖空/最小/最大/最大+1（按字段允许范围调整）；枚举每个业务取值至少一次，确认为等价的取值可在覆盖表声明合并依据 |
| 条件组合决定业务结果 | 判定表；条件有依赖、互斥或因果约束时先用因果图整理 | 列条件桩与动作桩；每个可达且结果不同的规则列至少一个用例；不可达组合写明约束，不伪造用例 |
| 端到端业务流程 | 场景法 | 基本流至少一条；每个会导致不同业务结果的备选流至少一条；取消、驳回、超时、恢复等按需求和风险展开 |
| 单据/任务/报价状态流转 | 状态迁移法 | 每个合法迁移至少一条；关键非法迁移与终态后的操作按风险覆盖；状态前置不得在全族用例中写死而不变化 |
| 多参数查询、筛选或配置组合 | 正交/成对组合（pairwise）作为降组合数手段 | 先识别硬约束和关键高风险组合；输出组合覆盖依据与未覆盖组合处置。不能用 pairwise 替代计费专项明确要求的全集穷举或风险强制组合 |
| 多角色/数据权限 | 角色-功能/数据范围矩阵 | 对每个关键角色覆盖有权成功、无权不可达；列表、精确查询、详情、导出、接口等通道按权限风险展开 |
| 历史缺陷或高发错误 | 错误推测法 | 从已知缺陷、代码变更、实现复杂点提出可验证反例；每个反例必须关联风险/来源并转为可判定用例，不以经验猜测代替需求证据 |
| 并发、重复提交、幂等、竞态 | 并发与时序设计 | 定义并发/先后关系、观察窗口和最终一致性断言；高风险场景尽量以接口/数据证据验证，无法自动化则明确人工或阻塞处置 |
| 跨操作、跨规则、跨菜单的交互 | 交叉矩阵/双向时序矩阵（与 §14 源四衔接） | 对可能产生新结果的规则对逐格指定用例归属；有金额账本时检查关键操作双向先后，不以各章分别覆盖代替交叉覆盖 |

### 22.3 方法组合和取舍原则

- 一项需求可同时用多种方法：例如金额输入同时做等价类和边界值；政策资格用判定表展开审核状态×生效状态；端到端审核链用场景法并用状态迁移补齐合法/非法转换。
- 组合数较大时，先删除逻辑上不可达组合、合并有证据支持的等价输入，再考虑 pairwise；保留组合裁剪说明。高风险组合、关键边界、用户明确要求、计费专项全集不得因数量大而被裁掉。
- 每个功能点的覆盖自检记录至少包含：功能点/风险、选用方法、方法覆盖元素、用例编号、裁剪或不测理由、验证通道。可作为 BRIEF 覆盖矩阵的一部分，不强制重复造一份格式相同的表。
- **优先级独立判定**：方法类型不直接决定 P0/P1/P2/P3；按本标准 §1.1 与 L5 风险治理标准判风险优先级。历史参考中“基本流=P0、备选流=P1”等映射仅作旧分发材料，不作为现行内部判级规则。

## 23. 预期结果编写标准（设计期要求；由执行结果可判定性反推）

> 来源：《测试执行结果判定标准_v1》§九。执行结果的 PASS 必须建立在系统可观测行为与预期比对一致之上，因此预期结果必须写到可观察、可判定、可复核。

1. **每条预期指明验证载体**：页面字段/提示文案/列表行列/状态/接口字段/数据记录等，写明检查对象和具体值或状态。
2. **禁止模糊预期词**：单写“保存成功/正常展示/正确处理/符合预期/拦截”不构成可判定预期；补充具体消息、值、行数、状态或其他可观察结果。
3. **至少一个实质断言**：每条用例至少包含一项能区分正确与错误行为的断言（如某列=某值、总数=N、回显=X）；只有操作成功、弹窗关闭或 any 不足以证明业务正确。
4. **步骤标明验证时机**：在执行步骤中标注在哪一步观察断言，异步行为写明等待条件，不以固定睡眠替代可观测信号。
5. **与执行判定分工**：本节定义设计期预期写法；最终 PASS/FAIL/NOT_EXECUTED/BLOCKED 的语义和证据裁定仍以《测试执行结果判定标准_v1》为正本。
