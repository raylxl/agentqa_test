## 9. 生成工序（大批量分章生成）

1. **BRIEF 先行**：分章子代理的公共规则文件必嵌——条目格式/六条/造数隔离表（章×前缀×日期域）/防撞规则/优先级口径/**本标准反直觉条目原文**（§4 静默四式、§6 判重、§8 穷举、§5 红线相关行）；只给路径视为未分发。
1a. **章节指派对账表（2026-10-30 入标，WB 对比教训）**：BRIEF 写完、派发子代理前，必须做一次**理解说明功能点清单→章节指派**的逐项对账——每个功能点（含每个功能按钮/子场景/联动）必须有一个"已指派到章 X"的落位，无落位=派发不完整禁止派发。对账表随 BRIEF 落盘。
1b. **原文回读（2026-10-30 入标，WB 对比教训）**：对导入模版字段结构/接口出参/列表示例等**字段级内容**，BRIEF 与生成子代理必须回读需求 v3 原文对应段落（含模版示例行），不能只看理解说明——理解说明是"蒸馏版"，会丢失原文特有的字段名映射（如"首重=基础数量"）与示例细节（如"河南省,河北省"多值单元格）。
2. **章前缀编号制**：TC-{模块}-nn 天然防重号；分片标题条数 `??` 占位、组装脚本统计回填。
3. **防撞编排台账**：每章附"判重键→区间切片"台账；正向落库用例同键按日/窗切分；容量不足用维度分桶（独立客户/仓组合）扩容；计费族跨章共用日期域时用**目的地/物流公司隔离**（硬条件互不可见）〔线级条款·财务线〕。
4. **确定性**：机械转化类内容（档位表/对决）用脚本生成工作清单再逐行转化，禁手抄。
5. **独立性纪律**：分章子代理禁读其它已有用例文件；门禁由主流程（≠生成者）执行。
6. **造数三态齐铁律（2026-10-28 用户拍板）**：报价类菜单造数必须 已失效/生效中/未生效 各至少一组，禁只造未生效数据（与 T13 双轴"不受限轴也要有断言"同源）。
6. 组装=拼接分章+回填条数+统计（总数/优先级/自洽分解）。
7. **导入造数方法论（上游 §八 吸收）**：字段级造数矩阵逐字段过——必填逐字段各造空值行；错误值五类（超长/引用不存在/格式/术语错位/逻辑）；**数字七态**（空/负数/正常整数/正常小数/超精度/最大值精确上限/超最大值）；段内起止 0-0、起=止（观察）、起>止；级联互斥维度错配互填；跨字段约束逐对反例；判重对照（同键明细不同仍判重/区间重叠/仅一维不同放行对照）；**行标签法**=混合文件每行名称写场景标签（错误-XX为空/观察-起=止/正确-合并组-段1，行名即断言锚点），冒烟回归用混合文件、深挖定位用单场景文件。

## 10. 九项尺子完成定义（DoD）

"完成"当且仅当九项全过且复跑零新发现：

| # | 尺子 | 方式 |
| --- | --- | --- |
| 1 | 结构机械检（编号/前缀/五列表/占位/优先级/统计自洽分解） | 脚本全量 |
| 2 | 红线速查逐条全量（§5 全表，禁只挑相关行） | 独立检查员 |
| 3 | 需求原文逐句映射（100% 功能点→用例编号） | 独立检查员 |
| 4 | 拍板全量反向映射（理解说明全部拍板逐条→用例编号） | 独立检查员 |
| 5 | 方法论覆盖度（反向/权限/边界+双轴矩阵逐格+穷举对称性） | 独立检查员 |
| 6 | 造数防撞全量比对（判重键两两比对，同键重叠=0，含跨章） | 脚本+台账 |
| 7 | 语言自包含（例间引用/Q污染/黑话/特征串零违例；公式与白话并列） | 脚本+抽查 |
| 8 | 独立性（①~⑦ 由独立于生成过程者执行） | 流程约束 |
| 9 | 收敛证明（全部尺子复跑零新发现） | 全部复跑 |

迭代版门禁：改动区逐项+统计自洽+防撞专项重跑，交付前补全量②④。交付附九项结果表（完成证书）。

**外部用例对比（含 WB 类）四查**：已包含/未包含/口径冲突之外加第四查——**对方判断依据引用的拍板/标准是否现行有效**（防吸收已被推翻的中间口径或未拍板上游新口径）；上游新口径经用户拍板后吸收并登记修订记录。

**治理前置门（2026-11-11）**：设计质疑前必须能定位本需求治理 JSON（风险与执行集唯一正本）、策略卡派生视图和执行就绪卡。设计阶段须完成全谱系测/不测理由、P0123分布、风险—TC映射、执行集计划及就绪状态登记；执行就绪状态可为 `awaiting_environment`，这不阻断设计证书，但不代表可执行。进入 execution 阶段前，执行就绪卡必须全部为 `ready`；未满足执行就绪的条目只能标 BLOCKED/NOT_EXECUTED，不得标 PASS。风险项必须有 TC、带责任人与指标的观察项，或经批准的不测处置。治理 JSON 是风险事实正本，其余材料不得另行维护冲突口径。

**外部用例对比第五查——根因反思回写（2026-10-31 云仓账单 WB 对比，用户定界"不止吸收，要反思为何没想到并学习"）**：对方有而我无的每一条，不止吸收，必须归因到**设计方法缺口**（原文直读缺位 / 跨章交叉无人认领 / 操作时序单向 / 上游特殊规则未映射 / 越权路径不全 / 控件族模板缺——见 §14），并回写本标准或域标准对应条款；对比报告须含"反思与回写"节，**无反思的吸收视为对比未完成**。

### 15.8 生成输入三件套（源：完成定义与生成工序标准 §二.7 + 11-01 补强）

分章生成前 BRIEF 除需求+拍板外必带三件：

1. **规则矩阵**：每条校验/计费规则 × 通道（表单/导入/API）× 对象（每个数值字段/每个费项/每个页签）**全积展开清单**，禁规则只落第一次出现处；通道抽样须用户逐次确认留痕。
2. **系统行为清单**：分页/空格/残留/排序/勾选/注入等通用回归项（从通用规范问句表取向后带入）。
3. **对抗反例清单**：实现可能怎么错（排序语义反例如字典序 vs 打分制/并发/越权/绕过界面如 Excel 白纸直写）。

配套口径：**计费场景从严重视、宁可多不可少**〔线级条款·财务线〕（计费类穷举矩阵默认逐同构对象铺满，跨对象等价声明须用户逐次确认）；**并发场景断言写机制无关最终态**（库内唯一/后保存覆盖等），不断言中间过程。

### 15.11 检查员观点冲突处理（源：完成定义与生成工序标准 §四.3）

多检查员对同一项结论冲突时（如一判缺口一判低值），呈现必须标注冲突+给出建议+交用户拍板，不得静默取其一。


## 19. 执行出口尺（量化判定，吸收外部《AI 测试规范》§6）

设计完成=九项尺子全绿（§10）；**执行完成=本节量化出口**，全部满足才可出执行报告终版：

- **P0 用例通过率 = 100%**（任一失败禁止出口，回缺陷流程）；
- **P1 用例通过率 ≥ 95%**（非阻塞 Fail 逐条说明）；
- **P2/P3**：可按策略卡裁剪，但每条未执行、人工、失败或观察项必须有执行集、风险理由和处置结论，禁止用“低优先级”代替原因；
- **需求覆盖率 = 100%**（沿用 §10 尺子③④覆盖对账）；
- **风险覆盖率 = 100%**：每个高风险项必须有 P0/P1 用例或经用户拍板的明确不测/观察处置；
- **Skip 零遗留**（有则逐条说明并登记待复验；manual_only 与〔已失效〕条除外、逐条列出——失效条场景由 SYS/DEF/IMP/CHG 增量模块承接，见《执行反馈闭环标准》§十三）；
- **环境类误报清零**（已隔离或修复后复跑受影响用例）；
- **NFR**：策略卡触发的性能/安全/兼容/可靠性/可访问性项必须有结果或明确 BLOCKED 与责任人；
- 语句覆盖率 ≥80% / 分支覆盖率 ≥70%——**平台接入覆盖率工具后启用**（当前无采集手段，挂账）。

出口不满足处理：P0 失败→退回修复；P1 失败率>5%→分析后裁定退回或升级；P2/P3 未执行无理由→补入专项集或形成风险接受；风险/NFR覆盖不足→补用例重执行或明确签收；覆盖率不足→补用例重执行；Blocked 大量→修环境重跑受影响用例。


## 20. 执行就绪度尺（设计期出口的 AI 可执行检查·2026-11-05 立）

设计完成≠执行就绪；交付前按下表机检（脚本并入 assemble 门禁或检查员逐条），违例当轮修：

| # | 检查项 | 判据 |
| --- | --- | --- |
| 20.1 | 操作动词白名单 | 步骤动词限于 点击/输入/选择/勾选/清除/展开/折叠/滚动到/上传/导入/等待/截图/调用/推送/查询/核对 等可执行动词；"验证/检查/确认"类心理动词禁单独成步（须落到具体操作+断言） |
| 20.2 | 控件指代格式 | 被操作控件一律「页面可见文案」（通用§19）；禁"该按钮/上述输入框"相对指代 |
| 20.3 | 输入值具体 | 禁"合法数据/正确格式/若干"；须确切值或 ${变量}＋取值来源（PRE/公共数据） |
| 20.4 | 断言可判定 | 预期必含可观测信号（文案/数值/状态/行数/响应字段/DOM 存在性）；"页面正常/显示正确/功能正常"＝黑名单 |
| 20.5 | 异步带等待条件 | 异步步骤（保存后刷新/推送后查询）须写明"等待X出现"，禁裸"然后查询" |
| 20.6 | 数值禁模糊量词 | 禁"大约/左右"；金额/数量写精确值或区间 |

（源：《执行期参考》三原则升级为门禁＋ai-test-bench 发现⑦视觉转写误差断言走 DOM、⑧通用 Agent 回传不稳；2026-11-05 用户拍板补）

## 16. 分章剪切迁移铁律与章序门禁（2026-11-17 立；源：平台价格 v4.8 事故——23 误入 14.10+十五章头位移，条数全绿掩盖结构损伤）

对分章源文件执行用例块**移动/剪切/迁移**（执行期补齐用例归位、章节重组等）时：

1. **剪切前 dump 节结构清单**：列出该分章全部节头（###）与用例标题（####）行号序列，人工核对剪切起止边界与目标插入点；
2. **禁止单点 find() 定位作大段边界**：目标块与相邻内容可能存在历史插入顺序交织（实证：新增用例曾插在某原始用例之前，按"新用例→下节头"剪切将原始用例连带剪走、章头被挤位致章序断裂）；
3. **剪切后立即重组装并核对章节统计表**：条数不变≠结构无损（事故中条数全程 367 未变而结构两处损伤）；章节统计表节序/条目分布异常即回滚重做；
4. **组装门禁含章序连续性机检**（工具层根治）：章内节号必须连续（如 14.1→14.2→…），章头之后不得紧跟其他章的节头（章头与本章用例分离=损伤形态）；违例判 structure 违例拒绝写入正本。
