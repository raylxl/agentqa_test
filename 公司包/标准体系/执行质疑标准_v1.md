# 执行质疑标准 v1（L6 执行层·质疑者视角）

> **定位**：执行结果判定的**独立质疑正本**——执行员报完四态（PASS/FAIL/NOT_EXECUTED/BLOCKED）后，由独立质疑方审计"通过是真通过还是假通过"。核心原则：**执行方不自证**——设计期两员制（门禁§15.11：检查员≠生成者）在执行侧的延伸：**质疑者≠执行者**。
> **来源**：2026-11-13 用户拍板立项——"执行说用例通过了，没有一个来质疑这个通过是真通过还是假通过的'人'"。直接诱因：设计侧有生成/质疑分离（usecase-challenger），执行侧是"谁跑的谁判谁报"自证结构；11-10 对客报价"报841条全量零缺陷、实际只跑38条"即本类风险实证（靠人工发现，非体系拦截）。
> **分工边界**：判定语义尺（PASS 三条件/断言四级/证据要求）在《测试执行结果判定标准》§二/§三/§四，本标准不重复定义；本标准只回答**谁来质疑、按什么手段质疑、质疑后怎么出口**。
> **治理**：只增不覆盖，文内修订记录递增并注明来源；引用一律带文件限定。

## 一、三员结构与独立性铁律

**三员结构**：执行员（跑+初判四态）→ **执行质疑方**（审计判定真伪）→ 用户（拍板终裁）。

独立性铁律（违任一条=质疑无效，重做）：

1. **信息隔离**：质疑者不读执行员的过程自述与判定理由，只读三样——①用例正本（预期结果列）②证据包（截图/DOM快照/日志，带 Execution ID）③结果台账（逐条四态）。
2. **操作隔离**：抽样重执行必须独立清场（执行操作细则清场清单）独立重跑，禁复用首轮的数据状态与操作路径。
3. **实例隔离**：质疑者与执行者禁为同一会话/子代理实例（对应生成/质疑分离的子代理隔离惯例）。
4. **产出限定**：质疑者对每条抽验对象只允许三种产出——**维持原判**（附复核证据）/ **改判**（附反证）/ **存疑呈报**（证据不足，交用户拍板）；**禁静默放行**（没看过的条不得计入"维持"）。

## 三、六手段实施细则

### 3.1 覆盖对账（机检·全量·质疑前置门）

- 执行台账 vs 用例清单**逐条对**：每条 PASS 必须同时具备 Execution ID + 证据载体引用；缺任一 → 自动降级 NOT_EXECUTED/BLOCKED，不得计 PASS（与 L5 治理前置门"未就绪不得标 PASS"同源）。
- 数字勾稽：四态加总=用例总数；报告各节数字=台账数（report_sync 现有校验的台账侧前置）。
- 溯源锚点：11-10 对客报价事故（报841全绿实际38）——本条是该事故的体系化拦截。

### 3.2 断言强度尺（机检·全量）

- 尺子=判定标准§三断言强度四级（强/中/弱/无）；**弱/无断言条禁标 PASS**（any 断言禁标 PASS，门禁§20 补充 2026-11-08 已立，本条为质疑侧复核）。
- 复核执行报告披露的断言强度分布与台账一致（披露要求见判定标准§六）。
- 抽样重执行的入样优先级：**弱/中断言却 PASS** 的条目优先入样。

### 3.3 证据审计（疑点导向·抽验+全量疑点）

- 审计对象：证据包 vs 判定四态。逐条核：证据中的实际值/文案/状态是否与判定所引预期值一致。
- 三类即处置：**证据缺失**（无截图/快照）→ 降级存疑；**证据与判定矛盾** → 改判；**证据模糊**（看不出实际值）→ 存疑呈报。
- 证据分级口径按交付物规范现行版执行。

### 3.4 抽样重执行（独立复跑·抽样式）

抽样规则（首发版，可按需求规模调整，但下限不可破）：

- P0 全部 PASS 条抽 **10% 且 ≥5 条**；P1 抽 5%；上轮质疑改判条 **100%** 复核；弱/中断言的 PASS 条优先入样。
- 独立重跑：按用例原文+执行操作细则清场独立执行，禁读首轮执行记录；结论与首轮不一致 → 该条**及同批次相邻条全查**（同批次同因偏差假设）。
- 抽样全 PASS ≠ 结论"无假通过"，只支持"未发现"——结论限定在实际抽验覆盖内（平实语言纪律）。
- 首发抽样参数（10%/≥5条/5%/100%）为首发版拍板值，**首战后按误检率与成本校准**再回写本条。

### 3.5 基础数据与造数复核（前置质疑·入账前）

数据错是上游假绿：登记错的数据会让按正确口径设计的用例跑出"全绿"假象（批次15货主归属登记错→八册58块拿违规组合测成全绿，批次25翻案才纠正）。执行质疑门再严也拦不住上游数据错，故质疑挂点前移到**入账前**：

- **高风险字段强制二次核对**：归属关系（货主/客户×仓绑定）、税号、结算规则、仓编码类"错一个污染一片"的字段，登记入批次前必须"字段→来源"逐字段核对留痕——来源二选一：需求原文段落 / 系统实查截图；凭记忆登记=违规。
- **第二实例抽验**：每批次入账后抽 ≥3 条（或 10% 取大）由另一会话实例只按"登记件 vs 系统实查"核对，禁与登记人同实例（§一实例隔离适用）。
- **勘误纪律**：复核发现登记错 → 禁改旧批次（基础数据总清单只增不覆盖），加勘误批次（批次25 先例）并联动执行反馈闭环§十二评估受影响用例族回归。

### 3.6 沉淀脚本质疑（回归前质疑·沉淀时）

分层模式第二层的自证循环：回归 spec 继承 AI 首跑断言——首跑断言弱，脚本就把弱断言**永久复放**。脚本绿≠断言有效，质疑挂点放**沉淀时**：

- **沉淀机检**：每条 spec 入回归集前过断言强度尺（判定标准§三断言四级），弱/无断言 spec 禁入回归集。
- **否定验证抽样**：每批沉淀抽 1~2 条做否定验证——把关键输入改错（预期值改错/必填置空），脚本应转 FAIL；**仍 PASS = 断言无效（恒过脚本）**，该 spec 退回重写。
- **继承审计抽样**：批量沉淀后抽 3 条比对首轮 AI 判定依据（截图/DOM 快照），确认脚本断言的对象=用例预期对象——防"断错了东西、两边都绿"。
- 质疑结论与否定验证结果登记入坑库验证状态（衔接交付物 v1.15 沉淀清单带坑库验证状态的现行口径）。

## 四、质疑流程与两道出口

**触发**：质疑挂点共三处——**数据入账前**（§3.5）、**执行报告终版出具前**（§3.1→§3.4 主链，终版报告必须经质疑门）、**脚本沉淀时**（§3.6）。增量执行轮/回归轮同样适用；单条改动后的快速回归可走轻量档（仅 §3.1+§3.2 机检）。

**流程**：覆盖对账（前置门，不过=直接驳回）→ 断言强度尺（机检）→ 证据审计 → 抽样重执行 → 出《质疑结论单》。

**质疑结论单字段**：抽验条数与抽样比例 / 维持数 / 改判数（附清单）/ 存疑数（附清单）/ 缺陷单变化 / 签发或驳回结论。

**两道出口分离**（对应门禁§"设计完成/执行完成/发布放行三道出口"）：

- 执行员出口：判定标准+L5§19 出口尺**初判**——只是"申请放行"；
- 质疑出口：改判后四态**重算**，重算结果仍满足 L5§19 → 签发"执行质疑签证"，报告方可出终版；不满足 → 驳回退执行员整改重跑。
- 改判产生的 FAIL 走执行反馈闭环§二分流（SYS/DEF/IMP/CHG），质疑方**禁直接改用例预期**（用例修改必经用户拍板）。

## 六、报告披露与交付物落位

- 交付物规范三段式骨架**永久冻结**，本标准不新增骨架节；质疑结果落位：1.1 状态一句话/出口判定语句中注明"质疑门过/驳"、改判与存疑清单入 A 系支撑数据（失败失效详说节）。
- 具体字段落位**挂账待拍板**后回写交付物规范（只增不覆盖）。
