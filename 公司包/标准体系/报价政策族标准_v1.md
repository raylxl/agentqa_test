> **定位**：报价类与政策类需求的**族级标准**——两形态**同族**，仅功能限制不同，差异一律以文内「报价形态/政策形态」变体标注、不分文件。典型差异：编辑模式（报价=全字段可改 §7 基线 ↔ 政策=生效×审核状态矩阵限字段 §7.6）、匹配资格（报价=命中即用 ↔ 政策=已审核+生效中双条件 G14）、门禁时点（报价=录入即校验 ↔ 政策=录入放行+资格后置拦截 G16）。

## 3. 排版顺序（报价类固定序，2026-10-15 用户定稿）

〇 执行前数据准备（非用例：PRE-xx 准备项编号、不计入用例总条数、不进 XMind）→ 一 新增 → 二 编辑 → 三 复制 → 四 详情 → 五 审核通过 → 六 审核驳回 → 七 删除 → 八 修改记录 → 九 导入 → 十 界面列表 → 十一 查询条件 → 十二 导出 → 十三 数据权限 → 十四 报价匹配与计费（可拆多组）→ 十五 其他相关。

**用例的定义（2026-10-30 用户定稿入标）**：测试用例=**基于需求内容设计**、每条验证**一个需求功能点/拍板口径**的可执行条目，须含可观测预期断言。用例执行所需的基础数据（环境客户池映射/仓与公司池/温层/包材主数据/机构形态等）**不归属用例本身**——归〇位「执行前数据准备」（PRE-xx 准备项：核对环境+登记环境记录表，不计入用例总数、不进 XMind）；准备项不承担需求覆盖，凡属需求口径的断言（如客户下拉展示形态、未设公司自动弹框）必须在正文功能章有用例主条。

- 界面功能模块顺序固定；章内小节按需求字段序，同字段用例内聚（展示→必填→正向→反向→边界）；重复性校验置新增模块最后。
- 设计顺序：反向场景 → 数据权限 → 边界值；一用例一测试点。

## 6. 判重校验设计法（对齐上游《重复性校验用例设计标准》v1.1 全量）

- **公式法 N×2+1**：判重键全同+区间重叠 → 拦截 1 条（判重存在性证明，须有"完全相同"专条，带区间变化的拦截条不能替代）；每个可变维"值变放行"+"置空放行"；可空维加"空→有值"反向放行（空≠具体值必须双向用例验证，禁推断）。
- **维度四类适配**：可空维=值变+置空+双向全测；**必填维**=只测值变（无空态）；**级联锁定维**=可能无法单变——如实标"双维同变=本页签极限"并到能单变的页签/菜单补纯单变条，禁硬写单变；**时间区间维**=用矩阵法替代（"值变"=区间错开）。
- **时间点矩阵法**：以基准区间为中轴，13 拦（左触/左交/左交至右端/超含/左内含/完全相同/右交/窄内含/内含右端同日/右触/被全含/最小重叠一日/跨右边界）+ 3 放（左分离/右分离次日衔接/完全不相交），时间边界枚举尽，禁只测"交叉+衔接"两三式收工。
- **特殊形态专条**：键外字段差异是否豁免（费用名称/计费维度/精度等）按需求拍板逐条；判重与明细无关（明细/段值不同仍判重，显式专条）；**审核状态不豁免**（已审核与未审核同键同区间仍拦，1 条）；**流向双向并存**（仅结算流向不同的一收一付同键 → 放行，判重章内显式验证）。
- **操作侧覆盖口径**：新增=公式全量；编辑/复制/导入各已有涉及条即可（改维撞库/不改或仅改名拦截+错区间成功/与库内及文件内互重），不必全量重复。
- **1+1 上限专条**：副本机制下同键同区间至多并存"1 已审核+1 其未审核副本"，第三条新增拦截（见 §7.4）。
- **基准报价要求**：全字段有值的已存在报价；每条用例前置内联基准全数据，禁"同 TC_xxx/同上"。
- **覆盖对账表（生成后完整性证据）**：每维三态（值变/置空或双向/不适用）逐维落位 TC 编号，**任何一格无落位=设计未完成**；必填维标"不适用（必填）"、级联锁定维标极限并给单变条编号、时间维落矩阵法；表随用例文件节头/设计说明交付，评审按表复核。

## 7. 状态机与功能按钮逻辑基线

### 7.1 状态机

```
新增保存/复制成功/导入成功 → [未审核]
未审核 --审核通过--> 已审核（回填审核人/时间）
未审核 --审核驳回--> 审核驳回
审核驳回 --编辑保存--> 未审核（复活路径）
已审核 --编辑保存--> 生成"(副本)"未审核新报价（同编码新ID）
```
- 混勾铁律：批量操作勾选中混入不满足状态的行 → 整批失败。
- 生效状态独立计算：生效日>今天=未生效；生效日≤今天≤失效日=生效中；失效日<今天=已失效。
- 修改记录：产生机制=仅审核通过+1（新增/编辑/复制/导入/驳回不落）；版本列=报价ID 倒序；七列=版本/修改内容/修改人/修改时间/审核人/审核时间/详情；修改内容=与上一审核版差异字段（字段：旧值→新值，多字段逗号分隔）。
- 删除：可删状态×生效状态矩阵逐格；未生效已审核删除连带未审核副本级联；副本可单独删；二次确认。
- 角标：未审核数统计=**数据权限范围 ∩（除审核状态外的）当前查询条件**下实时统计；0 不显示、>99 显"99+"；**与审核状态查询条件不联动**（切页签角标不变，专条）、与其他查询条件联动（专条）。
- 列表默认排序=创建时间倒序。
- **列表查询行为三拍板（2026-10-28 用户拍板）**：查询/重置后**每页条数保留用户选择**、仅回到第 1 页；**重置自动执行查询**（清空条件即回默认全量）；**翻页清空勾选**（勾选不跨页保留、翻回不恢复）。
- 性能/大数据量为**执行期观察项**，不设功能用例；结算流向等枚举**动态取自费用规则维护配置**，用例按配置值断言。
- 导出=列表列∪导入模板列；合并展示列按模板列形态拆分导出；数值原值导出不补零；导出数据范围=查看权限范围∩当前查询条件（三态互证：范围内含/跨支不含/带条件交集）；**无数据导出=仅含表头的空文件**（2026-10-28 用户定形态拍板，不弹"无数据"拦截）；新增弹窗日期默认：生效日期默认次日、**失效日期初始为空待选择**（同日拍板）。

### 7.2 数据权限三层模型

按钮全展示（不因权限隐藏）→ 置灰仅由勾选态决定 → 拦截发生在操作确认/保存时。查看范围按需求拍板的流向规则（如 收向=客户+业务仓 AND / 付向=操作仓 及下级）；机构范围=登录机构及下级；非总部仅查看（查询类功能详情/修改记录/导出不受操作权限限制）；API 两线（界面不可见+接口直调拦截）；拦截后表单数据保留不清空。
- **查看权限反向对照设计法**：每条查看权限用例**内嵌多机构对照断言**——同组数据用 范围内✓ / 范围外✗（平级或跨支）/ 必要时总部✓ 多视角验证；避免单一机构视角测"看不到"（无对照无法证明是权限隔离而非数据缺失）。
- **修改记录逐版本权限（报价类顶替机制存在时必出双向两条）**：可见范围=逐版本按该版本产生时维度判定——维度移入（只见新版不见旧版）+ 维度移出（列表不可见但历史属其版本可见）各一条。
- 标准用例族清单方法（按族生成：三层模型族/流向族/组织形态族/API越权族等）详见上游数据权限标准 v1.5。

### 7.4 副本机制四细则（吸收自上游 v1.2 〇.7，2026-10-28 经 WB 实证+v1.1 用例落地）

1. **对应关系**：副本与原报价编码一致、字段可异；列表同编码两行并存（原=已审核原值、副本=未审核新值）。
2. **并存豁免+对外不豁免**：原已审核与其未审核副本同键同区间并存合法（否则编辑已审核报价将永远被自身判重拦截）；但其它新增/编辑对象与该键重叠照常判重（豁免仅限"原+副本"一对）；1+1 上限见 §6。
3. **过审全量替换**：副本审核通过后按原编码展示**副本全量数据**（基础信息+明细+主子单均为副本值），无"仅换明细、基础信息留旧"形态。
4. **历史延续**：覆盖后主报价旧条不再展示，历史按过审累加在新条修改记录中，旧版本详情快照可查。
5. **"(副本)"字样展示规则（上游按钮矩阵 v3 §6.7 吸收）**：前缀仅列表展示、不写库不占字段长度；编辑态名称=原名称（无前缀）按原上限校验；再次编辑副本输入框不含前缀；断言三件套=列表含前缀/编辑框原名称/超限名称源可正常生成副本不截断。

### 7.6 政策类编辑模式（2026-10-28 用户拍板写入标准）

**报价类与政策类对编辑字段不一样**——报价类任何可编辑状态**全字段可改**（审核通过编辑走副本机制，见 §7.1/§7.4）；政策类按**"生效状态 × 审核状态"矩阵限字段**：

| 生效状态 \ 审核状态 | 审核通过 | 未审核 / 审核驳回 |
| --- | --- | --- |
| 未生效 | 全部字段可编辑 | 全部字段可编辑 |
| **生效中** | **仅可编辑"失效日期"，其余字段置灰** | 全部字段可编辑 |
| **已失效** | **禁止编辑**（编辑按钮正常展示不置灰，点击提示"已失效不可编辑"、不进编辑页） | 全部字段可编辑 |

- 两族禁混用：把政策类矩阵套到报价类（或反向）均为方向性错误。
- 政策类**其余功能按钮逻辑**（审核日期时间约束、生效中改失效日下限、版本列等）**按具体政策类需求内容再定**（参考上游逻辑标准参考附录 A，未覆盖处单独问用户）。
- 来源：2026-10-28 用户拍板"政策类这个模式先写入标准，然后根据具体的需求内容描述再定相关政策的编辑等功能按钮逻辑"（矩阵底本=上游附录 A1，源自客户特定结算规则配置 v2 已验证口径）。

## 17. 客户特定结算规则配置答疑沉淀·报价/政策族级条目（2026-11-03 云仓客户特定结算规则配置 11.30 第二轮答疑沉淀；适用范围以 G14~G18 各条说明为准）

### 17.1 报价/政策族级断言补条 G14~G18（接 L1 通用断言 G1~G13）

- **G14 政策类匹配资格双条件**：政策/规则的"匹配、参与计费资格"须**显式拍板双条件**——审核状态=已审核 **且** 生效状态=生效中，同时满足才参与匹配计费；两维正交（生效状态=纯日期计算、与审核状态无关）时，**单看日期维不作数**（"仅匹配生效中"未提审核=口径空白须补拍）。交叉态（未审核+生效中、已驳回+生效中）真实存在且仅用于列表筛选展示、**不代表可用**；客户唯一候选政策处于不可用态时按**无政策兜底**处理，用例须出正向兜底断言（如实时结算+默认维度），不能只断"不匹配"。列表"生效中"筛选**包含**未审核/已驳回政策（正交计算的必然推论）。（源：客户特定结算规则 11.30 N1 拍板，2026-11-03）

- **G15 唯一性校验三要素**：重复性/唯一性校验的口径与用例须拍齐三要素——①**比对状态全集**：凡列表可见政策（未审核/已审核/已驳回、含副本）均参与重叠比对，不默认"仅已审核参与"；②**主副本豁免**：同一主政策与其编辑副本必然区间重叠（副本由主政策编辑产生），必须豁免这一对，否则副本功能死锁；③**逻辑删除剔除**：逻辑删除数据不参与比对。缺任一要素即拦截范围错误——漏①产生"审核先后定计费"竞态、漏②副本无法保存、漏③已删政策占位误拦。（源：客户特定结算规则 11.30 N3 拍板，2026-11-03）

- **G16 门禁后置（录入放行+资格拦截两层断言）**：维护端录入控件**不限制可录范围**（如生效日期可选过去），无效数据靠**后置门禁**（如审核约束"审核日期<生效日期"）自然拦截废弃。用例按两层断言：**录入层=放行**（选过去日期保存成功）+**资格层=拦截**（永远无法审核通过、不参与计费）。禁把门禁规则前移成控件限制断言（"选过去日期被拦截"=错误预期）；转测若实现做了控件限制，按口径偏差/缺陷反馈（**分流细则已升格至《执行反馈闭环标准》§二**）。（源：客户特定结算规则 11.30 N6 用户口径"需求没有限制过去时间…政策是否真的能用看审核通过，审核通过时看了审核日期和生效日期的，所以维护时先不限制选择的时间"，2026-11-03）

- **G17 政策多区块独立生效**：一条政策内多个规则区块（如月结规则区块/出库计费区块）**独立生效、互不牵连**——区块内过滤条件（订单类型/物流公司等）未命中时仅**该区块**对该单据不适用（按系统默认处理），**不影响其他区块**（不产生"半月结客户"式混合态）；区块字段"仅维度/仅开关无过滤"形态合法（=全对象适用，原型示例常即此形态）。断言按区块分叉设计（未命中过滤→出库计费走默认、月结照走），禁整政策一刀切（未命中→全部兜底）。（源：客户特定结算规则 11.30 N4 拍板，2026-11-03）

- **G18 批量操作原子口径显式拍板**：批量操作（审核通过/审核驳回/删除等）遇"部分满足条件、部分不满足"时的成败口径（**整批失败 vs 部分成功**）**必须逐操作显式拍板**——不从同需求其他批量操作默认继承，更不从兄弟需求继承（同为政策类：包仓"部分拦截部分通过"与客户特定结算规则"整批失败"并存即证）。每个批量操作至少一条**混合勾选用例**落在拍板口径上（整批失败→全部未动+提示不可操作项；部分成功→可操作项已动+失败清单）。（源：客户特定结算规则 11.30 N5 整批失败拍板+Q6.5；反例=包仓 TC_158/TC_167 部分通过写法经 7.9 Q4 明确不适用本需求，2026-11-03）
