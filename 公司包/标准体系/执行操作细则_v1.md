## 四、操作注入

**总原则：只用 CDP 真实事件，不用合成 DOM 事件**——`element.click()`/dispatchEvent 对 Vue/Element Plus 组件不可靠（下拉不开、输入不绑值、按钮不触发）。

| 控件 | 注入方式 | 关键细节 |
|------|---------|---------|
| 下拉选择 | `page.mouse.click(x,y)` 真实坐标：点选择器→等面板→点选项 | 选项轮询 ≤20 次×60ms；选完点空白收起 |
| 文本输入 | `Input.dispatchKeyEvent` 逐字符 keyDown(text)+keyUp | code=`Key{大写}`，字符间隔 ≥20ms |
| 数字输入 | 同上 | code=`Digit{字符}` |
| 日期选择 | 真实鼠标点面板：开面板→导航→点 td→点「确定」 | 禁直接 fill（会被回滚）；过滤 disabled |
| 按钮 | `page.mouse.click` 真实坐标 | 点前确认无遮挡 |
| 搜索框 | 点→Cmd+A→Backspace→`keyboard.type` 逐字→Enter | 每字 delay 40ms |

- **坐标获取**：统一 `page.evaluate` 现场算 `getBoundingClientRect()` 中心点，**禁止硬编码坐标**。
- 〔自〕**DOM 断言限定可见容器**：DOM 存在隐藏 custom-dialog 表格副本，列表/表格断言须限定可见容器（如 `.tableDivCom`），防命中隐藏副本。

## 六、断言与取证

- **多要素交叉断言**：至少综合 2~3 个要素（弹窗状态+接口响应+列表数据），不依赖单一证据；
- **结果不一致以库/列表层为准**，不以 UI 层为准（UI 可能静默失败）；
- **XHR hook**：hook `XMLHttpRequest.prototype.send` 记 `{status,url,body,t}`；每批次校验重装+清基线；断言只认"本次操作新增的响应"；
- **拦截类判定**：必填拦截=弹窗未关+无目标请求+列表无记录；重复拦截=指定错误码+弹窗未关；输入过滤=读 `input.value` 确认；
- 〔自〕**角标/统计类断言跟随查询范围**：换条件重查后再断言（同通用 G5 结果集级动态绑定）。

## 七、干扰与异常恢复

- 组件状态异常（按钮点不动/下拉卡死/iframe 消失）：**整页 reload**→等待→重装 hook→清场→重试该用例（最多 3 次）；不可隐藏/删除组件 DOM；
- 重复性校验延迟：连续保存类用例间隔 ≥60s。

## 八、超时与批次停止（fail-fast，现行唯一口径）

- 元素等待/操作响应超时上限 **60s**；单条用例总墙钟上限 **5min（含重试）**。
- 任一单条用例超时且未到验证点→最终结果 `NOT_EXECUTED`，不得标 FAIL；若已确认是外部环境/工具/依赖限制→`BLOCKED`，必须写原因、责任人和处置建议。
- 页面级异常（登录丢失/空白页/iframe 消失）→立即终止整批，保留已完成结果并为未到达 TC 补写 `NOT_EXECUTED`（reason=batch_stop_page_failure）。
- 连续 **3** 个用例因环境/通道/超时失败→终止批次；`3` 是唯一连续失败阈值。
- 失败原因必须记入测试原因字段，区分产品断言失败、NOT_EXECUTED 和 BLOCKED；批次停止不得留下 MISSING。

## §十一 浏览器实例调度（2026-11-07 立，用户拍板"占用就开新端口验证"）

**执行测试前必须先取实例，不得直连固定端口。**

### 11.1 判定规则（三信号）

| 信号 | 判法 | 说明 |
| --- | --- | --- |
| 活性 | `curl /json/version` 2 秒 | 端口有无 Chrome 实例监听（**启动≠占用**） |
| 锁 | `jt_chrome\locks\{端口}.lock` | **唯一占用判据**：60 分钟内=占用中（超时自动失效） |
| 现场 | CDP **只读**当前页 URL | **仅参考信息不复用判据**（停在业务页≠有人用，可能只是未复位） |

> 判定修正（2026-11-07 用户纠偏）：v1 初版误把"现场停在业务页"当占用，导致每次 acquire 都起新实例（9333→9337 增殖）。正确逻辑：**活+无锁=直接复用**（复用后导航到目标页即安全，无锁=按协议无人正在用）；仅当全部活实例都有锁才起新；release 时把页面**复位到 welcome**（归位礼仪，让下个使用者拿到干净现场）。

### 11.2 调度流程（工具：`jt_chromerowser_pool.js`，已自测通过）

```
node browser_pool.js acquire "用途"   # 从 9333 起找第一个[活着且无锁且现场空闲]的→上锁返回端口；
                                     # 全忙→自动起下一端口(9335/9336…上限9340)+跑鲸天登录+上锁
node browser_pool.js release <端口>  # 用完解锁（实例保留，登录态复用；不关浏览器）
node browser_pool.js status          # 列全部实例占用态
```

执行器接入：runner/脚本 connectOverCDP 前必须先 acquire，结束必须 release。

### 11.3 纪律

1. **绝不**在他人占用实例上做任何点击/导航/清场（一次点击可毁对方一条用例）；只读 URL 探测除外。
2. 新实例启动=参数化模板（端口+独立 user-data-dir），登录=参数化登录脚本；**禁** `taskkill /IM chrome.exe`（杀全部），关闭只允许按端口 PID。
3. acquire 起新实例后若登录失败：如实返回 login:false，需人工登录一次后复用。
4. 锁信息必含用途+时间戳；跨会话冲突以锁+现场双信号为准，锁丢失时现场判定兜底。

## 测试数据生命周期（2026-11-07 用户定规·方案C）

### 时序规则
- **执行完成后：数据保留不删**——供用户复核造数与执行证据；
- **下一轮执行前：清场**——按三步校验法删除本轮前缀数据，清完才开新一轮造数。

### 造数标识（方案C：轮次前缀+台账）
- 每轮执行使用**独立前缀**：`ZC_R1_`（首轮UI）/`ZC_RG_`（回归轮）/`ZC_R2_`（第二轮）…——天然隔离不撞；
- 台账记录"本轮保留 N 条终态清单"（客户×名称×区间×状态），追加在执行记录末尾。

### 清场三步校验法（缺一不可，跳过任何一步=违规）
1. **范围锁定**：客户=本轮使用的池内客户 AND 政策名称 like '本轮前缀_%' → 仅命中本轮数据；
2. **数量核对**：清场前命中行数 vs 台账终态清单数——**多了停下逐条确认**（可能他人同前缀），确认后才删；
3. **逐条名称检查**：每条名称以本轮前缀开头才勾选删除——不以本轮前缀开头的→跳过并登记"疑似他人数据"。

### 已审核残留处理（2026-11-09 用户拍板修正）
- 已审核残留（审核通过且生效中/已失效）无法直接 UI 删，且实测**"先驳回再删"走不通**（审核通过的行不能被驳回，v1 原文废止）；
- **报价类三菜单（平台价格/仓内作业价格/配送价格）走"编辑改效"路**：编辑该数据，把生/失效日期改为未来时间→生成副本→副本审核通过后＝审核通过＋**未生效**→可直接删除（删除拦截只拦"审核通过且生效中/已失效"，未生效不在拦截区）；
- **政策类（生效日期不可修改，如客户特定结算规则）不适用**此路→无法自动清的记入"无法自动清"清单上报用户裁定。

### §十二 执行前数据清理（2026-11-08 立，用户拍板）

**每一轮测试执行开始前，必须清理上一轮产生的测试数据**（按造数前缀清理，如 TEST_*、UIT_* 系列）。目的：防判重撞历史数据——判重键=费用名称+8维+生效区间，保留上轮数据会导致本轮正向保存用例被系统正确拦截（判重行为无误，但测试点没验到）。

清理方式：
1. **界面法**：按造数前缀查询→全选→删除（适合少量）
2. **API/DB 法**：按批次6表映射清理对应表 TEST_* 记录（适合大量）
3. **日期域隔离**（兜底）：如果无法清理，至少确保本轮造数日期域与上轮完全无重叠

> 来源教训：配送价格 2026-11-06~07 执行中，因多轮数据保留（2027→2033 七个日期域），12 条正向保存用例被上轮数据判重拦截，测试点未验到。

### §十二.1 每步操作前弹窗检测与关闭（2026-11-08 补，用户拍板"遇到弹窗先关了再执行"）

**执行引擎必须在每个操作步骤（click/fill/navigate）前，自动检测并关闭干扰弹窗**，不能只在用例开头清一次。

检测与关闭优先级：
1. **系统异常框**（"程序运行异常或网络异常"）→ 点【刷新系统】
2. **消息确认框**（el-message-box）→ 点【取消】（如"是否去查看导入结果"）
3. **~~Element Plus 弹窗遮罩（el-dialog / el-overlay）→ 点【取消】或右上角 X~~** **（已废止，见下）**
4. **智能助理 iframe** → 移出视口（不能删，删了会触发系统异常）

**红线：业务表单弹窗（el-dialog）禁止在步骤间自动关闭。** "每步前清弹窗"只清杂散弹窗（异常框/消息框/助理），不碰业务弹窗——测试流程自己打开的新增/编辑/详情弹窗正是后续步骤的操作对象。业务弹窗的关闭时机只有两个：用例步骤明确要求（取消/确定操作）、用例结束的清场（hardReset）。

实现方式：在执行引擎的每个 op 分发前调用 `clearPopups()` 函数（幂等，无弹窗时不产生副作用）。
