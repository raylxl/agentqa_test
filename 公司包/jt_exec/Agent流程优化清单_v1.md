# Agent 流程优化清单（2026-11-27 · 平台价格 R4 轮复盘产出）

> 来源：《平台价格_各环节耗时与卡点分析.xlsx》+ R4 四轮执行复盘（135 PASS/11 BLOCKED/0 FAIL 全程）。
> 用途：下个需求执行前的流程 checklist——8 项优化已落地 5 项（标记 ✅），其余 3 项为规范约定。

## 一、策略结构级（3 项）

### 1. ✅ 硬坎先查 skill 库，自研穷尽是最后手段
- **教训**：组织切换 R3 十种 DOM 打法穷尽后误定性"Vue2 不可达须人工"，R4 org-switch skill UI 拟人法一次通过，12 条 PERM 白挂一轮。
- **落地**：写入坑库头条（Q12 位置）——"执行遇任何交互硬坎（组织切换/租户切换/导入导出/登录），先查 `~/.workbuddy/skills/` 与执行坑库，再自研"。

### 2. ✅ 通道策略执行前一次性拍板
- **教训**：R2 按"API 优先"定性 64 条"须 UI 通道"BLOCKED；用户 R4 拍板"所有用例界面测试"后全量返工 UI 直测（5.4h 攻坚本质=重做）。
- **落地**：新增 `channel_strategy.js`——生成段按用例类型标注 channel_hint（ui / ui_or_api / ui_with_api / file），执行计划呈报时附通道策略建议卡，用户拍一次板全程不变。

### 3. ✅ BLOCKED 定性须附穷尽清单
- **教训**：正反两例——组织切换（没穷尽就定性，被翻案）vs 导入链（UI 完整链/XHR 直连/CDP 注入三通道+官方模板+真实导出改造+30 分钟迟到复查，定性无人能推翻）。
- **落地**：写入判定纪律——"环境/系统类 BLOCKED 定性必须附通道穷尽清单与证据（响应原文/任务中心核对/迟到复查），没试尽不准定性"。

## 二、执行工程级（3 项）

### 4. ✅ 执行器公共库抽取
- **教训**：R4 十四批执行器每批重复 80% setup（登录/租户/gotoBiz/清遮挡/查询/勾选/造数/审核/删除），约 2000 行重复代码。
- **落地**：新增 `pp_exec_lib.js`（setup/uiQuery/checkAndAction/mk/audit1/delByIds/record 全公共化）——后续执行批只写差异断言，开发量减半。

### 5. ✅ audit 延迟复核内置
- **教训**：audit 接口落库有延迟（立即查拿旧态）——DEL-04 两轮误判根因。
- **落地**：`audit1()` 内置轮询复核（5×2.5s），从库函数层面消除此类误判。

### 6. ✅ 判定纪律函数化
- **教训**：R1~R3 误判 8 起（勾错全选框/参数缺 pageSize/语义误用），共性=判定纪律未内化。
- **落地**：`judgeWithDiscipline()`——预期不符先跑 precheck（前置态复核）分流 BLOCKED/FAIL，断言值强制从 getState() 接口响应取（禁凭记忆）。

## 三、流程规范级（3 项，约定不改代码）

### 7. 答疑拍板分批合并
- **教训**：18 项一次一问共 2.8h，约 1/3 是关联口径（判重键×状态豁免、批量行为×混勾）。
- **约定**：关联口径合并成组拍板（每问覆盖 2~3 项），预计省 40 分钟——写入 requirement-qa-loop 操作建议。

### 8. 证据密度前置
- **教训**：质疑门复核最大卡点="旧轮缺逐 TC 独立证据件"，R4 才补上响应原文。
- **约定**：record() 须带 evidence（响应原文/复验记录）从第一轮就开始——已在 pp_exec_lib record 结构预留，执行时自觉带全。

### 9. 造数错键四维配方
- **教训**：撞库贯穿四轮，错键四维（特殊属性/流向/操作仓/客户成对）R4 后期才总结出。
- **落地**：已写坑库+pp_exec_lib mk() 支持四维参数——下个需求首日可用，无需再踩。
