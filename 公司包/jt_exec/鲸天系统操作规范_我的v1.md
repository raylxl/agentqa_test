# 鲸天系统操作规范（我的 v1）

- 适用：jt-ll.test.ztoeco.com（冷链·测试/预发）的一切自动化操作
- 分工：**用户只下指令**（切租户 / 开菜单 / 测试 / 查数据），**助手全程操作**；一切操作副作用（页签刷新、缓存对齐、异常重试）由助手闭环，不推给用户
- 本文件是鲸天操作细则的唯一正本；两个技能（jingtian-login / jingtian-tenant-switch）是入口，触发后按本文件执行
- 修改纪律：实测口径变化时**先改本文件再改脚本**，版本号+1，并在文末记录变更

## 0. 操作前置检查清单（每次鲸天任务开工必走）

1. 实例在线：`curl -s --max-time 3 http://127.0.0.1:9333/json/version`；不通 → 跑 jingtian-login 的 launch 脚本（必须带防 https 升级参数）
2. 登录态：跑 jingtian-login 登录脚本（幂等）；判据=正文含凭证 `jt_login.display` 或预发环境标识
3. 租户态：跑 `chrome_jt_tenant.js current`；不是目标租户 → `switch <id|名称>`
4. **页签对齐**（关键，最易漏）：切换租户后，本次要操作的 jt-ll 页签若是旧租户态（localStorage 菜单全页签共享），先 reload 该页签并核对：选中租户名 + 顶级菜单数签名（见 §3 表）；多页签时逐个核对
5. 以上全绿才执行菜单/页面操作

## 1. 环境事实

| 项目 | 值 |
|------|-----|
| 鲸天地址 | `http://jt-ll.test.ztoeco.com`（**全程 http，出现 https 即异常**） |
| 浏览器 | 独立 Chrome 实例，CDP `127.0.0.1:9333`，用户目录为部署根 `.chrome-cdp`（登录态持久化） |
| 启动参数 | 必须 `--ignore-certificate-errors --disable-features=HttpsUpgrades,HttpsFirstBalancedModeAutoEnable,HttpsFirstModeV2ForEngagedSites`（防 http→https 自动升级断 SSO） |
| 账号 | 当前同事自己的 `agent-secrets.json` → `jt_login`（user/pass/display）；文档与脚本不得写死个人账号 |
| playwright | 部署器在部署根自动安装 `playwright`；CDP 用 `connectOverCDP('http://127.0.0.1:9333')` |

## 2. 登录规范

- 用 jingtian-login 技能自带脚本（launch_chrome_9333.ps1 / chrome_jt_login.js），幂等，勿手写
- 登录成功判据：URL 回鲸天域，正文含凭证 `jt_login.display` 或预发环境标识
- SSO 动态码失效（登录超时+密码错误截图）→ 页面停扫码模式请用户用中通宝盒扫码，其余情况不麻烦用户

## 3. 租户切换规范

- **唯一有效方法=API 法**（jingtian-tenant-switch 技能）：`changeTenant` 拿新 token 写回 localStorage → 清菜单缓存 → reload /dashboard；**下拉 UI 点击法已失效，禁用**
- 切换后必须做 §0.4 页签对齐
- 全量租户与菜单数签名（2026-10-27 实测；以 `list` 实时为准）：

| tenantId | code | 名称 | 顶级菜单签名 |
|---|---|---|---|
| 1 | ZTOCC | 冷链快运（**别名：快运、总部**） | 32（主租户 type2，默认/回切首选） |
| 43 | T00011 | 智冷仓链（**别名：冷链云仓、云仓**） | 28 |
| 77 | T00077 | 冷链智运 | 36（含测试栏目，自有 zhiyun 域） |
| 49 | T00049 | 网络货运 | 8 |
| 78 | 99 | 财务中台 | 4（code 异常，只按 ID 切） |
| 81 | T00081 | 项目管理 | 1 |
| 46 | T00044 | 物料商城 | 0（空租户） |
| 48 | T00048 | 客户服务平台 | 0（空租户） |

用户口径：说"快运/总部"即 冷链快运(1)，说"云仓/冷链云仓"即 智冷仓链(43)。菜单操作按"**租户 + 一级栏目**"作用域消歧（同名菜单可能跨租户/跨栏目存在）。⚠️ **快运租户新版优先（2026-10-27 用户定规）**：快运下新旧双轨菜单并存（网点账户/网点账户（新）、手工充值/手工充值-新…），用户指令**不会带"新"字**，打开器自动改开带"（新）/-新"的版本（无可衍生新版则开原名）；其它租户保持精确匹配原名。

## 4. 页面/菜单操作规范

- 找页签：CDP 连上后按 URL 含 `jt-ll.test.ztoeco.com` 过滤；操作前先确认该页签租户态（§0.4）
- **打开菜单一律用菜单打开器**：`node <公司包执行工具>/chrome_jt_open_menu.js <一级栏目> <菜单名> [--tenant <租户ID|名称|别名>]`（部署器会把配置 `paths.执行工具` 指到实际安装位置）
  - 交互模型：侧栏一级栏目(li.el-menu-item)→点击弹左抽屉(el-drawer)→抽屉搜索是 **el-select 联想**，输入菜单名→点联想项→内容区开页签，URL 形如 `/app/#<uri>`
  - ⚠️ **禁止直跳 uri**（location.href=/wbms/...）：微应用按错误基地址拉资源 404，卡"资源加载中"（实测）
  - 菜单重名：脚本在"一级栏目子树"内解析，精确文本匹配；**快运租户新版优先**（指令不带"新"→自动开 （新）/-新 变体，2026-10-27 实测 网点账户/手工充值/平台价格 三例通过；无新版开原名）；抽屉/侧栏存在与二级分组同名的独立一级栏目，按入参消歧
  - 菜单结构数据：`MICRO_APP_MAIN_MENU_LIST`（分组 categoryName / 叶子 chilePlatformMenuList[].menuName+uri）
- 等待：切页/弹窗/表格给足异步时间（菜单渲染 ~8s 量级）；evaluate 报 "Execution context destroyed" 多为页面正在跳转，重试即可
- 留痕：关键结果写到同事自己的执行结果目录（由执行器账本配置决定）；批量探查先 dump 结构（文本优先，截图为辅）
- 报告口径：只报结果与证据（RESULT 行/截图/数据），过程性排障不展开

## 5. 红线（禁止事项）

1. 绝不 `taskkill /IM chrome.exe`——只能 kill 9333 端口对应 PID
2. playwright `browser.close()` 只断 CDP 连接不关浏览器，保持此用法
3. 鲸天全程 http；任何 https 化迹象=实例参数丢失，按 §0.1 重启实例
4. 不照搬 WorkBuddy/Edge 9222 参考体系的脚本（参考目录文档仅作业务知识查阅）
5. 不把操作副作用转述成"请用户刷新/请用户点击"——用户不下场操作
6. 主会话模型由用户切换；批量图片识别走 GLM-5.3-Flash 通道（全局规则）

## 6. 故障速查

| 症状 | 处理 |
|------|------|
| https 升级/白屏 | kill 9333 PID → launch 脚本重启 → 重登录 |
| 登录超时+密码错 | SSO 停扫码模式，请用户中通宝盒扫码 |
| 切租户 api-failed/login-lost | 重跑登录脚本后重试 |
| 页签内容与租户不符 | reload 该页签并核对菜单签名 |
| 表单/菜单选择器失效 | dump 页面结构（chrome_jt_probe.js 思路），按实测调整，勿猜 |
