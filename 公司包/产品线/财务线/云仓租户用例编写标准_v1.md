### 2.1 单元格金额格权限（源：数据权限标准 v1.6，云仓账单 10.? 2026-10-31 拍板；通用三层框架见独立定稿 §15.7）

适用：同一列表行内多个数据模块各有独立权限维度的账单/交易菜单（行可见性由 A 维判、行内模块可见性由 B 维各自判，两刀叠加）。

- **三层粒度模型**：①第一层·行过滤——按主维度 OR/AND（按需求拍板）判整行可见，行不命中整行不出现；②第二层·模块可见性——行内各模块（业务仓账单（支出）/操作仓账单（支出/收入））按**各自维度的上级链独立判**，A 模块有权≠B 模块有权（叠加模型：双线命中行可全模块可见、单线命中行仅对应模块可见）；③第三层·呈现粒度=**单元格金额**——表头/列结构恒全可见，无权限仅该行该模块费用项下**金额格展示空**（非整列裁剪、非打码、非 `***`）；**导出与页面同形态**（列全带、无权限金额格空）。
- **两条铁断言**：权限底线（无权限行的对应模块金额格不得出现任何数值——混合行一屏断言：同列下有权行有金额、无权行空）；表头完整（无权限账号的列表/导出文件列头仍完整——防整列裁剪实现，与拍板冲突即缺陷）。
- **必测组合 2×2**：双线命中（全模块有金额）/ 单线命中×2（镜像各一条：仅业务仓线、仅操作仓线）/ 双线不命中（行不可见）。
- 域级落位：云仓账单域标准"无权限侧列在、金额格空"（行级金额判定行）。
- **云仓账单差异标注（2026-11-02 用户拍板"用动态判定设计用例，用全展示兜底"）**：云仓账单菜单以**结果集级动态判定为主形态**（单侧结果集→对侧模块列整体不展示；空结果集仅订单信息模块；导出随界面动态列），本节"表头恒全可见/列全带"为其**兜底形态（不判缺陷）**；两形态均合法、执行记录实际形态；**任一形态硬断言=无权限侧金额格零数值**（兜底形态下本节两条铁断言必须成立）。其他云仓菜单仍按本节执行。

### 2.2 重算类操作逻辑基线（源：按钮参考 v1.12 〇.13，云仓账单 10.? 拍板；标注：云仓财务侧拍板，同族不一致以各自拍板为准）

**机制四要素**：

1. **取数**：拿所选订单/运单调**源系统（仓链）取最新数据**（非本地缓存）——用例须设"改源系统数据后重算按新值"取数时效断言。
2. **节点裁剪闸门**：事件驱动计费的重算产出受单据**当前事件节点**裁剪——**全选费用项+全模块 ≠ 全量重算**（订单处理节点只更新订单处理产出费用侧，出库完成节点费用侧不产生）；用例按节点态分组断言产出范围。
3. **颗粒度**：按所选账单行维度（订单维度行按订单、运单维度行按运单）。
4. **跨模块/跨费用项独立**：重算精确到"模块×费用项"生效，不联动其他模块同费用项（两向金额来自各自独立报价，本就独立计费）。

**分支判定=费用项级结算状态**（核心纠偏）：重算金额变更后的结算补偿，判定粒度是**每个费用项自身是否已被结算**，不是账单状态字段——

| 费用项 | 结算状态判定 | 金额变更时 |
| --- | --- | --- |
| 平台费用（恒实时结算类） | 不看账单月结状态——事件时点已结算 | 恒红冲重结（账单"未月结"也一样） |
| 业务费用-现结账单 | 已实时结算 | 红冲重结 |
| 业务费用-月结挂账中 | 未结算 | 只更新金额、零结算动作 |
| 业务费用-月结已结 | 已周期结算 | 红冲重结 |

**必测格**：同一张"未月结"账单同时重算平台费+业务费 → **红冲重结与仅更新双行为并存**（最易漏测）；红冲重结断言锚独立定稿 §7.5（原额红冲流水+新额结算流水双交易断言）。

**修正类操作不动状态机（通用方法论，随本节收录）**：重算=计费层金额修正+结算层红冲补偿，**只动"钱"不动"状态"**——状态字段只由其实际驱动事件改变（月结状态只由实时结算动作/周期月结作业驱动）；修正类按钮用例必须断言状态字段（月结状态/日期等）重算前后不变。设计前先问"这个状态是谁写的"——不是本操作写的就不该变。

**修正→终态时序组合+终态冻结**：先修正后终态（先重算后取消）→终态处理按**修正后金额**执行（对冲红冲=最新金额，防串账），该顺序用例必设；终态单据冻结（已取消）→退出周期作业、状态/日期保持终态时刻值不再参与推算——跨周期观察用例（过 N 个周期日断言不变）+对照组（正常单据照常流转）。

**反馈与批处理**：反馈=异步任务（提交任务→完成后查看；任务形态转测校准）；金额不变→无红冲无重结算（防过度重算断言）；重算后无有效报价→金额**变空**（回到无费用行，非 0）。批量原子性=**B 逐单独立型**（独立定稿 §15.4）：能重算的重算、不能的跳过，不整批拦截。

### 2.3 事件闸门月结模型（源：按钮参考 v1.14 〇.13 增补，存储账单 Q4/Q4b 拍板；云仓租户专属口径）

月结闸门不是只有"出库完成"一种——**费用项的月结闸门=其自身事件的完结语义**：

- **有终态事件类**：出库业务费→出库完成；**入库完成自身即订单完结状态**（B2B/B2C 订单上的入库费不等出库、周期日照结）。
- **无终态持续事件类**：存储事件日日产生无完结概念→**周期日到达即结算当期累计**（与出库无关——托盘在库永不出库，照搬出库闸门会死锁）。
- 用户口径原文："入库完成、存储这两个事件来了就算费，到月结周期了就结算，没有出库完成的概念。"
- **用例落点**：周期日即结（存储月度累计）+ 入库费不等出库照结 + **同账单内"已结费用项与挂账费用项并存"断言**（入库费已结/出库费仍挂账——最易漏格）。
- **云仓账单落定注（2026-11-02，F23）**：入库费/卸车费只产生于**入库类型订单**（B2B/B2C 无入库完成事件，无"入库费挂出库单"场景）；月结客户入库单=入库完成即完结、周期日照结（状态流转），非月结实时；本节"同账单内并存"在云仓账单落为**同客户同期"入库单已结/出库单挂账"两单并存**。

### 2.4 事件驱动更新模型（源：按钮参考 v1.14 〇.13 增补，存储账单 Q18 拍板；云仓租户专属口径；§2.2 取数要素的细化）

账单数据的更新触发器只有两个——**新事件 或 重算**；历史数据不主动变：

1. 财务侧不感知上游配置变化（客户换绑业务仓等）——**拿到事件就查源系统订单数据，查到什么用什么匹配报价**；
2. **不重算且无新事件 → 账单不更新**（即使源系统数据已变）；
3. 触发时重查源系统：数据有更新→按新数据匹配+更新账单；没更新→不动。

**用例落点**：源数据变+无事件无重算→账单不变（对照组）；源数据变+新事件→后续账单按新值；源数据变+重算→重算范围内按新值（历史行可追溯更新）。

### 2.5 多费用项来源豁免逐项核实（源：通用规范 v23②，标注云仓财务专属）

同一业务限定（如单仓）作用于多个费用项时，各费用项**豁免与否按其来源规则独立判定**（仓内来源豁免 / 平台来源已取消 / 配送来源无豁免——三种结论可并存），**禁止整单一刀切断言**；用例按"费用项×来源"矩阵落断言 + 对照组（非限定场景费用正常产生）锁豁免真实生效。（教训：AI 曾把"仓内 9 项不产生"误扩大为"11 双向项全空"）

### 2.6 双接口分流切换模式（源：通用计费规则调整 11.30 Q18/T3 拍板；标注：**当前云仓租户做法，非通用纪律**）

切换类需求（新/老逻辑并存）当前云仓采用的隔离机制=**接口分流**：仓链按**开单业务时间**推老/新接口（财务侧被动接收）——老接口→老事件→老逻辑+老报价+老账单，新接口→新规则+新报价+新账单，属**长期并存**非过渡熔断（不依赖老数据失效与否）。测试模式三条：
1. 新老通路用例**分别直调各自接口**驱动，不依赖、不构造任何"切换开关"配置；
2. 在途/临界用例**造数控制点=推送方判定字段**（开单业务时间），断言两单分别落入对应通路；
3. 必含回归组**"老接口匹配老数据"**——切换后老通路全链（老接口→老规则→老报价→老账单）照常、不被新逻辑污染。

⚠️ **适用边界（2026-11-03 用户拍板）**：本条是**当前云仓租户的做法**，不默认外推——后续需求若采用其他切换机制（如时间开关硬切换），**按需求实际内容另行设计、由用户提供具体方案后执行**，禁套用本模式。

### 2.7 通用计费规则调整 11.30 拍板常量（源：同需求答疑终局 2026-11-02/03 拍板；本族需求直接引用，全量详见该需求理解说明）

- **接口校验范围**：WMS 取号报价测算接口"校验=是"=**6 项（快递费/配送费/包装服务费/操作费/整箱分拣费/拆零分拣费）× 2 流向（总部收业务仓/总部付操作仓）**；③操作仓→总部（流量管理费）不在范围；业务管理费/流量管理费/装车/卸车/入库/出库/订单拦截/存储 8 项不在校验范围（费用照产生）。
- **单仓豁免矩阵**（范围内）：单仓豁免=操作/整箱分拣/拆零分拣/包装 4 项；正常校验=快递/配送 2 项；单自提（非单仓）=4 项参与；自提×单仓=0 项参与（断言无任何缺失报错）。
- **出参呈现**：无报价/被豁免费用项在费用详情 list **不出现**（断言"list 不含该项"，实测与此不符=缺陷提单非改预期）。
- **账单断言 B 档+载体**：行有无+流向+金额格非空（不做公式验算，公式归三报价菜单用例）；载体=UI 账单页（普通费用=云仓账单菜单、存储费=云仓存储账单菜单）+菜单未上线降级接口/数据核对（断言强度不降）。
- **存储费结算流向=①+②双向**（总部收业务仓+总部付操作仓）。
- 分拣费=整箱/拆零两个费用项勿折叠计数（通用纪律见独立定稿 §16.1 G10）。
- **账单展示模型（宽表）与无报价形态（跨需求继承 M4 四态）**：云仓账单一行=一条订单/运单（行粒度按客户特定结算规则的出库计费维度），费用项作为**列**横向挂载——能匹配报价的展示金额、**匹配不到报价的金额格空白（非 0、不可点击）**，与"有报价但计费结果 0 元"（金额=0 可点击）区分；凡云仓族需求以云仓账单/存储账单为断言载体（如通用计费规则调整），断言单位="订单行×费用项列的金额格"、**禁"费用行"条式语汇**，无报价呈现直接继承 M4 四态不自创（通用计费 WB 对比 TC_086/089 吸收沉淀，2026-11-03 用户拍板）。

### 2.8 单仓判定基线（云仓族；迁自通用正本 §7.3，2026-11-04 体系拆分原文搬迁）

单仓=业务仓=操作仓（同仓）OR 归属公司一致（纳税人识别号相同：当前最新版**已审核**税务记录、按业务时间落段取值、空不属于一致、未审核不参与）。**报价类结论端：任一形态为真→费用照常产生、无豁免**（与仓内作业价格的同号豁免区分，防代码误移植）；须覆盖五维不等排除、同仓/同号/异号/单空/双空/未审核/时间范围外七要素。

### 3.1 页签内「维度组合唯一」卡控（源：按钮参考 v1.5 〇.9）

- 唯一性粒度=页签内声明的维度组合（对客原型：同订单类型仅一条规则**不论计费维度**——两维度同订单类型互斥，杜绝订单双值命中两规则的匹配歧义）；不同订单类型互不排斥可并存。同构：装卸/拦截页签「同费用名称+订单类型仅一条」「同订单类型+特殊属性仅一条」。
- **卡控形态=或关系两可**（用户定稿）：形态A 前置卡控（下拉动态剔除已维护类型）或 形态B 保存拦截（可选相同类型、保存时校验拦截）——按双形态识别前置设计（独立定稿 §2.6），**核心断言=唯一性卡得住**（最终不可出现两条同维度组合规则），形态仅为实现路径。
- 必覆盖：①各类型各一条并存成功；②重复维度组合→下拉不可选或保存拦截（或关系断言）；③计费匹配无歧义（该类型订单仅命中唯一对应规则）。

### 3.2 成本取数口径（源：按钮参考 v1.6 九.7，含成本上浮/下调的报价类通用）

成本「业务仓支出费用项金额」三定稿：

1. **来源=另外三个报价菜单的账单**：平台价格/仓内作业价格/配送价格的计费结果（业务仓支出账单各费用项金额=对客报价公式中的成本），对应统收统付链路"总部收业务仓"侧。
2. **时序=同事件同时**：同一事件触发时，成本侧计费与对客计费同步进行，无先后等待。
3. **缺失兜底=成本按 0 进公式**（无报价导致的缺失与真实为 0 同口径）：成本上浮按 **0+金额①** 出账；成本下调按 **max(0−金额①,0)=0** 出账（金额出 0 **非费用项为空**——与"匹配不到报价→费用项空"是两类场景：报价在而成本缺=算 0；报价不在=费用项空）。

必覆盖 6 用例：①上浮正常；②下调正常含成本<金额①出 0 边界；③上浮无成本→0+金额①；④下调无成本→0；⑤成本真实为 0 与无成本等价断言；⑥公式原值带 4 位小数进三态合成（E1：全程不中途舍入，终值按费用精度一次性取舍〔2026-11-03 修订〕）。

### 3.3 费用精度定稿（源：按钮参考 v1.7，配送/冷链运输 11.27V3/Sprint60 快递费/Sprint82 调拨费四需求一致）

- 「**最终金额=费用精度（计费结果）**」：分=保留两位小数 / 角=一位小数 / 元=整数元，**四舍五入 half-up**（1.125→1.13）。
- **计费过程全程不中途舍入（2026-11-03 对客报价拍板 E1，修订原"金额①四舍五入保留两位小数"中间值口径）**：各费用项公式原值（含多明细原值合计）→三态合成→明细加总→**最终按费用精度 half-up 一次性取舍**，无任何中间舍入步骤（需求正文"金额①（四舍五入保留两位小数）"句已同步修订作废）。基础+分精度下终值与旧口径多数相同（round 幂等），三态合成含厘位成本/多明细原值合计时可能差 1 分，以原值链路为断言口径。
- 重量精度作用时点（匹配段前 vs 计算时）两说并存时按各需求实证，执行校准。

### 3.4 导入模版公式形态映射与形态判定（源：按钮参考 v1.8 九.8 + v1.10 〇.11）

- **映射规则**（模版字段组合表达公式形态，与页面三形态同构）：只填首价/基础价格=**一口价**；只填续价=**单价**；两者都填=**首价+续价（阶梯）**；都不填=校验拦截（计费公式不允许为空）。不存在"模版缺一口价/单价形态"问题。
- **形态判定**（执行细化）：形态由导入实际填写的字段组合判定；**多形态字段冲突组合（一口价+单价同填）=拦截**；最低收费>最高收费=拦截；模版与计费维度错配（重量模版导箱数维度公司）=拦截。
- 最低/最高收费为可选列，按勾选/填写独立生效。
- 必覆盖：①三形态各一行导入断言入库公式形态；②首价+续价全空行→整批失败；③一口价行的首重/基础箱数可空性观察。

### 3.5 多维明细报价的导出拆行（源：按钮参考 v1.9，平台价格 TC_198/199 实证）

- 适用：一条报价内含多维明细组的报价菜单（对客报价=物流公司×目的省市为首例；平台/仓内/配送一报价一行、不适用）。
- **拆分粒度=明细组维度逐行展开**（物流公司×目的省市×重量段/箱数段），总行数=Σ各报价的明细组行数。
- **数据范围=按查询结果**：含未审核/副本，不按审核/生效状态过滤（实证：行数=页面总数、各状态组合均可导出）。
- 断言：①拆分行数=Σ明细组；②同报价多公司分片呈现（公司标识列区分）；③行数=查询总数。

### 3.6 三态合成精确口径（源：按钮参考 v1.10 九.9，含上浮/下调的报价类通用）

- 公式：基础报价=金额①；成本上浮=**业务仓支出费用项金额+金额①**；成本下调=**max[(业务仓支出费用项金额−金额①), 0]**（max 兜底属合成逻辑，非最低/最高字段）。
- 四条核心口径：①**三态合成与最低/最高彻底脱钩**（最低/最高仅是金额①内部的保底/封顶字段，勿当三态一部分）；②**费用项级一一对应合成**（每个费用项用自己的成本×自己的金额①，不整单打包；基础报价的费用项不消耗成本）；③官方示例可直接用作例数据：成本 操作费10/包装7.8/快递8.2；报价 操作费（基础）12/包装（下调）1.2/快递（上浮）1.2 → **最终=12+(8.2+1.2)+max(7.8−1.2,0)=28**；④存储费特例：仓内作业价格算出的存储费=该费用项"业务仓支出费用项金额"，对客存储费按三态取最终金额。

### 3.7 费用项内部明细 vs 独立费用项辨析（源：按钮参考 v1.10 九.10）

- 费用项**内部明细类型**（合并一笔）：操作费一级/二级单位=同一费用项的两个计费公式明细——账单仅展示合并后一笔（缺失行按空/0 加总）。
- **独立费用项**（各自入账）：分拣费整箱/拆零=两个独立费用项——账单各占一列，无合计不合并。
- 判定方法：看账单费用项列结构——固定列中各占一列的是独立费用项，同列合并的是内部明细；勿把内部明细当多笔费用。

### 3.8 范围段双态同构与段匹配三口径（源：按钮参考 v1.10 〇.10，报价类范围段字段通用）

1. **双态同构**：编辑态=起始/结束两个输入框（首段开始系统默认 0 不可改、只编辑结束值；次段开始自动带出前段结束值）；配置/展示态=文本区间（如 `0<kg<=10`）。两态同源同一份数据。
2. **首段起点=0、左开右闭**（与独立定稿 §8.7 价格明细段口径一致）。
3. **字段值=0 不命中任何段**：计费字段值=0（数量/重量/箱数/天数）落不到首段→该费用项按兜底为空——首段起点是 0 但不含 0。

### 3.9 产品级与公司级匹配（源：按钮参考 v1.10 九.5补，带物流产品/产品类型的报价通用）

- 匹配规则=**产品级精确>公司级兜底**（同构特殊属性精确>空）：订单产品有对应产品级报价→命中产品级；无→命中同公司"未选产品"的公司级明细；仅产品级无公司级兜底→费用项空。
- **订单侧可空性不对称警示**：物流产品订单侧**始终有值**（不造"订单产品为空"场景）；特殊属性订单侧**可为空**（必须覆盖"订单为空+空兜底命中"路径）——两字段匹配方向同构但可空性不对称，用例数据设计勿混用模板。

### 3.10 机构自治制权限（源：按钮参考 v1.11，对客报价 v3 文本）

对客报价=**机构自治制**：查询=登录机构**及下级**；写=**仅本机构**（不含下级——省公司可查辖内但编辑下级被拦截）——**不同于**仓内作业价格"仅总部可操作"模型，同族需求用例勿套错权限模板。角标计入下级机构未审核（与查询范围同源）。
