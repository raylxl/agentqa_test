# 对客账单 用例编写标准 v1

> **定位**：**对客账单域**的用例编写标准，**跨需求版本复用**——适用于"对客账单增加寄件人信息 1.27"及后续对客账单优化需求；**不挂需求版本号**，需求版本级差异一律以该版本《需求理解说明》为唯一依据。
> **通用方法与归属正本**：《通用用例设计标准_v1》现行版及适用族标准《账单族标准_v1》；本文只管对客账单域的列结构、寄件信息取值来源、查询/导出与断言锚点。不复制通用正本内容，只引用；涉及金额格可点击性等按账单族标准 §15.6（本域展示列改造未涉及，仅背景）。
> **抽离来源**：《财务需求2026_快运_对客账单增加寄件人信息 1.27_需求理解说明_v1.0.1》5 项拍板（2026-11-20 全闭环，含独立质疑补漏 Q5）。后续拍板新增按 v2 只增不覆盖。
> **消费方式**：对客账单用例分章生成时随章分发，子代理**不得重复询问、不得自创口径**；与通用正本/理解说明冲突时以理解说明为准；无覆盖 → "转测校准"句式 + 上报主流程，禁臆断。

## 一、固定枚举与控件常量（禁止自造取值）

| 项 | 常量 |
|---|---|
| 寄件人姓名（列） | 原"寄件客户名称"列**更名**而来；取值=**下单运单寄件人姓名 `senderName`**（地址簿 `contactName` 同源，Q2）；**完整显示、不脱敏**（Q3） |
| 寄件客户名称（列） | **新增**列，位于"寄件客户编码"**前面**；取值=**下单运单快照 `senderCustomerName`**（非实时主数据 `customerName`，Q5）；完整显示、不脱敏（Q3）；**支持导出** |
| 寄件客户编码（列） | 既有列，位置作新增列的锚点（新列在其前）；本需求不改其取值 |
| 查询条件"寄件客户" | **维持原口径**=按**寄件客户（客户主体）**查询；**不**改用寄件人姓名查；更名/新增列不影响查询逻辑（Q4-6.2，原文 PS） |
| 导出 | 导出**当前查询结果集**（按现有筛选条件、全量约 2336 条 / 234 页），非仅当前页；导出列含新增"寄件客户名称"且与列表同序、取值一致（Q4-6.3） |
| 列表规模 | 约 2336 条 / 234 页 / 10 条每页（原型图，仅量级背景，无性能指标） |

> 说明：本域无金额计算、报价匹配、月结、重算等枚举（对客账单展示列改造不涉及）；如需扩展见账单族标准。

## 二、业务对象常量表（含来源→本菜单呈现映射）

| 业务对象 | 来源/取值 | 本菜单呈现 | 现行出处 |
|---|---|---|---|
| 寄件人姓名 | 运单 `senderName`（运单创建/变更经 MQ 回写地址簿 `crm_address_lib_info` 的 `contactName`） | 列表列"寄件人姓名"，完整显示 | Q2；KB RB-032（侧证） |
| 寄件客户名称 | 下单运单快照 `senderCustomerName`（**不是**实时客户主数据 `customerName`） | 列表列"寄件客户名称"（位于寄件客户编码前）+ 导出同列 | Q5（修正 Q2 斜杠歧义）；KB RB-032/QA-2026-0058（侧证） |
| 寄件客户 | 查询维度=客户主体 | 查询区"寄件客户 请输入"输入项 | Q4-6.2 |

**来源规则→呈现映射**：
| 规则 | 本菜单呈现 |
|---|---|
| 客户改名（主数据 `customerName` 变化） | 历史账单寄件客户名称**仍显示下单时名称**（取运单快照），不随改名漂移（Q5） |
| 寄件联系人与寄件客户主体不同 | 两列各自独立显示、不串值；构造"寄件人姓名 ≠ 寄件客户名称"数据验证（Q2） |

## 三、列结构常量

- **列序（本需求相关段）**：…寄件人姓名（原寄件客户名称更名，绿色高亮）→ **寄件客户名称（新增）** → 寄件客户编码 → …（其余列不变）。
- **新增列插入点**：寄件客户名称**紧邻寄件客户编码之前**。
- **导出列**：含新增"寄件客户名称"；列序与取值与列表一致（Q4-6.3）。
- 表头文案按理解说明/原型图，不臆造别名。

## 四、处理链路

本域为**展示列改造**，无计费/重算/结算链路。取值链路（背景）：下单运单创建 → 寄件人姓名 `senderName`、寄件客户名 `senderCustomerName` 落运单快照 → 对客账单列表/导出取该快照呈现（Q2/Q5）。客户主数据变更不影响已生成账单的这两列（Q5）。查询/导出链路：查询区按寄件客户过滤 → 列表按结果集呈现 → 导出按当前结果集全量导出（Q4）。

## 五、判定规则表（前置/预期直接引用）

### 5.1 取值判定
| 列 | 预期值 | 断言 |
|---|---|---|
| 寄件人姓名 | 运单 `senderName` | 列值=下单运单寄件人姓名；与寄件客户名称可不同、不串值 |
| 寄件客户名称 | 运单快照 `senderCustomerName` | 列值=下单运单寄件客户名；客户改名后历史账单仍为此快照值 |

### 5.2 查询判定（Q4-6.2）
- 按寄件客户查询 → 命中该客户账单（断言正常）。
- 寄件人姓名**非查询条件**（反向确认：不按寄件人姓名查；不测人名查询能力）。

### 5.3 导出判定（Q4-6.3）
- 导出行数=当前查询结果集全量（非当前页 10 条）。
- 导出列顺序/取值与列表一致（含新增寄件客户名称）。

### 5.4 安全/权限判定（Q3 + Q1）
- 两列列表/导出均**完整显示、不脱敏**，无掩码断言。
- 权限隔离：客户仅见自身账单；导出=数据出口的合规确认。

### 5.5 可靠性判定（Q1 + 转测校准②）
- 取不到寄件人姓名/寄件客户名称时的降级显示：默认留空不造假数据（转测校准②观察是否需要占位）。

## 六、断言锚点口径（对客账单域）

| 断言对象 | 标准句式 |
|---|---|
| 寄件人姓名列 | 列值=下单运单 `senderName`；与寄件客户名称各自独立、不串值 |
| 寄件客户名称列 | 列值=下单运单快照 `senderCustomerName`；改名后历史账单仍为快照值（Q5 快照断言） |
| 列位置 | 寄件客户名称紧邻寄件客户编码之前 |
| 查询 | 按寄件客户查询命中；寄件人姓名不是查询条件 |
| 导出 | 两步：结果集全量行数 + 列序/取值与列表一致 |
| 脱敏 | 两列完整显示、无掩码；不做掩码断言 |
| 权限 | 客户仅见自身账单；导出合规 |

## 七、转测校准清单（**不得写成肯定式断言**，用"转测校准：观察…"句式）

①多条寄件地址时账单取哪条（方案 A 锚定运单 `senderName` 不读地址簿表，观察展示值是否稳定）；②取不到值时显示的降级形态（默认留空，观察是否需占位）；③列表 2336 条 + 导出大批量的加载/导出耗时（无指标）；④原型图绿色列数据行空、人名在右列（改造稿未填样例数据，以 Q2/Q5 取值口径为准验真实数据）；⑤两列文本超长展示（截断/省略/换行/自适应，导出保留完整值）；⑥含 CSV 分隔符/引号/换行/公式前导符时的导出转义（归通用导出基线，观察错位/注入风险）。

## 八、数据准备（PRE）依赖清单（造数配置项，不归属用例、不计数）

| 类 | 需备数据 |
|---|---|
| 运单快照 | 寄件联系人姓名 `senderName` ≠ 寄件客户名 `senderCustomerName` 的运单（验证两列独立）；含完整寄件人信息的账单行 |
| 客户改名对照 | 同一寄件客户改名前后各一笔账单（验证 Q5 快照：历史账单仍为下单时名称） |
| 多地址客户 | 同一寄件客户多条寄件地址（addressType=2）的运单（观察转测校准①） |
| 空值/超长/特殊字符 | 寄件人姓名或寄件客户名称为空、超长、含 CSV 分隔符/公式前导符的账单行（覆盖转测校准②⑤⑥） |
| 权限 | 不同客户账号各若干账单（验证权限隔离）；查询区寄件客户编码/名称（验证查询） |

## 九、用例组织约定（对客账单域）

- 条目格式/执行规范/优先级/门禁证书=按通用正本执行；一用例一测试点。
- 章节按该版本理解说明的用例组落位（功能/UI/导出/安全/可靠性）；分章源件入 `用例文件\对客账单分章\`，主流程组装成册。
- 断言引用优先级：本文 § > 理解说明 § > 原文；三者皆无 → 转测校准句式 + 上报主流程。
- 明确不测：计费金额计算、报价匹配、优先级、云仓账单（本需求不涉及，Q4-6.1）。
