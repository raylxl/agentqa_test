## 一、固定枚举与控件常量

| 项 | 取值 |
| --- | --- |
| 审核状态 audit_status | 0 未提交、1 未审核、2 已审核、3 已驳回 |
| 审核节点 audit_code（冷链快运） | 10 申请人、20 省区网络、30 省区财务、40 快运网管、50 快运税务 |
| 税务信息维护标识 isTaxpayerInfoFlag | none 未维护、done 已维护、notVerify 不校验 |
| 录单被税务拦截时保存接口的返回 | HTTP 200、success=false、code=WAYBILL_ERROR_00001502、msg 为页面提示语 |
| 机构类型 | 一级网点 FIR_SITE、二级网点 SEC_SITE |
| 录单页面单据类型 | 录运单（默认）、录回单、录订单、录整车单 |
| 录单页面提交按钮 | "保存"（运单号在保存后生成） |

## 二、税务信息对象常量表

| 对象 | 常量 |
| --- | --- |
| 主表 | `pasdb.t_fip_finance_invoice_corp_info`（tenant_id='1' 为冷链快运） |
| 有效期 | start_eff_time＝生效日 00:00:00；end_eff_time＝失效日 23:59:59 |
| 审核通过过的标记 | his_is_audited＝1（审批中的记录为空，流程走完审通过才置 1） |
| 审核通过快照 | audit_snapshoot（公司名称、税号、法定代表人、纳税人资质、生效日期、失效日期） |
| 审核轨迹 | `pasdb.t_fip_finance_invoice_corp_info_log`（提交、各节点通过与驳回各一行） |
| 查询接口 | `POST gateway-ll/phecda/api/phecda/data/account/findAccountBalance`，入参 orgCode，出参 `result.isTaxpayerInfoFlag` |
| 录单保存接口 | `POST gateway-ll/waybills/web/waybill/save`（运单服务；税务校验在这里做，录单页面不调查询接口） |

来源菜单特殊规则 → 本域呈现：

| 来源 | 规则 | 在本域的呈现 |
| --- | --- | --- |
| 营业网点 | 财务中心加盟属性＝直营 | 决定一级网点是否需要校验 |
| 省区会计架构维护 | 类型＝省公司且集团关系＝集团内 | 决定二级网点是否需要校验 |
| 统一税务信息维护页面 | 一个机构可有多条记录，有效期按天维护 | 判定按"寄件时间落在哪条记录有效期内" |

## 三、结构常量

- 录单入口：冷链快运 → 经营管理中心 → 运单中心 → 网点录单（`/Waybill/SiteRecord`）。生产环境清单里二级分类名为"运单管理"。
- 录单页面默认值（机构 220303 实测）：收件业务员自动带出；产品分类 冷链快运(包含鲸小包)；温区 冷冻；服务方式 派送；寄件网点＝登录机构（不可改）；支付类型 现汇；是否保价 是；送货上楼 无需上楼；增值服务 无；产品方案默认选 鲸鲜达（特惠件）。
- 录单必填 20 项：收件业务员、温区、服务方式、寄件人、寄件省、寄件详细地址、收件人、收件省、收件详细地址、物品名称、物品类型、包装类型、总体积、实际重量、总件数、支付类型、是否保价、保价金额、送货方式、增值服务。
- 操作步骤实录见理解说明 12.4（8 步）。

## 四、统一处理链路

1. 录单保存链路：填单 → 点"保存" → 页面提交保存接口 → 运单服务校验（含税务信息校验）→ 通过则生成运单；不通过则返回失败消息，页面顶部红色提示，运单不生成、表单保留。
2. 税务信息判定链路（每个参与校验的网点各走一遍）：是否需要校验 → 有没有审核通过过的记录 → 寄件时间是否落在某条记录有效期内。
3. 录单页面打开时不调 findAccountBalance；该接口是给其它调用方用的。

## 五、判定规则表

**5.1 哪些网点需要校验**

| 网点 | 需要校验的条件 |
| --- | --- |
| 一级网点 | 其省公司（营业网点中财务中心加盟属性）为直营 |
| 二级网点 | 其上级一级网点在省区会计架构维护中为"集团内+省公司" |
| 其它 | 无法录单，不纳入 |

**5.2 单个网点的判定（N8、N17~N20）**

| # | 是否需要校验 | 有没有审核通过过的记录（含已失效的） | 寄件时间是否落在某条记录有效期内（不看审核状态） | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 否 | 不看 | 不看 | 通过 |
| 2 | 是 | 没有（新入网） | 不看 | 拦截 |
| 3 | 是 | 有（老网点） | 是 | 通过 |
| 4 | 是 | 有（老网点） | 否 | 拦截 |

**5.3 寄、派件网点都校验**：两边都通过才放行，任一方不通过就拦（N17）。

**5.4 匹配口径**：录单的寄件日期是带时分秒的当前时间；税务信息有效期按天维护；用寄件时间去找有效期覆盖它的记录（N18）。

**5.5 "不看审核状态"的含义**：覆盖寄件时间的那条记录，未提交、未审核、已驳回、已审核四种状态都算"有"（N8）。

**5.6 老网点**：机构下存在 his_is_audited=1 的记录即老网点；记录即使已失效，只要审核通过过就算（N20）。审批中的不算。

**5.7 改有效期立即生效**：老网点把记录的失效日期改到过去，从那一刻起拦截；未提交、审批中、已驳回三种情形都拦；新增一条覆盖寄件时间的记录后恢复（N16）。

**5.8 拦截的表现**：保存接口返回 WAYBILL_ERROR_00001502；页面提示"{网点名} 还没有维护税务信息，请去"网点税务信息"菜单维护税务信息后再开单！"。

## 六、断言锚点口径

| 层 | 锚点 | 口径 |
| --- | --- | --- |
| 录单界面 | 页面顶部提示 | 被拦：出现 5.8 的提示语，网点名与被拦的网点对应 |
| 录单界面 | 运单号 | 被拦：仍为空；放行：保存后生成运单号 |
| 保存接口 | 响应 | 被拦：success=false、code=WAYBILL_ERROR_00001502、msg 同提示语；放行：success=true |
| 查询接口 | isTaxpayerInfoFlag | 按判定表：通过＝done（范围外＝notVerify），拦截＝none |
| 一致性 | 查询接口 vs 录单保存 | 同一网点、同一时刻，两者结论须一致 |
| 数据佐证 | 只读查库 | 记录的 audit_status、start_eff_time、end_eff_time、his_is_audited 与用例前置相符 |

判定以界面或接口的实际落地为准；只查到库里的数据不算通过。

## 七、转测校准清单（"观察XX"句式，不写成肯定断言）

① 提示语里的菜单名"网点税务信息"是否与快运现行菜单名一致。
② 派件网点不通过时，提示语里是派件网点名还是寄件网点名。
③ 已录成的运单之后改单、重开时是否再校验。
④ 补录税务信息后多久恢复录单（判定有无缓存）。
⑤ 税务信息页面的生效、失效日期能否选过去的日期。
⑥ 迁移来的已审核记录节点码为 40，页面上的节点名称显示为什么。
⑦ 失效当天 23:59:59 末尾不足一秒的极端时刻。
⑧ 存量数据里多条已审核记录有效期重叠的机构，判定取哪一条。

## 九、用例组织约定

- 按判定表组织：范围外放行、新入网拦截、老网点在期放行、老网点过期拦截（覆盖未提交／未审核／已驳回／已审核四种状态的记录）、改有效期立即拦截与恢复（N16 四条）、寄派件组合（寄件过／派件过／都过／任一不过）。
- 另设：查询接口标识逐行、查询接口与录单保存结果一致性。
- 回归：智运、云仓的录单校验不受有效期影响；优化点一~三与本轮交叉的点。
- 不写：非一级、二级网点的标识预期；性能、可靠性用例；物料申购等录单以外的消费点；到期提醒；批量录单入口（批量录单、批量录单（新）是另外的菜单，用户 2026-11-25 拍板不考虑，不留观察条）。
- 优先级：拦截与放行的主路径、寄派件组合为最高级；一致性、回归次之。
