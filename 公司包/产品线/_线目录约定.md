# 产品线目录约定 v1（2026-11-19 立·拍板"一把梭"物理拆分）

> **职责**：`公司包\产品线\` 下每条产品线一个目录，线级资产物理隔离（00 索引定位序第 0.5 步判线后只读当前线目录）。线名自取名制，正本登记=公司包《业务线登记_v1》（查重防撞+接入三步）。**新线预留位=本约定固定子结构，登记后照建；不预建空目录、不预写空文件**（空壳=漂移源）。

## 一、线目录固定子结构

```
公司包/产品线/{线名}/
├── L2族标准…           # 族级标准（初期无族=无此类文件，同类需求≥2 再立族）
├── {线名}租户用例编写标准…   # L3 租户口径（有租户维度才建）
├── L4域标准/            # 域标准仓内副本（活正本=各线需求文档库；对账防分叉）
├── {线名}_用例设计线内补充_v{N}.md   # L1 抽离的线级条款正本（§A 数值约定/§B 线级红线细则/§C 资损形态词——各线自定章节）
└── （线配置三段=agent-company.json 业务线.{线名} 段，非独立文件）
```

财务线为首个实例（L2 三族+L3+L4域标准/+线内补充+线配置三段），照此结构对照即可。

## 二、纪律

- 判线非当前线 → 目录一律不读（generator §0a / 00 索引定位序 0.5 双拦）；
- 线内条款与公司级冲突 → 公司级为骨架基准，线级只能**补充/收严**，推翻级差异走 00 索引 §三 第 7 条晋升/降级协议（发起人拍板）；
- 命名模式：`{线名}_` 前缀类文件（线内补充/租户标准）显式挂线名；需求前缀等值在 agent-company.json `业务线.{线名}`；
- 本目录（产品线/）不公司级化：任何"看起来通用"的内容先按 00 索引 §三 判归属，通用→公司包/标准体系/，禁在线目录里养第二正本。
