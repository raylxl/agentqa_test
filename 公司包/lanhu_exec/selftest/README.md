# lanhu_exec 自检包（改判据后必跑）

采集标准 R14a：**凡放宽或重写任何一道闸门的判据，须同时用"故意弄坏的文档"验证它仍拦得住**，全部拦截才算合格；只看真文档变绿就上线，等于把闸门拆了。

| 脚本 | 检查对象 | 联网 | 内容 |
|---|---|---|---|
| `selftest_fidelity.py` | `lanhu_fidelity.py` 文字忠实闸 | 否 | 8 份假文档须全红（且须是"疑似改写/自撰"那一项报的）+ 1 份真文档须绿 |
| `selftest_reconcile.py` | `lanhu_reconcile.js` 对账器 | 是（经浏览器池连蓝湖） | 5 份假文档须全红，且拦住的原因要对 |

```bash
python selftest/selftest_fidelity.py                                    # 退出码 0 = 全部符合预期
python selftest/selftest_reconcile.py --stage <batch_recollect 暂存目录> --port 9334
```

- **仓库里没有任何真实需求内容。** 文字忠实闸的样例是合成的虚构数据（`build_fixtures.py` 生成 `fixtures/`）；对账器的假文档在运行时从本地暂存区的真文档现场改坏，放系统临时目录、跑完即删。
- 假文档都"像真的"——用页面上现成的词去改，所以才能检验判据是不是真的严。文字忠实闸的 8 种改法：
  工具栏里状态词换成重复的另一个；插入一行全由页面词拼成的假规则；九行长段里改一个词；九行长段里调换两个短语；同一行里三个词换成重复的另一个页面词；插入自撰句；一格里两行都是页面真话但取自毫不相干的位置；一格里上下两行顺序颠倒。
- 新增反向用例：文字忠实闸——在 `build_fixtures.py` 的 `MUT` 里加一种改法，并在 `selftest_fidelity.py` 的 `CASES` 里加一行；对账器——在 `selftest_reconcile.py` 里加一种现场改坏的方式。
- "退出码非零"不等于"检查拦住了"——两个脚本都把闸门自身报错（`ENOENT` / `MENU_NOT_FOUND` / 没产出结果）算作未通过。
- 构造不出所需的假文档（比如暂存区没有带流程图的文档）时，对账器自检直接判未通过，不会静默放行。
