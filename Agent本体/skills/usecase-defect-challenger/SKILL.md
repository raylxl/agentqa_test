# usecase-defect-challenger 提单前质疑方（2026-11-18 立·执行质疑标准 v1.3 挂点⑤）

## 0. 公司适配层（开工第 0 步）

读 workspace `公司包/agent-company.json`（integrations.defect_platform=平台适配器）；坑库正本路径取 `{paths.执行坑库}`。无公司包→降级通用模式（坑库位置由调用方给，缺则 D1 降为通用自问清单）。

## 定位与教训溯源

血泪校准（三起差点报给开发的假缺陷 + 一族连坐）：
- **ARGB 子串误判**：黑 FF000000 含子串 FF0000 被 includes 判红 →"非必填列也全红"假缺陷，用户两次质疑后精确匹配复验才撤；
- **EXP05 只读首 sheet**：导出按费用项拆多 sheet，只读第一个误报"数据缺失"，差点立 NEW-D1；
- **页签模式自我证伪**：诊断工具（旧引擎快照 reload）自己改变了页面状态，把工具病当成系统病报出；
- **连坐族**：toast 3 秒时序 / label 标红 / blur 失焦 / 拦截链影子行——一批"失败"全是断言姿势错。

结论：**起草方自检（四闸门）不够，提单前要一个没参与起草的实例做对抗复核**。

## 六查清单（D1~D6，逐项过，禁跳项）

**D1 工具层排除（最高频翻案源）**：拿坑库 G/H/Q 系索引逐类反查——时序类（toast 消失窗口/采样过晚）、解析类（子串匹配/只读首处/编码转义）、焦点类（hasFocus/blur 未触发）、自我污染类（诊断脚本 reload/切租户残留）、多载体类（多 sheet/多页签/多格式）。**任何一条疑似命中→先修姿势复测，复测翻案即销，禁带疑提单**。

**D2 对照组**：同类正向场景是否有通过记录（同功能不同数据/同数据不同入口至少其一）——有对照才可断言异常；无对照先补正向复测。

**D3 复现稳定性**：≥2 次复现或时序窗口确认（偶发一次=观察项登账，不提单）；复现步骤须可被第二人照做。

**D4 第二通道交叉**：API×UI / 第二实例（933x 另一端口）/ 第二账号 至少其一交叉印证；通道间矛盾→先查通道再报。

**D5 五段齐全与原文完整**：场景/操作/预期/实际/消息原文五段；消息原文**逐字**（禁转述/截断）；预期必须引自需求或用例原文（禁自设预期）；附证据锚点（订单号/编码/截图/账本行）。

**D6 根因四归属**：系统 / 数据（主数据错→管理员通道）/ 配置（规则配置错→配置方）/ 工具（我方姿势→修姿势）——只有"系统"走缺陷单；数据配置类转对应通道并登台账。

## 三道出口

| 出口 | 条件 | 动作 |
|---|---|---|
| **放行** | D1~D6 全过 | 质疑记录（六查逐项结论）并入提单"判定过程留痕"字段，按平台适配器落单 |
| **驳回补证** | 任一查缺证据 | 给补证清单（缺哪查哪条），回起草方 |
| **转呈报** | 根因=口径/需求歧义 | 不提单，登呈报台账给用户拍板 |

## 纪律
- 质疑方独立实例（spawn 子代理或另会话），起草者不自证；
- "放行"结论必须附六查逐项记录，无记录无效；
- 已提单后发现 D1~D6 有漏——撤单走平台流程，禁将错就错；
- 与四闸门关系：闸门=起草侧自检（模板规范 v1.1），本技能=提单前独立质疑；两道都过才出单。
