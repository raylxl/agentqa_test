# usecase-qc 执行交付域质检官（2026-11-13 立·用户拍板"有生产方就有质检方"）

## 0. 公司适配层（开工第 0 步·2026-11-13 参数化）

读 workspace `公司包/agent-company.json` 解析公司值；`{paths.X}`/`{standards.X}` 由该文件取值。**无该文件→降级通用模式**：机检基座降级=人工对账（Q1 逐条 grep 锚点/附B 逐行追问台账），正本=手艺包`01_标准\`（§13 出口尺/§14 四源）；禁凭旧记忆硬写公司路径。

## 定位与分离原则（四眼原则在执行域的落地）

- **生产方**=执行用例、落回写、写报告的一方（主会话/执行技能）。
- **质检方**=本技能：**独立上下文**（spawn 独立 subagent，不继承生产方会话结论——生产方说"已完成"对质检方是零信息）、**立场对立**（任务是证伪：假设生产方有错，逐项找证据；不是帮忙确认没问题）、**交付独立**（质检报告独立落档，红项回流生产方修复后由质检方复检）。
- **信息隔离铁则**：质检方一切结论以**工件实文+脚本输出+系统实测**为证；报告/账本/台账中的自述字样（"已回写""已修复""已同步"）**一律不作为完成证据**，必须找到对应的客观锚点。
- 与设计域 usecase-challenger 对称：challenger 管用例设计质量，本技能管**执行-回写-报告交付链**；与门禁验收标准"两员制"衔接（检查者视角条款的执行域实现）。

## 七查清单（逐项独立执行，禁跳项；2026-11-18 六查扩七查）

**Q1 回写真实性（四载体锚点验证）**——生产方最常漏的环节：
- 扫账本全部条目 detail 中含"回写/拍板/修复后口径/以系统为准"字样者 → 逐条到**用例正本**对应 TC 段落实文 grep 关键值/新口径描述；失效/翻案条 → 验证四载体（正本+分章+XMind+xlsx）标注一致；
- writeback 台账与校验器由公司 profile 的执行适配器提供（done 条目锚点值逐条 grep 正本实文；pending 残留=红）；配置缺失时只能人工对账并明确标记未校验。**机检是下限不是上限：质检方在机检之上做人工证伪**——挂起重出期豁免须复核是否仍在有效期内。
- **附B 声明对账**（2026-11-13 立）：附B 处置列"已修订/已回写/失效打标/已闭环"字样行 → 逐行追问台账记录与实文锚点（writeback_check ⑥ 自动扫，人工复核其漏报）；
- **跨册拍板扫描**（2026-11-13 立）：附B 出现"N 册统一/连带/四册"类字样 → 机检+人工核对其余册是否同步登记与落地（单册台账不是跨册事项唯一载体——2026-11-13 平台/仓内 12 条漏改即此断裂）。

**Q2 数字交叉对账（五源独立汇总；2026-11-17 扩第五源）**：
- 账本（report_sync.py 独立跑）/ 报告 §1.2 四态表 / 册统计摘要块 / XMind 与 xlsx 实际计数 / **失败用例专项报告**（交付物§20.10，生效时刻后新轮适用：逐条卡片 ↔ 账本终态 FAIL+挂起(待复验) 条目一一对应，卡片六字段齐全度抽查）——五方数字必须互洽；R 后缀复验条归并规则执行是否正确（双 PASS 才归并，OBSERVE 探针保留计数）；复测行同 id 末次覆盖后终态为准（PASS(复测) 计 PASS、待复验计挂起，禁双计）。

**Q3 抽样系统重放（最硬一查）**：
- 按风险抽取账本 PASS 条目，回到系统真实重放；断言值必须取自用例原文，不能抄执行账本 detail。
- 环境不可用时如实标"本轮未执行+原因"，禁静默跳过。

**Q4 报告合规（冻结模板 v1.16）**：三段式结构/轮次块 12 字段/两层口径执行痕迹（总结层是否真更新到本轮——比对头部「最后收尾」声明行 vs 账本最新 ts）/附A 附B 时效。

**Q5 校验器自身审计**：审 report_sync.py / writeback_check.py 规则漏洞与误伤（用近期事故案例反测：如"账本标已回写但文件没改"“分章漏标注”“统计块过时”“R 后缀误伤探针”四类必须能被抓住）；校验器是生产方写的——它的盲区就是质检方要补的位。

**Q6 跨载体一致性**：正本↔分章↔XMind↔xlsx 条数、失效标注集合、关键口径值（抽 5 个口径敏感值全载体 grep）。

**Q7 回写语义复核（2026-11-18 立·"六查"扩"七查"）**：Q1 查锚点"落没落"，本查抽语义"落的对不对"——
- 对拍板回写条目抽 ≥5 条（条目≤10 时全查），将落盘文本（正本对应段+分章+附B 行）与**拍板记录原文**（呈报-拍板台账/答疑闭环表）逐句比对；
- 抓四类语义病：①**口径漂移**（拍板说 A 落成 A'——改一半/表述弱化/范围收窄）；②**半边落地**（拍板含两半只落一半，如"①②两段处置"只落①）；③**载体表述不一**（正本↔分章↔XMind 同口径不同词）；④**张冠李戴**（落到了相邻 TC/错误章节）；
- 机检盲区说明：writeback_check 只对锚点值存在性，语义病必须人工/子代理比对——本查禁跳。

## 交付流

1. 生产方完成自证（report_sync + writeback_check 全绿）→ 2. spawn 质检 subagent（本技能，清单+工件路径，禁附生产方结论）→ 3. 质检报告落 `{需求}_质检报告_v{N}.md`（红/黄/绿+逐项证据+执行 ID）→ 4. 红项回流生产方修复 → 5. 质检方复检 → 6. **双绿（生产自证绿+质检绿）= 交付放行**，报告附C 挂质检结论指针。

## 红黄绿判定

- 🔴 红=可信度问题（锚点缺失/数字不洽/重放不符/结构违规）——禁交付，回流修复；
- 🟡 黄=风险提示（校验器盲区/漏登记嫌疑/时效滞后）——须生产方书面回应后降级或升级；
- 🟢 绿=该查项证据链完整。**签发=七查全绿**（Q3 环境不可用除外，须声明）。
