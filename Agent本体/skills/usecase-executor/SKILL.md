# 用例执行（AI 执行工序）

## 0. 公司适配层（开工第 0 步·2026-11-13 参数化）

读 workspace `公司包/agent-company.json` 解析公司值；`{paths.X}`/`{standards.X}`/`{naming.X}`/`{环境.X}` 由该文件取值（校验器清单/坑库/端口矩阵/报告命名均配置化）。**无该文件→降级通用模式**：正本=手艺包`01_标准\`（§11 就绪度/§12 四态纪律/§13 出口尺/§14 反馈闭环），校验器降级=人工对账+报告附台账，浏览器通道按目标系统自配；禁凭旧记忆硬写公司路径。

正本：《{standards.L6_操作细则}》管执行引擎动作/清场/取证；《{standards.L6_执行期参考}》仅管被测系统（{环境.被测系统}）AI 编译动作、断言、变量等执行契约（旧设计方法矩阵为历史附录，现行方法见 L1 §22）；门禁§19管执行出口；{standards.L5_交付}§20管报告格式；《{standards.L6_判定}》是 PASS/FAIL/NOT_EXECUTED/BLOCKED 与证据语义正本。测试阶段号以《{standards.索引}》为准，本技能不另设生命周期阶段编号。**接口通道执行（2026-11-15 立）同依细则§十六**：框架=Playwright request（token 引导/三层断言/采集沉淀纪律，与 UI 通道同 runner 同账本）。

## 执行纪律（批量优先、时间盒、禁停与覆盖度透明）

| # | 纪律 | 违规判定 |
|---|---|---|
| D1 | **批量优先**：接“全跑/全量”指令→先建批量执行器（解析用例 MD→逐条 dispatch→结果写账本）→**禁逐条手写脚本** | 逐条写脚本=违规 |
| D2 | **5 分钟规则**：单条自动化到达墙钟上限仍未到验证点→最终记 `NOT_EXECUTED`；若已知外部通道阻断→记 `BLOCKED`；**全量执行期间禁调试工具** | 超时后继续调试或误报 FAIL=违规 |
| D3 | **禁停**：从开始到全部跑完或硬阻塞才停；**中间禁出报告/禁等指令/禁主动暂停**（用户主动问可答但不停） | 中途停下来出报告=违规 |
| D4 | **覆盖度实时可见**：每完成一个模块打印进度（N/总数=X%） | 用户问覆盖率时答不出=违规 |
| D5 | **一份报告**：全部跑完出一份报告（§20 规范命名+九节＋尾注结构），**禁按轮次/按批次出新版** | 多份报告版本=违规 |
| D6 | **结论限定覆盖**：禁基于部分覆盖下"零缺陷/功能健康"结论；正确写法="基于已执行 N/841 条（X%），核心链路验证通过" | 部分覆盖+全量结论=违规 |

## 指令语义表（2026-11-17 立，用户拍板"全量跑=一版到底"显式化）

| 用户指令 | 计划集 | 行为约定 |
|---|---|---|
| **"全量跑／全部跑一遍"** | 治理计划集全部 | **一版到底**：遇 FAIL/BLOCKED/观察项都不停、不呈报、不修码（D3 禁停照旧）→ 跑完自动接**工序 4.5 失败复测轮**（细则§十七）→ 自动生成含六字段的失败数据报告与失败用例专项报告（交付物§20.10）→ **一次性终审呈报**（feedback-loop） |
| "跑XX模块／跑P0／这N条" | 指定子集（≤计划集） | 同上流程，范围=子集 |
| "复测XX／回归" | 指定条目/待复验清单 | 直入复测/回归通道（有 spec 先走脚本回归，细则§十四 14.2） |

**两条共同保留**：① 连续 3 条环境/通道/超时失败终止阀在全量模式同样保留（自动恢复重登/清场/reload×3 失败后才动作——环境挂了硬跑＝NOT_EXECUTED 假覆盖，不是"执行一版"）；② **"全量跑"禁突破治理计划集**（工序 1.6 对账）——意图超计划集先更治理 JSON 再开跑，禁自行扩大。

## 执行流程（固定顺序，禁跳步）

### 阶段〇：批量准备（执行前一次性完成）

0. **角色自检（L0）**：按《{standards.L0_角色}》确认姿态——本轮执行结束须输出**置信度判断**。
0.5 **读报告规范**：读《{standards.L5_交付}》§20（测试报告生成标准）——**报告命名/九节＋尾注结构/触发时机/禁忌在开工前先入脑**，禁执行完再查。
1. **输入适配**：用例册（MD 正本或同名 xlsx）；无先例模块先补“模块接入配置”——**补配置前先扒开发知识库**（`{paths.公司包}/tools/wk_kb.py search "<菜单名>"`，公司层 `integrations.knowledge_base`，2026-11-17 接线）：菜单名→uri/服务路由（IF 卡）、接口→鉴权/请求头/分页参数、字段线索——命中即写进接入配置少走探索弯路；无卡→**直读源码**（`integrations.dev_git`：后端接口路径/鉴权注解＋前端仓 vue 路由→组件定位字段）→ 仍无果菜单探索实查兜底（KB/源码＝加速器非依赖，不可用记 BLOCKED 不阻塞）。
1.5 **执行前用例分流**：四桶分流（正常/已失效跳过/SYS-DEF-IMP-CHG 必执行/manual_only 跳过登记）。CHG 为需求变化载体，按反馈闭环标准登记；若当前执行批没有 CHG 条，记录“不适用”。**`API-` 前缀条走接口通道 dispatch**（2026-11-15 接口通道立，细则§十六；与 UI 条同批可混编，runner 按通道分组）。
1.6 **治理计划对账**：新需求从治理 JSON 读取 `execution_plan.selected_set` 和 `planned_tc_ids`，按计划集/执行前排除态（`SKIP`、`manual_only`、已失效）形成 dispatch 清单；不得自行扩大/缩小计划集。正式 dispatch 前核对集合完全一致，记录实际 `dispatched_tc_ids` 与 `execution_id`；执行完成、账本与报告已生成后，在治理运行副本中登记 `ledger_ref`、`report_ref` 并校验 execution 阶段。未 dispatch 的计划项补 `NOT_EXECUTED` 或按阻断规则记 `BLOCKED`，并在报告区分计划、排除、已 dispatch、未执行。执行结果账本仍是执行事实正本，禁止把计划 JSON 伪装成执行结果。
1.8 **批量执行器搭建**：
   - **计划集硬对账**：执行循环开始前将实际 dispatch TC 集与治理 JSON `execution_plan.planned_tc_ids` 对账；集合不一致不得开跑。执行完成后回填治理运行副本的 `dispatched_tc_ids`，阶段切为 execution 前必须满足 readiness=ready，并引用账本与报告；治理 JSON 记录计划与追踪引用，不替代 JSONL 执行事实账本。
   - 解析用例 MD → 提取全部 TC 编号/标题/前置/步骤/预期 → 按模块分组
   - 建执行循环：`for each module → for each TC → dispatch(自动化) or mark(人工/BLOCKED) → 写账本 → 打印进度`
   - **进度内置**：每完成一个模块打印 `[进度] 模块X: N/总M (X%)`
   - **禁停内置**：执行循环中间无暂停点/无报告产出点；退出条件=全部跑完 or 连续 **3 条**环境/通道/超时失败（与阶段二、操作细则唯一口径一致）
   - **双通道（2026-11-15 立）**：UI 条走浏览器批量执行器；`API-` 条走接口批量执行器（token 引导→三层断言→账本 channel:'api'/执行号 AX-YYYYMMDD-NNN）——同一账本同一份报告（细则§十六）
1.85 **环境适配器注入（坑库机制）**：按 `execution_adapters.pitfall_scan` 注入环境坑与信任度扫描；对策注入后未命中的按坑库规则计数（累计 N 次转待复验，N 与细则由公司配置提供）。适配器缺失时记录 `BLOCKED`，不把公司工具路径硬编码进本体。

1.82 **规格保真门（开批前置·2026-11-18 立·自动接线）**：凡 1.8 产出**机器规格**（册 MD→specs，含 UI spec/接口 spec/计费 specs）且批量 ≥30 条，开跑前**必须**过 `usecase-spec-gate`（机检七检+子代理六保真维度），**红清单未清零禁开批**——生产方不自证，翻译层失真在开批前拦（溯源：仓内计费 R2 215/296 失真烧完执行轮才被翻案）。<30 条或纯人工通道可声明豁免（报告记录），机检部分仍须跑（一条命令成本）。

1.86 **开工第 0 步＝验上轮收尾（硬闸）**：开工先跑 `execution_adapters.report_sync` 与 `execution_adapters.writeback_check`，**任一红＝先补上轮收尾再开新轮，禁带病开跑**——时间戳/声明行/锚点值/文件计数是客观信号，不依赖 memory/自觉。未配置适配器时降级人工对账并明确标记"未校验"。

1.93 **拍板/修复回写台账纪律**：任何产生用例回写义务的拍板，**当场向回写 pending 台账登记**（登记与拍板同步发生）；回写落地后必须由 `execution_adapters.writeback_check` 验证锚点再置 done——**"回写完成"的自证＝校验器全绿输出，禁口头声明、禁以报告处置列自证**。
1.9 **前置数据清场**：按三步校验法清上一轮残留。
1.92 **批次开始计时（细则§十五）**：dispatch 第一条前账本写 `run_start` 行（run_id＋ISO 时间戳；含准备时段可另记 prep_start）——批次终止（连续 3 条停批/硬阻塞）同样必须落 `run_end`（含终止原因），禁只记成功轮。

### 阶段一：环境前置

2. **浏览器实例调度**：`node browser_pool.js acquire "用途"` → 登录 → 切租户 → 开菜单。
   - **批次清场 Checklist**（细则§九 12 项）。
   - **接口批次环境前置**（全 `API-` 条；细则§十六）：token 引导（独占实例借取→登录→切租户→读 token→建 APIRequestContext，**业务全程无页面**）＋接口就绪 checklist（token 有效/环境注入全解析/网关探活/api 数据锁）；混合批次两种前置并行做。

### 阶段二：批量执行循环（核心——禁停禁调试）

3. **执行循环**（批量执行器自动驱动，逐条 dispatch）：
   - 控件定位=「页面可见文案」＋控件类型；操作=CDP 真实事件；断言=多要素交叉
   - **接口条**：断言=三层（L1 状态/L2 结构/L3 值·数值相等优先 1000.5=1000.50；动态字段降级"存在且格式合法"）；**L1 单独禁判 PASS**；401=refresh（同租户重发 token）重试一次（细则§十六）
   - **单条5分钟超时**：未到验证点→最终结果 `NOT_EXECUTED`；已知外部通道阻断→`BLOCKED`；只有观察到实际与预期不一致才 `FAIL`；记录原因后下一条（禁当场调试）
   - **连续 3 条环境/通道/超时失败**→终止批次升级人工；页面级异常立即终止；未到达 TC 补写 `NOT_EXECUTED`，禁留 `MISSING`
   - **每完成一个模块**打印进度
   - manual_only 条自动跳过登记
   - 证据留痕：账本 jsonl 逐条写入（PASS=断言摘要/FAIL=截图+diff/NOT_EXECUTED=未到验证点原因/BLOCKED=阻断原因+处置）
4. **执行中发现预期不符**→记录证据→继续跑下一条→**全部跑完后**统一转 usecase-feedback-loop 呈报（禁现场改用例、禁中断呈报）
4.5 **失败复测轮（阶段二结束后自动触发，2026-11-17 立；操作正本=《{standards.L6_操作细则}》§十七，判定语义={standards.L6_判定}§5.1）**：对本轮全部终态 FAIL 条目逐条复测——**换通道交叉优先**（UI 首败→API 通道验数据态〔token 引导复用细则§十六〕；API 首败→UI 验展示态；无对应通道才同通道重跑）→ 账本写复测行（**同 TC id**＋`retest:true/retestOf:首败执行号/round:2/channel`，report_sync 末次覆盖=终态对账不双计）→ 三支处置：复测通过且首败**无**系统错误消息原文=**PASS(复测)** 全披露；首败**含**错误原文=挂起待复验（SUSPEND）转人工禁自动翻案；仍失败=FAIL 两轮证据并列（复现率偶发 1/2·必现 2/2）。复测轮同规适用单条 5 分钟/自动恢复/3 条环境阀；**run_end 在复测轮结束后落**（计时归批）

### 阶段三：收尾（执行完自动触发）

5. **出口判定**（门禁§19）：P0=100%/P1≥95%/NOT_EXECUTED 与 BLOCKED 逐条处置/环境误报清零；`SKIP/manual_only` 属执行前排除态，必须在执行集构成中单列，不作为最终状态。
6. **自动生成报告**（交付物规范§20 强制）：
   - **命名**={naming.报告模式}（版本号跟用例）
   - **报告结构＝三段式冻结模板**（§20.2 v1.16 永久冻结禁改骨架）：**一、总进度置顶**（1.1 当前状态一句话含质量结论+置信度+出口判定/1.2 四态数字表含环比+优先级维度/1.3 模块全景表/1.4 余量摘要——每轮必更）→ **二、执行轮次**（每轮一块 12 字段=做了什么/做了多久/环比/解决了什么/有什么问题/缺陷单变化/需求变更/系统实现/用例问题/拍板记录/剩什么问题/为何只做这些·为何剩的做不了——只增不回改）→ **附、支撑数据**（A1 环境与就绪/A2 失败与失效详说含用例册演进账本/A3 工件与沉淀索引/A4 口径说明＋附A 当前余项清单/附B 呈报-拍板台账）＋头部「**最后收尾**：第 N 轮 · 轮次名 · 日期」声明行（每轮必更，report_sync.py 硬校验靶）
   - **轮次块"缺陷单变化"字段单号来源**＝按 `{standards.L6_缺陷模板}` 落单回填的 defect_id（适配器未接入时=人工落单后回填），标题句式与锚点格式见该规范 §一
   - **覆盖率声明**放第一节最显眼位置（N/总数=X%）
   - **数据来源**=账本 jsonl 脚本汇总（禁手算）
   - **A2 失败条固定六字段**（2026-11-17 立，交付物§20.2 A2）：每条 FAIL/待复验带 severity 初判+规则依据（闭环§八口径，金额类先 P0）／紧急度建议／复现率（偶发 1/2·必现 2/2）／单号／截图×2／接口 json+带注释入参+执行号（首败+复测两轮）——数据源=账本+证据目录禁手写
   - **失败用例专项报告**（交付物§20.10，2026-11-17 立）：本轮存在 FAIL/待复验条目时自动生成/更新独立报告（命名=报告模式中缀替换 `_测试报告_`→`_失败用例报告_` 同版本跟随用例；无失败条不出；结构=头部+汇总表+逐条失败卡片含六字段与分流/拍板状态；数据源=账本脚本汇总禁手写；report_sync 硬⑥校验存在性与逐条对账）——终审呈报附件＋缺陷单证据源＋QC 对账对象；**第七块"ZBASE 日志证据"（2026-11-17 立，可选块）**：六字段后按账本 `zlog_evidence` 指针 include 证据目录内 `zlog_<单号>.md`（zbase-log-query 技能 `zlog_evidence.js` 失败钩子产出；测试环境默认1天；ERROR 行+关键业务行，单号优先防噪音）；缺失标"未取（原因）"不红不阻塞硬⑥，登录态失效先走 zbase-login（宝盒须通知用户）
   - **§20.8 总账两节**强制含：附A 当前余项清单 + 附B 呈报-拍板台账
   - **§20.4 禁忌**强制过：禁"抽测"字样/禁零证据PASS/禁BLOCKED无原因/禁版本独立递增
6.5 **效率指标适配器**：按公司 profile 的 `execution_adapters.metrics_summary` 调用；未配置时记录“指标未自动生成”，不得手写伪造指标。
   - **6.6 批次收尾计时（细则§十五）**：全部跑完或终止时写 `run_end` 行，耗时=run_end−run_start——轮次块「做了多久」三要素由此出，漏记=执行工序违规
6.9 **每轮报告同步（硬性工序·2026-11-13 用户拍板"有规范必须执行"）**：每一轮执行收尾（含增量轮/攻坚轮/复测轮，不只全量轮）必须完成三件事后才算收尾：
   ① **账本落定**（全部状态写回账本 json/jsonl）；
   ② **报告同步**——按 `execution_adapters.report_sync` 运行收尾校验，再更新总进度、轮次块、最后收尾声明和余项清单；本轮有失败条时同步更新**失败用例专项报告**（交付物§20.10，硬⑥校验对象）；
   ②b **回写完成性校验**——按 `execution_adapters.writeback_check` 对 pending、锚点、统计块和分章一致性做校验；本轮有回写义务时先登记再运行；
   ③ **memory 更新**（本轮关键拍板/新教训一句话）。
   **收尾完成的客观标识=重跑 report_sync.py 三重全绿（exit 0）**；汇报对话里固定附"本轮报告已更新：v2 §X＋最后收尾行"自证行。

## 分层执行模式（AI 首跑→脚本回归→失败回流）

> 具体浏览器、租户、登录、spec 台账和数据清场由公司环境适配器提供（细则正本＝`execution_adapters.环境细则`）；本体只规定通道选择、四态和失败回流契约。

- **执行前必查适配器 spec 台账**：若公司 profile 配置了 spec 台账与 runner，先走已沉淀的回归脚本；适配器缺失或不可用时按四态记录 `BLOCKED`/`NOT_EXECUTED`，不得假设环境已具备。
- **通道/实例纪律**：AI 执行走无头实例池；脚本回归走独占实例（持锁+心跳+占用检测，防多会话互切污染）；用户交互实例默认禁占（用户要求现场演示时短暂借用除外）。端口矩阵与锁协议由公司配置提供。
- **沉淀准入禁入清单**：坐标定位条 / any 降级断言条 / 判重造撞类条——永久留 AI 通道，不沉淀。
- **脚本红只记「待复核」**：必经 AI 回流定性（诊断→自愈修 spec / 真缺陷转反馈闭环），禁直接判不通过。
- **造数自清**：只清自己登记过的数据（名称台账精确删），禁前缀模糊删；沉淀脚本一律声明数据前缀。
- **preflight**：脚本声明租户→runner 自动查/切；登录过期自动重登，机器过不去的坎（人脸/验证码）才停叫人。
- **通道选择（2026-11-09 用户拍板升级：默认无头）**：**AI 执行一律走 cdp_pool 无头实例（{环境.chrome端口.无头AI执行} 优先，全忙自动扩 {环境.chrome端口.runner独占}，launch=--headless=new）——禁止默认占用 {环境.chrome端口.用户交互主实例}/{环境.chrome端口.辅助} 有头实例**（用户交互主实例=红线，仅限用户要求现场演示/人工坎时短暂借用）；已 PASS 稳定条＝脚本回归 `node pw_runner.js --specs …`（runner **独占取实例**：{环境.chrome端口.runner独占} 优先、避开无头池，持锁+每条心跳续锁+全页签业务路由占用检测，他人持锁端口拒用，结束解锁——多会话共用实例会租户互切、结果互相污染，坑库 G36）。无头实例登录态过期→{环境.登录技能} 脚本自动账密重登，机器过不去的坎才停叫人。
- **沉淀准入禁入清单**（拍板#4）：坐标定位条 / any 降级断言条 / 判重造撞类条——永久留 AI 通道，不沉淀。
- **四态**（拍板#3）：通过/待复核/阻塞/不通过——**脚本红只记「待复核」**，必经 AI 回流定性（diag 诊断 → 改版=自愈修 spec → 真缺陷=转 usecase-feedback-loop），禁直接判不通过。
- **造数自清双向 + 只清自己造的**（拍板#4；2026-11-09 拍板库内历史 TEST_ 数据保留）：spec 点「确定」前 `recordCreated` 登记名称台账 → 跑前/跑后 `cleanupOwn` 按台账名称逐条精确删（查询前先点「重置」防条件残留污染）；**禁止 spec 按前缀模糊删**（会误伤同命名格式的历史/他人数据），`deleteByPrefix` 仅留诊断用且带数量闸；沉淀 spec 一律声明 dataPrefix。
- **preflight 设计掉跑错租户/登录过期**：spec 声明 tenant → runner 自动查/切（changeTenant API）；登录过期自动账密重登，机器过不去的坎（人脸/验证码）才停下叫人，不带病跑。
- 回归窗口内执行实例独占；沉淀定位一律走 helpers 配方（2026-11-09 实测页面结构），**勿照抄 11-06 旧 exec_*.js 选择器**（已部分腐烂）。

## 接口通道与流量沉淀（2026-11-15 立，细则§十六正本）

- **通道选择**：回归/复测自由选 `node pw_runner.js --channel ui|api|all`——接口通道单条毫秒级、不占浏览器业务页签（仅 token 引导期借实例）；接口轮落同账本（channel:'api'，执行号 AX-YYYYMMDD-NNN）同一份报告；**正式 PASS 至少一个 L2/L3 实质断言**（与"UI 断言落地才正式 PASS"同构）。
- **旁路采集**：UI 首测执行时挂 `netcap_daemon.js`（被动监听无头执行实例全部页签，七元组含响应体、鉴权脱敏）；脚本化 UI 回归由 runner 内置采集自动落 `apicap/<execId>.jsonl`（通过与否都落=沉淀素材）。
- **沉淀与基准确认（硬纪律）**：收尾触发 `depose_api.js` → 草稿**必落 `api_specs/_pending/` 标候选基准，机器拦截禁执行**；候选断言清单（步骤/层/路径/首录值）随 usecase-feedback-loop 五段式呈报——**首录值≠正确值**（回溯**三源**：断言基线库／拍板记录／开发知识库 IF·RB 卡〔`{paths.公司包}/tools/wk_kb.py`，细则§十六 v1.13〕，任一命中才算验真，全空标"无源待拍板"）；用户拍板确认后才转正（编 API-{域}-{序号}、迁出 _pending/、入总用例库接口用例/），**拍板前禁入任何执行轮**。
- uas/merak 会话基建流量禁沉淀为用例（token 引导自有链路）；接口条禁写死域名/token（环境注入）。

## 硬规则

- **铁则**：执行中发现任何与预期不符的现象——记录证据后立即转 **usecase-feedback-loop** 技能呈报，**禁现场改用例**（用例修改必经用户拍板）；
