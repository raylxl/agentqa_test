# 答疑闭环格式模板

## 一、五段式提问格式（2026-11-02 对齐上游通用规范 v25 §12.5；示例为通用占位场景，公司示例已随 2026-11-13 参数化外移至 agent-company.json 语境）

```
## 疑问 N：一句话主题

### 【疑问】
①……？②……？（拆到一句一个，一次只问一个主题）

### 【需求原文】
原文对XX只有一句"……"——对YY没有任何描述（引原文关键句，标注章节，不改写）。
相关已拍板口径（防同题重问）：
| 拍板 | 内容 |
| M9 | …… |
（没有就写：本主题此前无拍板，属原文空白。）

### 【我的理解】
两种（或多种）可能解读并列：解读甲=……；解读乙=……（各自会导致的系统行为差异说清）。

### 【解决方案】（全部候选，含倾向；用户只做选择题）
- 方案 A（我的建议）：……。理由：……。
- 方案 B：……。后果：与XX矛盾/需另行补拍……。
每个方案给足细节：用例断言口径、影响范围、组合场景——宁可多给备选与推演，不给模糊方向。
（用户可能给出方案 C=跟上游走之类或文字补充，照落=拍板记录回填。）

### 【对用例设计的影响】
选 A：用例X组按……断言、需补XX场景；选 B：……（不同选择改变哪些用例/断言/场景）。
```

要点：需求原文引原句不转述失真；我的理解必须多解读并列（不预设单一答案）；方案必附建议与理由且详尽优先；说明对用例断言的影响；一次一个主题，等拍板再下一个；拍板即登记进理解说明，不得同题反复追问。

## 二、《理解说明》骨架

```
# 需求理解说明 — {族}{菜单}（vN · 答疑全闭环终版）
> 本文为需求理解说明（{编号体系共 N 项疑问已全部拍板闭环，{日期}），供评审/用例设计参考；用例设计待用户"go"后启动。
> 源需求：…vN.md ｜上位规则：…｜同族已闭环需求：…
> 答疑记录时间线：起 ~ 止（逐笔列修正）

一、需求定位（…）
二、结构常量（列/费用表/枚举…）
三、判定矩阵（…）
四、机制（处理链路…）
五~十、各主题章节（把拍板口径写进对应章节）
十一、答疑闭环记录（| # | 疑问 | 结论（拍板时间） |，含"→ 修正"链）
十二~十四、杂项/导出/用例规划摘要（12 组式）
> 版本约定：后续新疑问按 v2 追加（只新增不覆盖）；本文已全闭环（N 项），作为用例设计唯一依据。
```

修正写法：`~~旧口径~~ → **Fx 修正（日期）：新口径**`，同步在闭环表该行追加箭头注记、文首计数+1、时间线补一笔。

## 三、终检清单

1. 全文搜"待确认/待拍板/？（悬置）"——零残留（有意挂转测校准的除外）；
2. 闭环表计数 = 文首计数 = 实际行数；
3. 修正链一致：被修订口径的章节句、闭环表行、时间线三处同步；
4. 原文逐句：每句功能表述有口径或挂转测校准；
5. 拍板间矛盾扫描：后拍与先拍冲突处是否都有"修正"标注；
6. 四源补扫：上游特殊规则呈现、拍板两两交叉、时序对、越权路径——无新疑问；
7. 数据定论是否抽得出：枚举/矩阵/断言锚点能直接抄进域标准。

## 四、域标准骨架（九大块）

```
# {菜单} 用例编写标准 v1
> 定位：{菜单}域用例编写标准，跨需求版本复用（不挂需求版本号，版本级差异以各版本理解说明为唯一依据）。
> 通用方法正本：{standards.通用正本统称}（现行 vX）——条目格式/执行规范/红线/门禁/§13 写法六条按正本；本文只管域规则。
> 抽离来源：《{理解说明}》N 项拍板。消费方式：分章生成随章分发，禁重复询问、禁自创口径；冲突以理解说明为准；无覆盖→转测校准句式。

一、固定枚举与控件常量
二、{域对象}常量表（含 来源菜单特殊规则→本菜单呈现映射）
三、结构常量（列/模块）
四、统一处理链路
五、判定规则表（5.1 5.2 …按域列）
六、断言锚点口径
七、转测校准清单（不得写成肯定断言，"观察XX"句式）
八、数据准备（PRE）依赖清单
九、用例组织约定
> 版本：v1（日期，自理解说明 N 项抽离）；拍板新增按 v2 只增不覆盖。
```

## 五、G 条目上收提案格式

```
| # | 条目 | 内容 | 来源拍板 | 建议落点（正本章节） |
| G1 | 异步时间不作绝对断言 | 跨系统异步链路时间字段不作"=操作时间"断言；快照锚定触发时点 | F13/F18/F19 | §13 追加 |
```

规则：只收"换个需求也成立"的写法，域内规则留在域标准；提案须用户拍板后以只新增方式入正本（修订记录注明来源与日期），域标准同步改为引用。
