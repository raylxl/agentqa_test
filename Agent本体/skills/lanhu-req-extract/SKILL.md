## 一、环境与地址（前置）

- **浏览器**：不自启。经 `browser_pool` 租实例：`bash {paths.公司包}/jt_exec/pool_run.sh <脚本> [参数]`（`POOL_START=9334` 防抢 9333 交互主实例；蓝湖场景无视 login 字段——自动登录的是鲸天，蓝湖用不着）。
- **蓝湖地址（因人而异，产品发谁的链接就用谁的）**，四层解析：① 对话里用户给的链接 → 命令 `--url`；② `LANHU_URL` env；③ 本机 `{paths.蓝湖工具}/lanhu_config.json`（给过一次就写入记住，永不入 git/包）；④ 全空→问用户要，别猜。
- **访客态被拦**（"用户状态变化请重新登录"横幅≠阻断，R11：内容可见即可继续；链接落到项目总览页时脚本自动点 rp 文件进原型树）。真被账号级拦截→请用户人工登录一次蓝湖（固定单一端口实例），再续跑。
- **非 Windows 宿主 / 池化工具不可用**（2026-11-19 Mac 真机实证，snapshot 截断/iframe 跨域/CDP frameId 限制三坑同解）：降级走**直连 axure-file 原始 URL**——取蓝湖 axure 页 iframe 内 axure-file 链接直接 `goto`，服务端把 HTML 源码按纯文本整页返回（百 KB 级、无 snapshot「…」截断），跨域与 frameId 限制同时绕开；本地解析**裸文本行**（非空、不含尖括号的缩进行）还原全文。产出仍须过 lanhu_verify＋对源抽样逐段核对（R22 采集忠实，禁改写混入——该次首版混入改写即靠人工抽核抓回）。

## 二、单菜单采集（默认走路线 A）

```bash
POOL_START=9334 bash {paths.公司包}/jt_exec/pool_run.sh {paths.蓝湖工具}/collect_lanhu_req.js \
  --menu "<probe 出的树内真实菜单名，一字不差>" \
  --name "财务需求{年份}_{域}_{菜单简名}_v1" \
  --outdir "<产物目录：正式={paths.需求文档}；试采=lanhu_exec/out>" \
  --url "<用户本次给的链接（可省，走本机默认）>"
```

- 先跑 `probe_menu_names.js`（同入口）dump 树内真实菜单名（半/全角问号以树为准，R2）。
- 退出码：0=闸门过；3=验收红（图片未落地/弹窗缺裁/正文为空）须处置重跑；1/2=连接/参数错；**页面未渲染（等 60 秒仍无内容）会中止、不出文档**——偶发，重跑即可；连续出现再查蓝湖访客态。
- 采完**必跑**第二道闸门：`python {paths.蓝湖工具}/lanhu_verify.py <md> <imgdir>`（MISSING/表格列数/关键词/残留，非零退出）。
- **流程图（R23，标准 v1.2）**：几何识别为图示、且拓扑能重建的，采集器自动产出三层：①蓝湖原图截图 `流程图_*.png`（2 倍像素）②**可见的 ```mermaid 流程图代码块**——ZCode 客户端、Typora 这类阅读器直接把它画成流程图，这就是用户眼里的"流程图"，**不许藏进 HTML 注释**（2026-11-24 v5 藏了，用户原话"怎么流程图没了，还没上次展示的好"）③渲染图 `流程图渲染_*.png`（给不支持流程图代码块的工具）。重建不出或渲染不出的图保持"截图 + 逐行节点文字"。采集日志"流程图去向"四数之和须等于图示数（硬闸门）。渲染依赖 `{paths.蓝湖工具}/vendor/mermaid.min.js`，缺它不出重绘图。**2026-11-24 16:05 之前采出的文档都没有流程图块**，对账会报"流程图块数"红，重采即消。

## 四、批量采集（现行=批量驱动，先暂存、全绿才入库；2026-11-24 立）

```bash
# ① 逐菜单：采集（内置闸门）→ 文件校验 → 忠实闸 → 对账 → 结构体检；产物落暂存区，状态逐菜单落盘
python {paths.蓝湖工具}/batch_recollect.py run --config "<财务需求{年份}_菜单配置_vNN.md>" --stage <暂存目录> \
       [--shard k/N --start-port 9334] [--skip "行序号|关键字"] [--only "关键字"] [--rerun-ok]
# ② 汇总（状态 / 字数比 / 新旧文档文字差异）→ <stage>/report.md
python {paths.蓝湖工具}/batch_recollect.py report --config … --stage …
# ③ 入库：默认只预演；确认计划后加 --apply
python {paths.蓝湖工具}/batch_recollect.py land --config … --stage … [--force "行序号|行序号"]
```

- **暂存区不碰权威库**；`land` 只动四道闸门+结构体检全绿的菜单：旧版 md 与 `_images` 整体移入 `{paths.历史版本}\全量重采前_<日期>\`，新版拷入，入库后逐字节比对。红的留在暂存区、权威库里保持旧版，收尾列清单。
- **断点续跑**：重跑自动跳过已通过的菜单——所以**采集器或检查代码一变，必须加 `--rerun-ok` 全量重跑**（旧的"已通过"不代表现行代码的产物；2026-11-24 首次全量就因此只重跑了红的 5 份）。
- **多路并行**：开 N 个进程 `--shard 0/N … (N-1)/N`，各给不同 `--start-port`（9334/9337/9339/9340），每个进程输出重定向到各自的日志文件；**一个菜单同一时间只归一个进程**（分片批量在跑时别再单独重跑其中某个菜单，会读到半截文件）。
- `--skip` 里的纯数字只按**全表行序号**匹配（菜单配置的"序号"列按模块重新起算，不唯一；菜单名里到处是迭代号，拿数字去匹配菜单名会误滤）。
- 采集器/闸门改了代码要证明"没改坏别的菜单"：**毛坯对毛坯**（extract 的原始提取结果）做改前/改后对比——`node {paths.蓝湖工具}/diag_full.js --make-baseline <基准目录> --rev <改前的提交>` 建基准，再对每个菜单各提一次 `--impl before --base <基准目录>` 与默认（工作区现行代码），逐行 diff；预期只有要改的菜单有差异。拿毛坯比落盘成品会满屏假差异（`@@TBAND@@`、查询条件带文字、流程图节点标签是成品阶段才处理的）。
- 入库前顺序：`run`（全绿）→ `report` → **与上一版逐份对比**（每份变化的文档都要能解释：是修对了，还是改坏了）→ 漏采审计清零 → `land` 预演 → `land --apply` → 入库后核对（库内副本逐字节 = 暂存产物；旧版全部在归档目录且内容指纹不变；其余文件未动）。
- 入库后收尾：菜单配置升版（§八 3b）、台账登记；被别的文件按文件名引用的需求文档（2026-11-24 实测仅 平台价格 v1 两处）在汇报里点出，**不改用例文件**。

## 坑（本体系实测）

- 菜单名含 `/？` 当文件名=Windows 非法字符（脚本已 sanitize，--name 仍建议规整）；
- 池实例无头态 `el.screenshot` 常卡"waiting for element to be stable"→已内置 clip 降级；
- Playwright 1.65 与展示包（1.64）API 漂移两处已修（addStyleTag remove/dispose）；同事环境装最新 1.6x 均可；
- 三候选 sid 实测等价（同项目 tid）；换产品新链接直接 --url，无需改代码。
- **pool_run 的输出不能接管道**（`| grep`、`| tail`、`| head`）：心跳子进程里的 `sleep 300` 会占住管道，命令要卡满 300 秒才返回（脚本其实早跑完了）。一律重定向落文件（`> x.log 2>&1`）再读文件。同源现象：心跳子进程在脚本结束后还占着日志文件句柄最多 300 秒——批量日志名带时刻，别同名覆盖后再清理。
- **"退出码非零"不等于"检查拦住了"**：先看日志是判红，还是 `ENOENT`/`MENU_NOT_FOUND` 这类自身报错（给 node 传文档路径要 `cygpath -w` 转 Windows 绝对路径；单引号里的 `$(...)` 不展开）。2026-11-24 五个反向用例曾"全部拦截"，其实是文件没找到。
- **蓝湖页偶发不渲染**（点菜单后文档高停在视口高、可见文字 0）：采集器现在会等 60 秒并中止；对账/诊断脚本没有这层等待，遇到"菜单未找到/enterPrototype 超时"重跑一次，**零星失败=偶发；每个菜单每次都失败=自己的环境有问题**（如基准目录取不到 lanhu_config.json）。
- 写/改脚本用写文件工具，不用 Bash heredoc 拼源码（heredoc 会吃一层反斜杠，`\s`→`s`）。
