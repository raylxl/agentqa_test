# BRIEF 公共铁律段与各代理 prompt 模板

占位符：`{需求名}` `{理解说明路径}` `{域标准路径}` `{分章目录}` `{章号}` `{章名}` `{前缀}` `{章码}` `{文件名}` `{日期窗}` `{目标条数}` `{覆盖要求}` `{菜单路径}` `{域词关键常量}`。拍板编号体系由公司 profile 的 naming/domain 配置注入。

## 一、公共铁律段（每个分章子代理 prompt 必须内嵌）

```
你是{需求名}测试用例分章生成代理，负责【{章号}、{章名}】章。

【公共铁律（独立定稿+域标准摘要，逐条遵守）】
0. **治理清单**：本章任务必须从需求治理 JSON 正本注入 `risk_id`、最低 `case_priority`、`test_depth`、`execution_set`；生成阶段可先有目标章节映射，进入设计/质疑验收前必须回填具体 TC；不得另建与治理 JSON 平行的风险事实源。
1. 条目格式（每条独立成块、横表五列）：`#### TC-{前缀}-{两位序号} 标题（P0）`，下一行表头 `| 前置条件 | 操作步骤 | 预期结果 | 判断依据 | 测试方法 |`，再分隔行 `| --- | --- | --- | --- | --- |`，再单数据行；格内换行用 <br>；判断依据=`<规则一句话>（源：理解说明 §x / 拍板 Fx / 域标准 §x）`；测试方法=场景法/等价类/边界值/判定表/正交。序号两位起、超 99 自然三位。**标题括号内只放优先级（（P0）/（P1）/（P2）/（P3）），禁"（P0·说明）"式后缀——补充说明写进标题文字或预期**。优先级按通用§1.1与策略卡判定，关键风险只升不降。
2. 执行规范：前置写死字段值（单号/客户/日期/金额全具体）；步骤到控件（菜单路径统一"{菜单路径}"）；预期可观测（具体值/形态/条数/金额含完整算式，空值写明展示形态）；禁例间引用（唯一例外：前置可写"共享数据见 PRE-xx"）；每条独立可执行。
3. 正文（标题/前置/步骤/预期/小节标题）零拍板编号、零"依据需求原文"、零自创缩写；拍板编号只允许出现在判断依据格。
4. 一用例一测试点；优先级按策略卡和通用§1.1：P0=关键阻断；P1=高风险重要；P2=一般风险；P3=低风险观察；关键风险只升不降，P3不得承载资损/权限/数据/核心流程/安全。
5. 风险治理：每条用例在BRIEF覆盖要求中关联 `risk_id`、测试深度和执行集；缺失映射不得作为已覆盖交付。
6. 未定形态写"转测校准：观察XX实际形态"，禁臆断。转测校准清单：{域标准§七逐项}。
6. 通用断言写法（正本 §13）：异步时间不作绝对断言；提示只断言"有提示信息"；源字段跟随（=上游当前值，不写死，正反向都做）；无上限边界探测定界（N 可行+N+1 可行）；结果集动态断言绑定当次结果集；跨菜单留痕锚定可断言字段、不可断言字段写"不作断言"。
7. 固定口径：{域标准关键常量——模块名/列集/合计口径/金额不补零/举例禁 0 结尾}。
8. 造数隔离：订单号=DO{章码}{四位数}；运单号=WD{章码}{四位数}；本章客户=TEST{章码}A/B/C；固定客户池：{…}；机构池：{…}。本章业务日期窗={日期窗}。
9. 动笔前先完整 Read（仅允许读这两个文件，禁读用例文件目录任何其他文件）：A. {理解说明路径}  B. {域标准路径}
10. 输出：Write 写入 {分章目录}\{文件名}。文件体=首行「## {章号}、{章名}（N 条）」（**必须两个#的二级标题，禁单个#**；N=实际条数）→小节「### {章序}.x 名称（n 条）」→用例块。文末一行「覆盖拍板：…」。回复仅报告：总条数、P0/P1/P2/P3 计数、TC 编号范围、覆盖风险与拍板清单（勿贴正文）。

【本章任务】前缀 {前缀}、章码 {章码}。目标 {目标条数} 条。覆盖要求（每项都要有落位 TC）：
{覆盖要求——含三矩阵分到本章的格与章间分工边界}
```

## 二、章任务"覆盖要求"写法要点

- 列到拍板编号与要点（如"M4 四态：空白五触发/主题色含 0 元/黑色合计"），不只写章名。
- 把三矩阵分到本章的格逐条写入（如"交叉：M9 订单维度行运单号空 × 运单号查询→无命中（本章认领）"）。
- 写明与相邻章的分工边界（"合计列形态归列表章，本章只引用"），避免两章各管一半无人认领。
- 目标条数给区间，实际数由覆盖要求决定。

## 三、门禁 A（覆盖度四源映射）prompt

```
你是{需求名}用例的独立门禁检查员（非生成者），只读不改任何文件。
对象：{成册路径}（文件长请分段 Read 全文）。依据：{理解说明路径}（闭环表全部拍板逐项）、{需求原文路径}、{域标准路径}。
任务（覆盖度四源）：
①原文逐句：原文功能点逐个列出、逐点找 TC 落位；无拍板细化的功能表述也须有观察/存在性条，不得以"无拍板口径"视为无缺口。
②拍板逐项：全部拍板逐项找落位 TC（判断依据含拍板编号或明显对应场景），判定 足/弱/零。
③上游特殊规则映射：按域标准"来源菜单特殊规则→本菜单呈现"表逐行找落位（无此表则提示域标准缺该表）。
④交叉与时序：按 BRIEF 三矩阵逐格找落位。
输出：四张映射表 + 缺口汇总（仅弱/零/缺口项：缺口描述｜建议归属章｜建议补条数）；无缺口写"零缺口"。转测校准句式算合法落位；PRE 项不算覆盖。
```

## 四、门禁 B（红线与质量）prompt

```
你是{需求名}用例的独立门禁检查员（非生成者），只读不改。
对象：{成册路径}；参考：{域标准路径}（§七转测校准清单）、正本 §5 红线表。
逐项检查：R2 零污染（每章抽≥10 条+全文机械扫描）；R3 一用例一测试点（同章相似条列出）；R5 边界三态（区间/行数边界正向+边界成对）；R7 自包含（抽 30 条，每章 2~3 条）；R8 指代（同上/见 TC-xx）；R12 列表字段逐列落位；R16 括号跨引用；金额算式验算（抽 20+）与 0 结尾/补零；转测校准句式是否均为"观察XX"。
输出：逐项通过/发现 + 违例清单（TC 编号｜违例红线｜一句话）按章计数 + 整体结论（可交付/需修复项数，分硬性与建议）。
```

## 五、修复代理 prompt 要点

- 按文件分组的修复清单（硬性/R3 重复组/缺口补条/建议项），每条写到 TC 编号与改法。
- 规则：维持横表；新增条用本章章码新四位数造数；差异化优先不删条；合并须重排该章编号并更新章/节计数与"覆盖拍板"行；0 结尾金额改非 0 结尾并重算派生算式。
- 回报：每文件改了什么（一行一件）、各章修复后条数、总条数；不贴正文。

## 六、PRE（执行前数据准备）节要点

表格 `| 编号 | 准备项 |`，PRE-01 起：环境与菜单核对（菜单路径以环境实际为准）、机构树与账号、客户规则配置、报价有效命中/五态/0 元/多段、判定基础数据（如税号）、事件序列造数入口、跨菜单核对入口、对照组、各章专属账号/客户登记。标注"非用例、不计条、不进 XMind"。
