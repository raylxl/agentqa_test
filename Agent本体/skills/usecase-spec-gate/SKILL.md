# usecase-spec-gate 规格保真门（2026-11-18 立·执行质疑标准 v1.3 挂点②）

## 0. 公司适配层（开工第 0 步）

读 workspace `公司包/agent-company.json` 解析 `{paths.X}`；无该文件→降级通用模式。输入两件：**机器规格 json**（执行器实际吃的 specs）+ **用例册 MD**（#### TC- 块竖排五行，L3 通用形态）。可选第三件：域枚举表（订单类型/费项码/事件映射等键值，喂给 lint 与子代理）。

## ⏱ 计时打点（《计时与时间线规范》v1.2·2026-11-25 接入）

```bash
# 先把 {paths.Agent本体} 解析成 agent-company.json 里的绝对路径，再执行；<册名>＝流水线台账里的需求名，同一需求各阶段沿用同名
python -X utf8 "{paths.Agent本体}/tools/timeline_mark.py" begin --id "<册名>" --phase specgate --round "<如：仓内-R7 开批前>" --actor usecase-spec-gate
python -X utf8 "{paths.Agent本体}/tools/timeline_mark.py" end   --id "<册名>" --phase specgate --round "<同上>" --actor usecase-spec-gate --artifact "<保真报告路径>" --evidence "如：机检 0 命中·子代理 N 条全绿／红清单已回流"
```

- 第 1 步组包之前 begin → 出口结论（绿／红）落定后 end；复跑本门至清零＝同一段不拆（红→修复→复跑都在段内，end 时 `--note` 写复跑次数）；工具打印的 `⏱` 行**原样转述给用户**；耗时取底账自动算，**禁手填、禁事后补造**，整段漏记只能 `miss … --phase specgate --reason "…"` 如实申报。

## 定位（为什么这道门值钱）

血泪校准：2026-11-18 仓内计费 R2——296 条规格里 215 条失真（E1 最低/最高收费组序错绑、E2 多报价优先族压缩成单报价、E3 专造仓编码截断同码→EXEMPT 劫持、E4 物料编码填了名称、E5 双单只推 A/温层归一），**烧完执行轮才被判定复核翻案**。此门=把同类失真拦在开批前，省执行轮+省翻案轮。

与三道门的相对位置：challenger（用例设计域）→ **本门（规格域，册→机器规格的翻译保真）** → executor → execution-challenger（判定域）。翻译层是设计到执行之间最易失真且此前无人看的一段。

## 五步流

### 1. 组包+机检（一条命令）
```
python <skill>/scripts/spec_gate.py --specs <规格.json> --md <册.md> --out <输出目录> [--group tab|prefix|flat] [--enums 枚举.json]
```
每例复核包：册原文（pre/step/exp）+ 实际规格 + **lint 命中清单**。通用七检：
| 规则 | 检什么 | 溯源 |
|---|---|---|
| L1 预期金额核对 | exp 里"金额=N"值必须出现在 expects | 期望值错位 |
| L2 多报价计数 | 前置"两条/N条报价" vs quotes 数量 | E2 压缩 |
| L3 多订单计数 | "订单甲…订单乙/N张" vs pushes 数量 | E5 只推A |
| L4 最低/最高落位 | 原文"最低收费X"的 X 必须出现在某行 minPrice（最高同理） | E1 组序错绑 |
| L5 编码-名称错配 | materialCode/skuCode 含中文=填了名 | E4 |
| L6 同码劫持嫌疑 | bizCode==opCode 且原文无"同一个仓/单仓"字样 | E3 EXEMPT |
| L7 段值存在性 | 原文明细数值（单价/基础数量/续价）在 details 里找得到 | 数值漂移 |

**机检是下限不是上限**：lint 绿≠保真（语义失真机检查不出），必须走子代理深查。

### 2. 分路派独立子代理（六保真维度）
按页签/分章分路（每路 20~90 条），并行 spawn。prompt 模板：
> 你是{需求名}执行规格的保真质疑方（对抗性，翻译者不自证）。对全部 N 条规格逐条比对册原文与机器规格，六查：a) 维度忠实（客户/业务仓/操作仓/订单类型/温层/特殊属性——原文"空"不得填死值，原文专造名不得截断或替换）；b) 明细数值逐项（段边界/单价/基础数量/续价/最低最高——落位键名要对）；c) 结构完整（原文 N 条报价全在？多报价差异维度保留？N 张订单全推？链事件/复用事件在？）；d) 主数据编码完整（专造名=码类是否原样传递；截断同码=红线）；e) 预期金额独立重算（按原文公式算一遍 vs expects）；f) 反例保留（no_fee 预期的故意不一致要在，不得被"对齐"抹掉）。
> 输出 {out}/保真结果_{路名}.md：汇总表（绿/红计数+失真分类）+逐条表 | TC | 保真结论(绿/红-失真类) | 依据（引原文值vs规格值） | 修复建议 |。全条目禁抽样；只读，除输出外不写。

### 3. 红清单处置
失真项回流规格生成方修复（解析器/造数修正）→ 复跑本门至清零；存疑语义项标注"执行后由 execution-challenger 终审"放行。

### 4. 出口
- **绿**：红清单清零+子代理逐条表在案 → 准开批；
- **红**：禁开批（执行纪律； executor 开批前应见本门绿单）。

### 5. 留痕
保真报告（机检命中+子代理逐条表+处置）落执行记录目录，报告投影一行（规格域门禁结果）。

## 纪律
- 规格量小（<30 条）可人机同堂一次过；量大必须分路并行；
- 子代理汇报"全部绿"必须附完整逐条表，无表不可信；
- 本门质疑**翻译保真**，不质疑用例设计本身（challenger 管）也不质疑判定（execution-challenger 管）——三权分立；
- lint 规则按域可扩（--enums 注入域枚举后可加映射类检查），新增规则先拿历史失真案例反测（能抓住 E1~E5 才准入库）。
