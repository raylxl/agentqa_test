# 清理用例文件夹历史版本

## 0. 公司适配层（开工第 0 步·2026-11-13 参数化）

目标目录＝`{paths.用例文件}`（从公司 profile 解析；无配置时要求用户提供根目录，不猜测工作区路径）。

目标目录：如上配置解析（下称根目录），归集目标为公司 profile 指定的归档目录（默认 `archive` 子目录）。本技能只在用户明确要求归档后执行：dry-run 先展示计划；规则内的项经确认后移动并追加台账；规则外存疑项一律不动、列出请用户决定。

## 执行流程

1. dry-run 看计划（只打印，不动任何文件）——脚本在本技能 `scripts/` 目录内：
   ```
   python -I "<本技能目录>\scripts\archive_history.py"
   ```
2. 逐项核对计划与下方规则表是否一致（几秒钟的事，防规则误伤没见过的新文件形态；有疑问先停，按"边界与升级"处理）；
3. 确认无误后执行（真移动 + 自动在 `历史版本\归档说明.md` 末尾追加"增量归档"台账，旧台账行不改——批次只增不覆盖）：
   ```
   python -I "<本技能目录>\scripts\archive_history.py" --apply
   ```
4. `ls` 根目录与 `历史版本\` 验证落位；
5. 汇报（平实语言，见"汇报格式"）。

脚本只处理**根目录一层**的文件与目录，不递归进分章/执行记录内部。

## 判定规则（脚本内置，核对用）

| A1 | 文件/目录 | 命中公司 profile 中 `archive_policy.name_patterns` 的归档规则 → 移入 | 由公司归档策略给出原因 |
| A2 | 文件 | 同名族存在更高版本时，按公司策略保留最新、归档旧版 | 由公司归档策略确定版本解析规则 |
| A3 | 目录 | 命中 `keep_patterns` → 保留 | 由公司策略保护的源目录/执行证据 |
| A4 | 目录/文件 | 命中 `backup_patterns` 或 `draft_patterns` → 归档 | 公司策略中的备份/草稿规则 |
| — | 目录/文件 | 以上都不匹配 → 存疑不动 | 规则未覆盖，提请用户决定 |

## 禁区（任何情况不碰）

- `历史版本\` 自身及其内容（只允许追加归档说明台账，不改旧台账行）；
- 各分章目录内部的一切（含仓内分章里的 `_7col_archive\` 章内自归档，保持原位）；
- `执行记录\` 内部；
- 无版本后缀的现行件：基础数据总清单、各类报告（端到端审查/测试报告/UI测试报告）、三矩阵等（R4 对单版本族天然放行）。注意：**含 WB 的报告（如 用例WB对比报告）不属保护区**——按 R1 一律归档（用户 2026-11-04 拍板）。

## 汇报格式

| 段 | 内容 |
|---|---|
| 已移入 | 每项一行：名称 ← 规则编号+原因（注明台账已同步追加） |
| 保留 | 按类归并说明（现行用例族 / 分章 / 执行记录 / 报告类） |
| 存疑待拍板 | 逐项列名称+疑点，等用户文字拍板；不用 AskUserQuestion 选择框 |

## 边界与升级

- 出现脚本没见过的新形态（如带日期后缀的版本 `..._20261105.md`、新类型过程目录），脚本会归入"存疑"或"保留"；按上表列出请用户拍板，拍板后把新形态固化进脚本 `classify_root()` 的规则里，下次自动识别。
- 若 `历史版本\归档说明.md` 不存在（异地重建场景），脚本会自动创建并起头台账。
- 定向归档先例（2026-11-04 仓内门禁/合规检查报告）：历史过程件（被检对象已有新现行版）不进自动扫描范围，由用户点名 → 加族前缀改名 → 入历史版本 → 台账记"定向·用户拍板"。
