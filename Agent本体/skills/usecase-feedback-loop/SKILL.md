# 执行反馈闭环（反馈工序）

## 0. 公司适配层（开工第 0 步·2026-11-13 参数化）

读 workspace `公司包/agent-company.json` 解析公司值；下文 `{paths.X}`/`{standards.X}` 均由该文件取值。**无该文件→降级通用模式**：正本=手艺包`01_标准\`（§14 反馈闭环），writeback 台账/校验器机制降级为"拍板记录进报告附 B 台账"；禁凭旧记忆硬写公司路径。

正本：`{paths.标准体系}\{standards.L6_闭环}`（具体内容修订版以《00_标准体系索引》及该文件修订记录为准）。本技能=呈报与修码工序编排；SYS/DEF/IMP/CHG 四载体语义以反馈闭环标准为唯一正本。

**铁则：所有用例修改必须经用户拍板，禁自行按实现改预期（"系统就这样"不构成修改依据）。呈报一律对话内文字逐条展示，不用选择框。**

## 六类触发源（统一走本闭环）

执行观察／执行失败／待复验复验／转测校准回填／代码走查·端到端审查／外部用例对比发现。

## 呈报格式（五段式·一次一事）

1. **现象**：环境＋TC 编号＋步骤号＋预期 vs 实际（截图/接口报文佐证）；
2. **用例原文与出处**：该条判断依据格内容＋拍板/标准出处；
3. **系统实际表现**：可观测事实，不掺推断；
4. **分流初判**：下表三选一＋理由；
5. **拍板请求**：修用例（附建议改法）／建缺陷／回答疑——附紧急度（高/中/低）＋建议路由对象。

## 分流三选一（先查该条判断依据格出处，再分流；两可时呈报不擅自分流）

## 拍板后动作链（当轮全量根治，禁只修单点）
**收尾必更总账（交付物§20.8/闭环§十四）**：修码/销账完成后，同步《测试报告》「当前余项清单」并登记「呈报-拍板台账」行（问题｜答复｜处置｜日期｜Execution ID）——未同步即本轮未收尾。

**拍板回写四步铁律（硬闸）**：每条拍板产生回写义务 → ①**当场登记**回写 pending 台账（登记与拍板同步发生，含可 grep 锚点短语）→ ②**只改分章源，禁直接改正本**（PreToolUse hook 已拦）→ ③运行组装入口重出正本 → ④由 `execution_adapters.writeback_check` 验证锚点全绿才置 done。**附B 处置列"已修订"禁止单独作为完成声明；跨册拍板（N 册统一类）必须双登记流水线台账拍板队列分发各册；收尾门＝report_sync 校验 pending 残留=禁收尾**。

**修码形态铁则（执行反馈闭环标准 §13.3）**：用例修改禁原地改写或删正文留空位，采用“原文不动+新载体承载”：被推翻条目标失效标识并给替代指针，修正断言落 SYS/DEF/IMP/CHG 对应载体；增强型/适配型保留原条并挂关联注记。CHG 只承载需求范围变化及其派生回归，不替代 SYS/DEF/IMP。恢复源、失效形式、回归扫描和证据要求以反馈闭环正本为准；原 checklist 与例子在下文保留。

修码 → assemble 结构门禁复跑全绿 → 受影响时 **XMind 三步重出＋md2xlsx 重出**（双格式同 stem）→ 文内修改记录加拍板行＋证书版本行 → **影响面回归集（闭环§十二）**：按拍板编号/口径关键词 grep 全册反查引用面，受影响条目＋同机制兄弟场景＋其正向对照条全部复跑并记入修改记录行 → 缺陷线另跟进缺陷单状态（修复→按单内"修复回归要求"关联+影响面回归→关单附证据）；落单与状态跟进全工序=`{standards.L6_缺陷模板}` §四（适配器未接入时降级=呈报附完整模板内容、人工落单后回填单号）。

**回写出口=qc 七查（2026-11-18 立·自动接线）**：拍板回写动作链走完后，须过 `usecase-qc`（含 Q7 回写语义复核：抽 ≥5 条拍板回写 vs 拍板原文逐句比对——锚点落没落是 Q1，**落的对不对是 Q7**）才算本轮回写闭环；qc 红=回写返工，禁以 writeback_check 机检绿单独声明回写完成。

## 转测校准挂账与销账

- 挂账登记在理解说明/证书清单；用例内"转测校准"句式条＝manual_only（执行技能自动分流人工）；
- 回填：执行记录实际形态 → 呈报拍板定形态 → 用例改定形态断言（manual_only 随之解除）→ **证书＋理解说明台账双向划销**。

## 证据链要求（闭环§九）

呈报与修复全程挂 Execution ID；报告不可改、修订出新版本记原因；审计标准＝随机抽任意用例 5 分钟内找齐完整证据链。

## 回写一条龙 Checklist（拍板后按序执行，两个易漏点置顶提醒）
- [ ] 原文恢复源已查；失效项按正本规范带划线、尾标与替代指针（载体可为 SYS/DEF/IMP/CHG，按原因分类）；增强型/两可兼容条只挂〔关联〕不标失效
- [ ] **易漏②**：原用例判断依据中**已证伪的拍板引用标记删除**（断言正文保留）
- [ ] 新模块分章文件（五列表+来源标注）+ 组装配置追加 + 重组装全绿（条数核对）
- [ ] 登记：修改记录版本行/测试报告版本行/执行记录/记忆/口径正本 K 行（需求文档 7.x）
- [ ] 增强型/两可兼容条只挂〔关联〕注记不标失效
- [ ] 回归轮收尾再触发一轮四源盘点（提案-拍板-入册循环）

## 执行完成后回写提案（四源主动盘点·执行反馈闭环标准）
每轮执行（UI/接口/回归）收尾时主动触发，不等用户指令：
1. 盘点四源：执行记录不一致项+已落定观察 → SYS；缺陷平台本菜单缺陷 → DEF；实测合理但需求未定义的实现行为 → IMP；拍板后的需求范围变化及其影响面 → CHG（需求变化载体，单独维护，不与系统不符/实现固化合并）。
2. 按执行反馈闭环正本的分流与五段式呈报；候选用例逐条展示完整五列表并标明载体和来源。
3. 用户拍板后按正本增量修复：SYS/DEF/IMP/CHG 保留各自载体和血缘，禁止把 CHG 塞进 IMP；修复后重组装、过门禁并执行影响面回归。
4. 回归轮结束后重新盘点四源并更新报告总账。
